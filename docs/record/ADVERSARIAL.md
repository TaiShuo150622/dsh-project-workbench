# CI 后的 Sol max 对抗测试协议

用户已确认首轮为 S1 内核与 CI；GitHub 执行确定性检查，当前 Codex 会话在每轮 CI 结束后调用 `gpt-6.1-sol`，推理强度 `max`。本文件是可复用的任务协议，不是一个已经部署的常驻监听器。

## 每轮输入

- 固定仓库、PR、head SHA、GitHub run ID、attempt、结果和证据 artifact；即使 CI 失败也记录实际结论。
- 读取对应提交的 `record/README.md`、代码、已有测试、差异，以及先前反例索引。
- 使用独立工作副本；模型只写 `tests/record-adversarial-<round>-<line>.test.mjs`。报告放约定的临时输出，采纳后由调度者保存到 `docs/record/reviews/`。
- 显式传入模型和推理强度。若不可用，记录失败；不回退到默认模型。多个同模型上下文仅称为不同上下文审查。

## 生成者任务

尝试证伪已确认的业务契约，而不是模仿当前实现。优先检查：任务身份和交办重放、错误证据、完成/验收分离、旧结果按钮、取消/授权/发送竞态、未知动作占用、跨任务资源冲突、快照乱序和日志回放。

1. 先确认允许范围内能读、写和运行测试；工作副本范围外不得写入。
2. 产出可执行、确定性的最小反例；声明预期行为、对应约定、实际表现及复现命令。
3. 只新增候选测试。不得改生产代码、现有断言、依赖、工作流或授权边界；不得读取凭据、提交、推送、合并或发消息给其他人。
4. 允许在自己的副本运行 `node --test tests/record-adversarial-<round>-<line>.test.mjs`；测试失败是候选证据，不自行宣称已确认缺陷。
5. 无新缺陷可如实报告；不要为了增加数量写重复用例或断言未约定的行为。
6. 对已修复反例复核时，先运行原用例，再寻找变体，不反复提交同一问题。

## 调度者采纳

检查变更范围和断言依据，在固定的 CI 提交上独立运行候选并保留失败；排除需求歧义与测试错误后，再由实现者修复。保留原断言，在修复版本上复跑，然后运行完整 CI。有效的正向边界测试也可采纳，但报告中与已复现缺陷分列。

记录每轮模型配置、输入 SHA/run、候选文件、复现结果、采纳理由和修复提交。重复投递同一个 run/attempt 不重复派发；下一次真实 CI 是新的一轮。读取回执或文档归档不制造测试修改。超过预设的自主尝试范围时记录尚未解决事项，不用删测试、skip 或放宽约定来制造通过。

## 证据与结束

代码和工作流更新会进入下一次 CI，并再次触发当前会话的对抗审查。最终报告必须同时列出最后 CI 的 head SHA 和对应审查结果；只读报告归档可以使用后续文档提交，其代码树需与已验证版本相同。会话结束时说明监听覆盖到哪一轮，不宣称以后无人值守运行。
