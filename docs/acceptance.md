# 桌面验收

目标：用户正在使用的 `/Applications/DeepSeek Harness.app`，共享桌面宿主；不以浏览器开发预览代替验收。只创建明确标记的验收项目和小型 Git 夹具，不触碰现有用户任务。

写前存档：`.acceptance/desktop-before/` 保存桌面 profile 的相关配置、插件版本、项目状态（如存在）。代码提交作为可复现起点；夹具有独立初始提交。敏感配置和完整会话证据不进 Git。

## 固定场景

| 场景 | 输入原句 / 操作 | 预期与独立判据 | 结果 |
|---|---|---|---|
| 桌面入口 | 侧栏「项目」创建「桌面项目协作验收」 | 打开总对话和原生右侧项目标签，旧会话仍在 | 未量 |
| 自动分派 | `请自动安排两条独立研究线程：一条读取 README.md，汇报这个夹具的用途；另一条读取 numbers.json，计算 values 的总和。不要改文件。两条都结束后在总对话汇总结果。` | 模型自己调用分派工具，两个不同 session；用途准确，和为 42；均回报总对话 | 未量 |
| 原生双会话 | 点击一条工作线程标签，在右侧继续询问 | 右侧显示原生会话历史和输入框；左侧总对话未被替换 | 未量 |
| 线程复用 | `请让刚才计算总和的线程继续计算 values 的平均数，复用原线程，不要另开。` | session 数不增加，平均数 14，回报返回总对话 | 未量 |
| 隔离改代码 | `请安排代码线程把 result.txt 中的 pending 改为 sum=42，运行一次检查确认内容正确，汇报实际改动与检查结果。` | 修改在独立工作树；原仓库 result.txt 仍 pending；面板真实 diff；待验收不等于合并 | 未量 |

模型参数、耗时、截图及事件证据在执行后补记。未经过真实 UI 和真实模型的场景不能写通过。测试留下的验收会话、工作树和版本目录保留，以便复核。

## 已发现的桌面兼容约束

- 当前安装的工具输出 schema 接受标准 JSON Schema `required: ["result"]`；不能照较新源码中的字段级 required 写法猜测。
- 插件自己的会话容器使用独立 slot，再调用 DSH 原生 `conversation.content` factory。重复声明原生 `main.conversation` 的所有权会导致客户端插件启动失败。
- 后端热更新同时需要独立 Loader ID 和独立绝对模块 URL，避免 ESM 缓存保留旧模块。
