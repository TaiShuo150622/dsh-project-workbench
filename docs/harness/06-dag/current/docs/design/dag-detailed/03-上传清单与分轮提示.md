# 上传清单与分轮评审（Claude Design · DAG 第一期）

> 公开摘编与通用模板；源版本：未编号，2026-09 起；整理日期：2026-11-06。原稿中的个人账号状态、私人反馈、实际索引导出、参考截图和原项目提示词引用未收录。以下保留工作方法，并使用合成样例要求重新表述；未重新核对第三方上传限额，也未执行新的设计轮次。

## 1 · 准备材料

| 材料 | 作用 | 公开准备方式 |
| --- | --- | --- |
| 前端结构需求 | 明确场景、区域、内容、状态与交互 | 单独提供可读文本；先写结构约束，再讨论视觉风格 |
| 合成场景样例 | 固定设计所需的数据与边界情况 | 使用明确标为示例的节点、边、状态和计数，不导出实际项目索引 |
| 正向参考 | 说明希望借鉴的层级、密度或节奏 | 为每张图写清只参考哪些方面，并确认有权提供 |
| 反例 | 防止设计重复已知问题 | 标明错误位置和原因，不把反例当目标风格 |
| 视觉方向 | 收敛颜色、字体、间距和组件语气 | 将喜欢与不喜欢的原因整理成可讨论的约束 |

原稿记录的文件数量与上传格式属于当时环境，公开摘编不把它们当作现行产品规则。实际使用前核对工具支持的格式与限额；文档中的图片、SVG 源和纯文本需求能否被读取要分别验证。

## 2 · 提供次序

1. 先提供需求，让设计方理解要解决的问题。
2. 再提供合成样例，固定每种场景要展示的内容。
3. 然后提供正向参考，逐张说明借鉴点。
4. 最后提供反例，并明确它们用于避免什么。

这一顺序让文字与样例先定义任务，图片承担视觉参考，而非让参考图代替需求。每一批只提供当前轮次必要的材料。

## 3 · 分轮推进

| 阶段 | 本轮目标 | 应停下来评审什么 |
| --- | --- | --- |
| 视觉方向 | 比较少量明确不同的方向 | 是否符合场景、信息密度和可读性要求 |
| 主画板 | 做关键场景与主要宽度档 | 信息顺序、首屏、滚动与导航是否成立 |
| 子屏与全状态 | 补展开、空态、等待、失败、陈旧等 | 状态有无遗漏，是否把不确定内容装作事实 |
| 组件画廊 | 汇总卡片、边、标记、浅深主题和变体 | 是否只靠颜色区分类别，组合是否一致 |
| 动效 | 讨论进入、退出、成型与数据流动 | 动效是否表达真实事件，减少动态效果时如何退化 |

动效是后续讨论项，不因出现在分轮流程中就视为已经实现。每一轮完成自查与反馈后再进入下一轮，不让多个未解决问题持续累积。

## 4 · 可复用的提示结构

以下是公开整理时重写的模板，不是私人会话原文：

```text
本轮只处理：<明确场景和阶段>。
请先读需求和标为合成数据的样例，再读参考图及说明。
结构约束：<区域、字段、状态、宽度、交互>。
视觉范围：<本轮可以探索的内容>。
不在本轮：<排除项>。
请给出自查结果，并停在评审点；不要自行开始下一轮。
```

下一轮开始前，先列上一轮发现的问题及处理结果，再说明新增范围。需要反馈时写清“哪张画板、哪条要求、观察到了什么”，避免只给抽象喜好。

## 5 · 评审与交接

- 逐屏检查内容、状态、交互和宽度档；不能用省略号或缩字隐藏布局问题。
- 检查灰度效果，确认类别与状态不只靠颜色表达。
- 汇总命名一致的 token、组件变体和事件，不让各画板各自创造口径。
- 明确设计图、合成夹具、接口草案和实现代码的区别。
- 为每轮记录已决定项、未决定项及下一轮范围；公开交接只保留编辑后的决策摘要，不附原始私人对话。

原始真实样例、截图、各轮完整画板与导出脚本不随本文件发布。这里提供的是组织与评审方法，不能凭本文复原原项目设计环境。
