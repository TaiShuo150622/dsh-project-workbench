# 布局内核选型试验 · 历史方法摘编

> 公开摘编；源版本：未编号，2026-10-02 至 10-03；整理日期：2026-11-06。保留选型方法、当时结论和适用边界。实际项目图、几何读数、截图、原始会话、脚本与执行证据未提供；未重新运行或复测，不能在本公开文集直接复跑。

## 1 · 比较什么

历史试验比较了三种方案：A 是自建摆放与走线，B 是主要使用 ELK 布局，C 是让 ELK 处理次序、再由自建逻辑摆放与走线。试验针对一种具体的影响面：列内次序由业务名次固定，窄档还需要把同一列折成多行。

这种约束非常重要。若通用引擎只把原有次序交回，混合方案可能增加成本却没有改变结果；若通用引擎只支持整图折行，可能无法满足单列内部折行。不能把这组试验推成“自建布局总比 ELK 好”。

## 2 · 先设门槛，再比较代价

历史门槛包括：不重叠、不穿卡、遵守固定次序、能画出应展示的边、同一载荷结果确定、能在面板的 sandbox srcdoc 环境运行，并在目标宽度内达到响应预算。不适用的用例按未过门槛处理，不能跳过后再宣称全过。

过门槛后再比较叠段、标注额外占用、交叉和响应时间。只比较定义相同的量；例如竖排的行间距代价与横排的通道宽度不应直接相加排序。依赖体积也是代价，但不能替代前面的可读性约束。

## 3 · 历史结论与边界

原稿记录 A 与 C 通过当时的门槛，C 在固定次序场景下与 A 输出相同，B 在部分折行与标注场景不适用或未过门槛。因 C 没有给出额外布局收益且增加计算与依赖代价，当时选择继续 A。

这些结论对应原试验的约束、数据和适配方式。B 的失败也涉及对格、标注与主干聚合的适配，不能直接当成 ELK 的普遍能力上限。原项目规模与几何表未公开，本摘编也不构成新的性能证据。

## 4 · 如何验证尺子

- 对实际渲染的几何测量，而非只信引擎自报字段：卡片位置、线段、行距和世界尺寸都应从输出核对。
- 分别检查同一输入重复运行、打乱输入顺序和不同历史记忆下的确定性。
- 主动构造反例：让内核抛错、故意超时、少报卡片高度，或让页面载入脚本报错，确认检查能发现问题。
- 对走线、横排约束、空列说明、扇入次序、窄档和夹具核对做变异检查，避免测试只覆盖成功路径。
- 区分内核问题、适配问题和浏览器渲染问题，保留原始结果供实施者核对。

原稿记录过布局专属测试与变异检查，但原始证据未随文集提供；这里不把它们计为当前公开仓库的测试数量。

## 5 · 人工检查仍然必要

机器门槛不能回答所有可读性问题。需要人工看主干绕行是否难读、标注是否过挤、狭窄间隙是否仍能识别箭头、窄档长图是否需要折叠。截图和实际交互应分别检查，不能只看零违规的汇总数字。
