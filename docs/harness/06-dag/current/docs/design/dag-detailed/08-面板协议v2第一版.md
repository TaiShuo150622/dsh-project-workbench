> 公开整理版；源版本：未编号；整理日期：2026-11-06。保留原稿历史阶段，未重新运行或复测。内部项目实例、个人原话与私有地址不作为公开附件。

## 1. 为什么要 v2

历史第一版在换焦点时重新装载整页 HTML，导致闪白、选中与展开丢失、历史页重算以及页内交互受限。这里保留第二版的通用设计目标，不附原项目的具体命名空间与实现。

v2：**页面常驻**（srcdoc 只在首开和崩溃重载时用），宿主用 `postMessage` **推载荷**，页面原地重画；
页面能发「换焦点 / 后退 / 搜一下 / 交给模型 / 复制」，宿主照办并回话。

## 2. 规矩（两边都守）

以下是从原稿恢复的通用约束；消息前缀与页面版本标记由具体实现冻结，本公开稿不充当完整协议注册表。

1. 每条消息具有约定的类型和协议版本；不符合形状的消息忽略。
2. 页面核对 `event.source === window.parent`，宿主核对 `event.source === iframe.contentWindow`。对 sandbox srcdoc 的不透明 origin，不能仅凭 origin 字符串认定对端。
3. 上下行各有消息白名单；未知消息不执行，不接受对端传来的任意代码，也不使用 eval。
4. 由页面版本标记选择协议路径，并保留旧页面的明确回退行为。
5. 每次换视图递增 `seq`；宿主只接受最新 `seq` 的完成回执，避免旧请求覆盖新视图。
6. 页面不自行使用持久存储或发起网络请求，所需能力经宿主提供。


## 3. 下行：宿主 → 页面（第一版使用的 6 条）

| 名字 | 字段 | 页面怎么做 |
|---|---|---|
| `env` | `theme: 'light'\|'dark'`、`surface: 'dock'\|'full'`、`caps: string[]`、`nav: {canBack, canFwd, trail: [{title, cur, cached}]≤10}`、`host: {build}` | 换主题（`html[data-theme]`）；按 `caps` 决定显示哪些按钮（没有 `search` 就只搜这一屏，没有 `draft` 就不给「交给模型」）；后退 / 前进按钮按 `nav` 亮灭 |
| `payload` | `seq`、`reason ∈ new / same / nav / reload / reopen`、`payload`（影响面载荷，形状 = `pack_payload` 契约）、`restore?: {sel, open[], scrollY}` | 原地重画；`new` 清掉选中与展开、滚回顶；`same`（宿主后台把同一焦点重算了一遍）保留选中与展开；`nav` / `reopen` 用 `restore` 还原；`reload` 保留选中。画完报 `drawn {seq}` |
| `reply` | `rid`、`ok`、`value \| error {message}` | 只认自己发过的 `need` 的 rid（其余丢） |
| `host_state` | `seq`、`run: {state: 'idle'\|'waiting'\|'failed', what, t0, last_ms?, message?, hint?, retry?: Ask}` | 等待 / 失败的**唯一来源**（§6） |
| `notice` | `tone: 'ok'\|'warn'`、`text` | 顶上一行，4 秒后淡出（不是弹窗、不挡图） |
| `event` | `kind: 'view.stale'`、`why: 'index'`、`text`、`at` | 琥珀色一行 +「重算」（§6.3） |

第一版**不用**：`delta`、`present`、`emphasize`、`act_ack`（编辑与 AI 出示的那几条，等场景②③④）。

## 4. 上行：页面 → 宿主（第一版使用的 12 条）

| 名字 | 字段 | 宿主怎么做 |
|---|---|---|
| `ready` | `page: {scene: 'impact', build}`、`view: {seed, title} \| null`（页面里内联的那一份） | 回 `env`；有历史（面板关了又开）→ 推 `payload {reason: 'reopen', restore}`；没有历史 → 把页面那一份记成第 0 屏，**后台照同一焦点重算一遍**（内联的那份是出页时算的，可能是几个小时前），回来推 `payload {reason: 'same'}`。聊天在页面 ready 之前要打开一个焦点（宿主的 `openSeed`，面板多半还关着）：宿主先记下，ready 时开它（`new`，带着聊天给的选中），内联那份照常记成第 0 屏、不在后台重算；有历史时压在关之前那一屏上面（2026-10-20 场景④复现首开被内联那屏顶掉后改） |
| `drawn` | `seq`、`ms`（页面从收到到画完） | 收掉等待态，记「这种要多久」 |
| `open` | `ask: {scene: 'impact', seed, depth?}`、`from: {kind: 'search'\|'card'\|'more'\|'retry'\|'stale', id?, q?}` | 换焦点：`view/build {mode: 'impact', seed}`；种子和当前这一屏**相同**（旧了重算 / 重试同一屏 / 又搜到它）就**替换**这一屏（`reason: 'reload'`），不同就**压栈**（`new`，后退能回来）。按种子判、不按 `from` 判：失败的往往是**新**焦点，按 `retry` 一律替换会把上一屏从历史里挤掉（2026-10-20 宿主实现时改）。种子不过白名单（节点 id 字符集）直接回 `host_state failed`、不发 RPC |
| `nav` | `op: 'back'\|'fwd'\|'go'`、`i?` | 有缓存直接重推（`reason: 'nav'`，≤ 0.5 s，面板头写「从历史取，没重算」）；没缓存（第 0 屏后台重算还没回来）照那一屏的 ask 现算。历史最多 20 屏，超了丢最早的 |
| `need` | `rid`、`seq`、`kind: 'search'`、`args: {q, limit}` | `graph/search {q, limit, kinds: [file, mod, fn, cls]}` → `reply {rid}` |
| `select` | `id`、`label` | 记下来（第一版只记，不改宿主界面） |
| `draft` | `text` | 塞进 DSH 输入框（**不发送**）；成 → `notice ok「已放进输入框，没替你发送」`；找不到输入框 → 退回剪贴板并 `notice warn` 说清 |
| `copy` | `text` | 写剪贴板 → `notice` |
| `state` | `seq`、`snapshot: {sel, open[], scrollY}` | 存进当前这一屏的历史，后退回来时随 `payload.restore` 还给页面 |
| `cancel` | `seq` | 作废这一次（seq + 1），`host_state idle`，`notice「已取消，还停在上一屏」` |
| `error` | `message`、`where` | 宿主面板头下面挂一行红字（页面自己崩了也要让人看见） |
| `summary` | `scene`（`impact` / `decide` / `arch` …：小写字母、数字、`-`，≤ 20）、`title`（≤ 80 字，人看的那一句） | 面板头换成「这一页现在是什么」。一张页里装了几个场景（studio：①②③ 切页）时，切到哪页就报一条；`scene: 'impact'` 时宿主回到影响面自己那一行（「影响面「example.py」· 算 … · 共 …」），不用 `title`。只改面板头，不碰历史、不发 RPC（2026-10-20 场景②③线程提：切到 ②③ 时面板头还写着影响面） |

## 5. 一次换焦点的时序（目标：换焦点 ≤ 2 s，回到看过的一屏 ≤ 0.5 s）

```
页面                         宿主（panel.js）                  Node 半边                    图数据服务（常驻）
 │ open {ask:{seed}} ──────▶ │ seq=7，压栈前先等 state 快照       │                            │
 │ ◀── host_state waiting ── │                                    │                            │
 │（300 ms 后旧图变淡 + 计秒 + 取消）│ view/build {mode:impact} ─▶ │ svc.call('impact') ───────▶ │ BFS + 打包这一屏（≈ 0.1 s）
 │                           │ ◀───────────── {payload} ───────── │ ◀────────────────────────── │
 │ ◀── payload {seq:7,new} ─ │                                    │                            │
 │（原地重画）               │                                    │                            │
 │ drawn {seq:7} ──────────▶ │ host_state idle，记 last_ms        │                            │
```

上图用于说明消息顺序。原项目实际索引规模与延迟读数未公开；箭头旁的时长仅保留为历史设计示意，不能当作当前性能承诺。

## 6. 三态（页面怎么画）

等待 / 失败的来源**只有** `host_state`；「旧了」只来自 `event view.stale` 与载荷里的 `meta.fresh`。

### 6.1 等待（`run.state = 'waiting'`）

- 前 300 ms 什么都不变（快的时候不闪）。
- 300 ms 后：旧图原地变淡（不撤、不白屏），顶上一行「正在算「example.py」的影响面 · 1.2s（上次 0.1s）」+［取消］。
- 取消 → `cancel {seq}`，旧图恢复。

### 6.2 失败（`run.state = 'failed'`）

- 旧图**留着**（不变淡），顶上一行红字「算不出来：{message}」+ 下一行灰字 `hint`（有就给）+［重试］。
- 重试 → `open {ask: run.retry, from: {kind: 'retry'}}`。
- 第一屏就失败（还没有旧图）：页面中间一块「算不出来」+ 原因 + ［重试］。

### 6.3 旧了

- `event view.stale {why: 'index'}`：琥珀色一行「索引在 {时间} 重建过，这一屏是之前算的」+［重算］
  （→ `open {from: {kind: 'stale'}}`，替换当前这一屏）。宿主每 30 s 问一次 `graph/stamp`，同一个时间只报一次。
- 载荷里 `meta.fresh.files`（建索引之后改过的代码文件）：
  - 有文件**在这一屏的卡上** → 琥珀色一行「这一屏上的 example.py 在建索引之后改过：线和数可能不准。请使用宿主提供的重建索引操作」+［复制命令］；
  - 都不在这一屏上 → 尾行灰字一句「另有 N 个代码文件在建索引之后改过（不在这一屏上）」。
  - 后台自动写入的记录目录不计入代码变更提示，避免持续写入使提示一直亮着。

## 7. 场景①页面（影响面）在 v2 下长什么样
