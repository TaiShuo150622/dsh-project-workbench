## 0 为什么现在建组件库

> 公开整理时略去非公开项目实例或个人会话来源；通用设计仍见本节其他内容。

所以这套组件库要做到三件事：

1. **这一版照 A 图纸的设计做完、用顺**，逻辑、数据、交互都在真实使用里验过；
2. **下一版只换皮与动效**：换 token 的值、换动效层的实现，必要时换组件的画法，**组件接口、纯函数层、契约层与测试都不动**；
3. **第一版不做动效**（拍板 2026-09-27）：组件只**声明**「发生了什么」，动效层第一版是空实现，状态变化直接到终态。

## 1 分层与边界

| 层 | 放在哪 | 管什么 | 不许做什么 |
|---|---|---|---|
| 契约层 | `web/graph/proto/`（计划中；02 §1.9.1） | 消息表、载荷解码、宿主适配、DOM 契约探针 | 不碰 DOM 样式 |
| 纯函数层 | `web/graph/ui/layout/`（第一步只有 `fit.js`：卡的档与列数）、`web/graph/ui/skeleton/`（计划中）与现有 `web/graph/ui/measure.js` | 布局、宽度档、卡档状态机、强调栈、同名消歧 | 不画任何东西 |
| **组件层（本规格）** | `web/graph/components/` | 把 view-model 画成 DOM；发固定事件；声明动效事件 | **不取数、不算布局、不写死颜色与尺寸** |
| 皮肤 | `web/graph/ui/tokens.css`（02 §1.9.2 已列） | token 的名字与浅 / 深两套值 | 组件里不出现任何字面颜色 / 尺寸 |
| 动效层 | `web/graph/motion/` | 接住组件声明的动效事件，决定怎么动 | 第一版空实现：什么都不动 |
| 画廊页 | `web/graph/gallery/` | 用固定样例把每个组件的每档每态画出来 | 不接真数据服务 |

依赖只许往上：组件层可以调纯函数层与契约层，反过来不行；动效层只读组件声明的事件，不反向改组件状态。

## 2 组件接口的通用约定

### 2.1 输入：只吃 view-model

- 每个组件的输入是一份**纯数据**（可以直接 `JSON.stringify` 的对象），由纯函数层从载荷算好，组件里不再查索引、不再算几何。
- 几何（放在哪一列、占几列、多高）由布局引擎给出，组件只负责在给定的格子里画；组件可以**报告**自己量出来的高度（给布局引擎回流），但不自己挪位置。
- 设计稿里 Card 的参数表可以直接当第一版卡片接口的底子（`Card.dc.html` 的 data-props）：

| 字段 | 取值 | 对应 03 |
|---|---|---|
| `fam` | arch · code · iface · doc · data · decide · guard · trail · work | §6.1.4 九族 |
| `type` | 类型牌文字（文件 / 函数 / 文档 / 待拍 …） | 槽 S1 TypeBadge |
| `size` | chip · brief · card · open | §4.5 size |
| `cols` | 1–7（芯片 1–2、名片 2、卡面 3、展开 7；由布局给，不由卡自己定） | §3.5 |
| `title` · `where` | 标题（带消歧后缀）· 位置行 | 槽 S2 · S3 |
| `state` | 九态（ok 不画） | §6.1.7 |
| `marks` | corner（≤ 3 +「+k」）· chips · bar（进度带）· frame（还不是事实）· halo（此刻在跑） | §4.5 marker |
| `emph` | focus · lit · trace · dim；外加 `by`：me（我点的）/ ai（AI 指的）/ scene（场景给的） | §4.5 emph、§8.3 |
| `rows` | 类型行（RowModel，行态 fact / zero / unknown / restricted） | 槽 S6、§4.5 rowState |
| `sup` | 聊天里名字后的上标类型字 | 第二轮借 B |

### 2.2 输出：固定的事件

> 公开整理时略去非公开项目实例或个人会话来源；通用设计仍见本节其他内容。

| 事件 | 什么时候 | 带什么 |
|---|---|---|
| `select` | 点一张卡 / 一条边 | 目标 id、`by: me` |
| `expand` / `collapse` | 卡长大 / 收起（档位变化） | id、`from → to` |
| `openFace` | 切 open 卡的面 | id、face |
| `fold` | 面内摊开 / 收起（**新增 2026-09-27**，待并入 03 §4.5 / 01 §3.4）：代码面提纲 ↔ 全部摊开、摊开一个符号；文档面按节折叠 / 看全篇 / 只看相关、开合一节；概览 / 材料的段收起、「还有 N 个」 | id、face、key（`*` = 整面换态，否则是符号名 / 节的起始行 / 段键）、to |
| `navigate` | 去另一屏 / 面包屑 / 蓝字 | 目标视图键 |
| `act` | 点动作条上的按钮（复制运行清单、交给 AI、重算……） | 动作 id |
| `edit` | 编辑开始 / 写回 / 取消 | 字段、值 |
| `clearEmphasis` | 点说明条的「清除」「上一步」 | —— |
| `retry` / `cancel` | 等待态与出错态的按钮 | 任务 id |

### 2.3 状态键

只用 03 §4.5 那张表的键与取值（size · state · emph · evidence · rowState · tone · verdict · cell · marker · band · widthTier · surface · DockForm），不另起名字。

### 2.4 动效事件（声明，第一版不实现）

组件在状态变化时发一条**动效事件**给动效层，第一版的动效层直接忽略它、状态直接到终态。事件表按下一版要对齐的「动词」来定，这样下一版只换动效层：

| 动效事件 | 什么时候发 | 下一版可能对应的动词（参考下载夹 `weave-*.html`，只作方向） |
|---|---|---|
| `enter` / `exit` | 卡或边第一次出现 / 离开画布 | 生长 |
| `grow` | 卡换档（from → to） | 聚焦 |
| `yield` | 邻居为长大的卡让位 | （让位） |
| `emphasize` | 强调栈入栈 / 出栈（level、by） | 退场（压暗）、聚焦 |
| `stateChange` | 九态变化（from → to） | 抖动（只给红了与出错） |
| `decide` | 待拍被人拍板 | 盖章 |
| `append` | 列表 / 记录追加一行 | 追加 |
| `count` | 答案句里的数变了 | 计数 |
| `drawEdge` | 边第一次画出 | 生长 / 流动 |
| `stream` | AI 正在写（工具卡运行中、写回中） | 书写 |

规矩：**每个事件只表达一件事**；同一时刻只有一个前台动效；人再点就直接跳到终态；「减少动态效果」时一律终态。这几条下一版照守。

### 2.5 DOM 契约

每个组件的根元素带 `data-dag-*`（02 §1.9.1 的 `web/graph/contract/probe.js`（计划中）读它们）：至少 `data-dag-id`、`data-dag-kind`（组件名）、`data-dag-fam`、`data-dag-size`、`data-dag-state`、`data-dag-emph`。画廊页与真面板都跑同一套 `lintDom`（`web/graph/components/lint.js`），查：最小字号 ≥ 11 px、无省略号、无截断、尺寸是 u 的整数倍、主栏之外没有别的纵向滚动、没有只靠悬停才看得到的信息。第三到六轮我对设计稿用脚本量过其中四条（最小字号、省略号与截断、主栏外的纵向滚动、横向滚动），第六轮时全部画板通过；「u 的整数倍」「只靠悬停」「字面色值」三条还没对设计稿量过，第一次在画廊页上量（2026-09-27 第一步：画廊 128 格浅色、深色全过）。

### 2.6 每个组件的交付物

1. 组件本身（只调纯函数、只用 token）；
2. 画廊样例：这个组件每档、每态、每种变体各一格（样例数据取自 `给Design*` 目录里的附件，和设计稿同一份数）；
3. 测试：接口测试（给定 view-model → 期望的 DOM 契约属性与文字）、`lintDom` 通过、至少一条负向用例先自证会红。

### 4.1 展开卡与面（2026-09-27 实施时定的；设计稿没画整张展开卡，照 03 §6.2 的文字做）

**接口**：Card 在 `size = open` 且带 `faces` 时，卡里交给 `web/graph/components/open.js`（`OpenInner`）。输入是纯函数层 `web/graph/ui/layout/faces.js` 的 `openView(model, {cols, bodies, container})` 算好的视图：代码续行、md 分节、段的「还有 N 个」、动作分进「更多」都在那里算，组件只画、不截。模型在 Card 的 view-model 上多这几项：`status {flags ≤ 2, why}` · `actions [{id, zh, glyph?}]`（`openView` 把前 4 个留在卡头、其余并进「更多」，「更多」原地展开一行；`glyph: true` 表示文案里的「…」是字形，如「从这里找路到…」）· `faces [face 键]` · `face` · `body {<face>: …}` · `foot {src, fresh, edits}` · `stale {t, act}`。正文（代码行、md 行）不在模型里，走 `bodies[path]`；没有就画「代码 N 行（未外发）」占位。

**卡头分行排**（和 03:965「第一行 类型牌 · 标题 · 出处 · 状态 · 动作；第二行 面签条」的字面不同，是有意的）：类型行（记号 · 图标 · 类型牌 · 角标 · 动作 · 收起）→ 标题 → 出处 → 状态整句 →（字片 · 进度带）→ 面签条。理由：03 §6.1.2 规定槽位「从上到下、所有类型同一次序」、open 的 S2–S4 与 card 档相同，§6.1.3 又规定字片 / 进度带在「卡头下」；照这两条，面签条不可能总在第二行，7 列也放不下标题全文加动作一行。

**九个面的英文键**（新增，待并入 03 §4.5 / 01 §3.4）：overview 概览 · code 代码 · doc 文档 · raw 原文 · struct 结构 · inside 里面 · graph 图 · material 材料 · infer 推测。面签按这个次序排；`doc | raw` 画成一对，两面共用一份摊开状态（缺一个就用另一个）。只列有内容的面（模型里有它的 body，或正在取）；材料 / 推测整面为空不出面签；推测面体这一版没做，做出来之前不出面签。开哪些面按容器：`visibleFaces = faces ∩ FACE_EXITS[container] ∩ 有内容`，这一版只登记了 dock（聊天、架构框接进来时再登记）。

### 4.2 边（2026-09-28 实施时定的；同日对抗审查 76 条、核验 73 条为真，修完后改写）

**分层**：走线纯函数 `web/graph/ui/layout/route.js`（给定已落格的卡矩形算正交折线，不挪卡）· 强调栈纯函数 `web/graph/ui/layout/emphasis.js` · 组件 `web/graph/components/edge.js`（EdgeLayer · Caption · EdgeCard · EdgeLegend）· 几何尺子 `lintEdges`（在 `lint.js`）。卡放在哪一列、行间距多高是布局的事：这一版画廊扮演布局（按层摆、量卡高、走线、按走线报的需求加宽行间距、再走一遍直到收敛；走线来回几遍连线层不卸载），真排法等布局引擎。

**走线**（这一版只管竖排分层）：`route({cards, rows, edges, corridor, opts})` → 每条边**独有**的那段点列、主干、行间距需求 `need`、走廊宽 `corridorNeed`、编号对照 `legend`、画不出的 `unrouted`、画出的边数 `drawn`。输入的边是**原始关系**（from → to 是索引方向，`count` 是有几处）；`opts` 给网格（u · 列 · 间距 · 左边距 · 画布宽），箭头长 = u、断开 = 3u，全跟着 u 走。
- 只有横段和竖段，拐点都在 u 格上；线不进任何卡，也不贴着卡边走（离卡边 ≥ u）；尾卡底边出、头卡顶边进（同层边两头都在底边），同一条卡边上的几个口以中点为中心 2u 一档排开，挤不下改 u 一档，再挤不下的边不画；口一律夹在 [卡左 + u, 卡右 − u]；左右挪 u 能让相邻两层之间的线正对就挪（直线不拐弯）；
- 合并：同一对端点（按画出方向）、同一证据档的几条合成一条粗线，标注按关系现算计数（「import 28 · 调用 61」）；带断口的不合；
- 主干：同一个尾（**扇出**）或同一个头（**扇入**）、同一证据档、朝下、不带断口的边 ≥ 2 条合成一根。出口（扇入是入口）竖段和总线上**两支以上共用**的段归 Trunk 组，每段记着哪几支走它；每支只画它独有的那段（热区照这个切：点共用段选中这一组，点独有段选中那一条）。扇出各支带箭头；扇入的箭头归主干的入口竖段，分支不带；
- 跨层时竖线会穿过中间层的卡、或和别人的竖线重合，就走列间距中线（x = 左边距 − 间距/2 + k·(列 + 间距)），从离头最近的一条往外找（一样近先右边），找不到就不画（记进 `unrouted`：「跨层找不到不压卡的列间距」），**绝不静默穿卡**；
- 回边走布局留出的走廊列，按条数分道（2u 一档），跨得越远的越靠外（嵌套的回边不交叉）；道不够的不画；没有走廊的回边先判出来，不占口；
- 同层边走下方的行间距绕过去（U 形），不从中间的卡上穿过；
- 落线避让：往下进头顶的竖线正对别人从尾底出来的竖线时，换到头顶边上的下一个空口（2u 一档，不挪到同一张头卡别的入口上）；
- 行间距需求 = n·u（n 条轨，第一条离上面 u、轨与轨之间 u）+ 标注行 × 2u + 箭头长 + u，2u 一档取整；第一层上面那条（回边进第一层）从第一层卡顶往上排；断口所在的行间距还要放得下断开 3u + 上下各 u；
- 标注：只放在横段上方或竖线旁的行间距里，标注行夹在上一条线和自己那条轨正中（字的外框约 1.33 倍字号，放进 2u 一行上下都不碰线）；退档 一行全称 → 两行全称（在最靠中间的空格处断，第二行不以「·」「/」开头）→ 短词 → 编号圈（直径 2u），编号对照进图例「边的读法」；候选位置逐个试，不压卡、不压任何一条线（含箭头）、不互相压；主干的成员标注都相同时只标一次（出口 / 入口竖线旁、两边哪边长标哪边），不同就各标在自己独有的那段竖线旁（扇出在总线下方那一行，扇入在总线上方那一行）；
- 收桩：同一个尾、同一证据档，**不同的头**到了 6 个（超参 `dag_edge_bundle_min` 的值，还没登记）才收、留前 4 个头；数的是头不是边（同一对的几条边算一个）；带断口的不收；桩 id = `stub:<尾>|<证据档>`；桩走卡层（先用芯片「另外 N 个」，完整 StubCard 后做）；桩那条线的关系 = 这一组的关系（组里只有一种时）；
- 断口：落在这条边独有的那段上（朝下 = 进头顶的最后一段竖线；回边 = 走廊里的竖段；同层边 = 横段），真断开 3u（两端在 u 格上），叉在正中，旁写「断：<断口名>」；放不下不丢，退成编号、图例里写「断：名」；
- 端点不在图上的边不抛错，记进 `unrouted`（「端点不在图上」），交给图例写「另有 k 条没画：原因」；

### 4.3 列头（带头）· 列组头 · 空列结论（2026-10-04 起草，**待你过目；过目前不写代码**）

**为什么现在写**：布局引擎第 4 步已经照 fit.js 的暂定式子给这三样留了格子（06 §4.0.2、§4.0.3），组件还没做，所以 R14「预测高 = 实测高」只有 Node 那一半。这一节定三个组件的名字、接口、画法与验收。尺寸全照 fit.js 现在的暂定式子（10-04 你选的「尺寸照 06 暂定式子」）；做出来以后 DOM 实测要和式子逐张相等，改一边就得两边一起改。

**名字**（待并入 01 §3.4，那边已加一行草稿）：

| 中文 | 组件 | 在哪 | 页面键（= SizeReport 键） | 不叫 |
|---|---|---|---|---|
| 列头（竖排时叫带头） | ColumnHead | 横排：列头行里每个语义列一格，宽 = 这一列的宽，通道列上面不放；竖排：每条带左端那 1 列（有走廊列时在列 1） | `head:<列键>` | 不另起 BandHead（同一个组件，`flow` 不同）；不写 L1 / L2 层号（03:1824） |
| 列组头 | ColumnGroupHead | 横排：列头行上面一行，从组里第一列左边到最后一列右边，中间插的通道列一起盖住；竖排不单画，字写成第 1 跳带头的第一行（06 §4.0.3） | `head:group:<组键>` | 列组总头、hop 总头 |
| 空列结论 | EmptyNote | 没有卡、有一句结论的列。竖排：带里第 1 个格子行，宽 = 整个卡区；横排：分到一列时在列头下面（W(1) = 96）；分不到时并进右邻列头（最右那列没有右邻就并进左邻） | `note:<列键>` | 结论行（那是卡里为 0 的那一行，03:846）；ConclusionCard（画布中央那张，03:899） |

**接口**（只吃 view-model；几何由布局给，组件不挪位置）：

- ColumnHead 的 vm = 布局结果的 `heads[列键]`（x · y · w · h · notes? · group?）并上列本身：

| 字段 | 取值 | 从哪来 |
|---|---|---|
| `key` | 列键 | Column.key |
| `title` / `short` | 列名原文 / 短名；标题按 1 列内宽折 3 行以上才换 short | Column.title / short |
| `role` | seed · basis · hop … | Column.role；seed、basis 不画计数（03:1509） |
| `drawn` / `total` | 「画出 k / 共 n」；k 只数真卡，组卡的数在组卡「还有 N」里，不数虚节点 | 布局按列数卡 / Column.total |
| `note` | 说明，按排法取 `note.lr` 或 `note.tb` 那一句 | Column.note |
| `inPayload` / `toFetch` | 芯片「+N 在这一份里」「+N 要去取」 | 场景 |
| `folded` | 「另收起 N」 | 布局 folded（第 5 步才有） |
| `notes` | 并进来的空列结论 `[{col, text}]` | heads[k].notes |
| `group` | 列组头的字（只在竖排第 1 跳带头上） | heads[k].group |
| `flow` | lr · tb | result.flow |

- ColumnGroupHead 的 vm = `result.groupHead`：`{key, x, y, w, h, text, cols}`；text =「会被波及 · 共 N 个」，N 取场景 `folded.units`（06 §4.0.3，不拿各列 total 相加）。
- EmptyNote 的 vm = 布局节点 `note:<列键>`（kind = note）：`{key, x, y, w, h, text}`。

**画法**（token 照 §3；字号、内距、行数的算法和 fit.js 一一对应）：

- **ColumnHead**：不画框；底色 = 画布 `bg`（按 06 线本来就不进列头，这一层只是保险）；内距四边 u。从上往下：列组头的字（竖排第 1 跳才有；11/16 `muted`）→ 标题（600 11/16 `ink`，正文切法：只在空格与 `-` 后折）→ 计数「画出 k / 共 n」（11/16 `muted`；没有 total 写「画出 k」）→ 说明（11/16 `muted`，见下面待拍第 1 条）→ 芯片行（每个芯片 = 字宽 + 左右各 7 px，含 1 px 边；芯片之间 4 px；一行 16 高，放不下换行）→「另收起 N」（11/16 `muted`）→ 并进来的空列结论，每条一段（11/16 `ink`，写法见待拍第 2 条）。行高一律 16；h = 2u + 16 × 行数，取到 16 的倍数。
- **ColumnGroupHead**：不画框，底色 `bg`，内距 u；一行字 11/16 `muted`；下边一道 1 px `line` 横跨整格（画在内距里，不改高），表示它管下面这几列。h = 2u + 16 × 行数（「会被波及 · 共 14 个」在 5 列宽里一行，h = 32）。
- **EmptyNote**：不画框、不画底；内距 2u；整句 11/16 `ink`（它是这一列的结论，不是说明）；不连线。h = 4u + 16 × 行数。
- 三样都不截断、不出省略号（§5 第 2 条）。横排列头行（连同列组头行）吸顶是画布台 Stage 的事，骨架还没做；这一版组件只在给定格子里画，不自己 sticky。

**事件**：ColumnHead 点标题 → `select {id: head:<列键>, kind: column, by: me}`（03:1240「点列头标题 → 这一列的卡全部强调」；这一版只发事件，强调栈的 column 解析器随骨架接）；芯片 → `act {action: reveal, col, from: payload | fetch}`、「另收起 N」→ `expand {id: g:…}`（都是第 5 步折叠那边接）。ColumnGroupHead、EmptyNote 不发事件。

**DOM 契约**：根元素 `data-dag-kind` = ColumnHead / ColumnGroupHead / EmptyNote，`data-dag-key`（页面键）、`data-dag-id`（列键 / 组键），`data-dag-obstacle="1"`（线不许穿：lintEdges 的障碍从「Card」扩到所有带这个属性的）；ColumnHead 另带 `data-dag-flow`。内部各块 `data-dag-part` = HeadGroup · HeadTitle · HeadCount · HeadNote · HeadChips · HeadFolded · HeadMerged。

**画廊**：新开一组「画布头」，使用冻结的合成样例覆盖列名、说明、空列结论和计数；原项目真实附件未公开：
1. 竖排带头 4 格：种子（不画计数）· 第 1 跳（第一行列组头 + 计数 + 说明 + 两种芯片）· 第 2 跳（标题长、换 short）· 照着它改（说明长）；
2. 横排列头 3 格：2 列宽普通 · 并进了一句空列结论 ·「另收起 N」；
3. 列组头 2 格：跨两列加中间 1 列通道（5 列宽）· 跨三列、没有通道；
4. 空列结论 2 格：竖排卡区宽（6 列）· 横排 1 列（折几行）。
深色照同一套 token 自动出。

**验收**：
- 每格外面一层写 `data-g-box-h`（同一份 vm 调 fit.js 的 headBox / noteBox 算），DOM 实测逐张严格相等（R14 的 DOM 那一半，06 §7.9）；
- lintDom 全过；lintEdges 认 `data-dag-obstacle`，负向用例「一条线穿过列头」要红；
- 接口测试：vm → DOM 契约与文字（种子不画计数、什么时候换 short、并进来的结论、列组头的字、竖排第 1 跳带头第一行）；
- 变异体：每条新断言先破坏被测物、看它真红。

**要你拍板的（都有默认，不答就照默认做）**：
1. **列头说明超过 2 行**：fit.js 的暂定式子把说明封在 2 行，但画的时候照 §5 第 2 条不许截，两边一定对不上。默认：说明全画、列头跟着变高，fit.js 去掉那个封顶。另一个做法：列再多给一句短说明，超过 2 行换短的（注册表要多一个字段）。竖排 1 列内宽只有 80 px、一行 7 个字，「它用到的接口，改的时候守住它们的口径」要折 3 行，这条真会碰上。
2. **并进列头的空列结论怎么写**：默认「列名：结论」（06 §4.0.2 的样例就是「照着它改：它不依赖仓内任何东西」）；引擎把列名拼进 notes 的 text，fit 照拼好的量，组件原样画。
3. **列组头的字**：默认 11 号常规、`muted` 色，下边一道细线；要更醒目就改 600 粗（fit 量法跟着改）。
4. **空列结论用墨色**，不用 `muted`：默认这样。

## 5 第一版必须守的行为规则

前五轮设计核对形成的通用约定如下；原始会话记录未随公开文集提供：

1. 只有主栏一处纵向滚动；不弹窗、不浮层、不 toast。
2. 字不截断、不出省略号；放不下就升档或滚动，**不缩字、不缩像素**；「装下全部」只按 卡面 → 名片 → 芯片 逐档收，收到底仍装不下就写「还有 N 张」照常滚动。
3. 芯片少用；名字一行放不下占 2 列；最多 2 行；同一排并排的芯片同高（09-26 拍板）。
4. 虚线只表示「还不是事实」；文档、会话记录、检索命中用别的画法。
5. 强调不借状态色：强调用 `ink` / `link`，琥珀只给状态；「我点的」「AI 指的」分得开。
6. 界面上不出现「最多 N 条」「上限」这类字，也不出现画板编号。
7. 页脚第一句永远是本屏箭头的读法。
8. 面板、聊天工具卡、插头文字第一行对同一问题说**同一句话**（03 §14.1 S14）。**插头今天做不到**（`graph_impact` 返回的是结构化数据，没有这句话）——实现时补。

第六轮核稿新加的（设计稿没改，由实现照这里做）：

9. **没有只靠悬停才看得到的信息**：设计稿 P27 的边「预览」是悬停出关系句，实现时同一句要点一下也能看到（聊天里根本没有悬停）。
10. **全屏架构格子（A-01）保留框之间的连线**，照 893 纵排那套直角走线；全屏宽度用上（框用卡面 3 列，或把空列给「谁在动 / 进度」旁注）。
11. **聊天缩影**：聊天可见宽 ≥ 400 px 时保持完整，只有停靠 893 把聊天盖到不足 400 px 时才收成一行（半开 294 和窄条 56 都保持完整）。
12. **计划链要画等待线**：被挡的卡连到它等的卡；先后倒挂的那一对（例如后置任务已开始、其前置任务尚未开始）最显眼。
13. 深色下九态记号、强调框、此刻在跑两两分得开；对比度照 §3.3 的表。

## 7 实施顺序与验收

照 02 §4.2 的 P1 步骤，组件库插在前置修复之后、场景屏之前：

1. **S0 前置修复**（02 §3，隐私 P0 仍推后）。
2. **token 与画廊壳**：`tokens.css` 两套值、画廊页骨架、`lintDom` 与它的负向用例（先放一个 10 px 的字，看它真的红）。
3. **卡**：Card 九族四档 → 九态记号 → 标记位 → 特殊卡；每做完一种，画廊里对应格子亮起来。

5. **场景专属组件**，再把场景屏拼起来（首页 → 影响面 → 待拍 → 架构 → 聊天）。
6. **接进真面板**（DSH 插件）：换视图 = 宿主推载荷；真数据下再跑一遍画廊同款检查。
7. **验收**：终点屏的四项在真面板上由你判「看得懂」。

每个组件「做完」的说法：画廊里它的全部格子都在、`lintDom` 全过、接口测试与负向用例都在、没有字面颜色与尺寸。
