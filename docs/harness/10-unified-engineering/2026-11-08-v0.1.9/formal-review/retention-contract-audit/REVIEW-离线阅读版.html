四个情景的直接核对

逐项读初态、扰动、observe、oracle 和 does_not_prove，未运行或机械穷举。下列是条件推导，不增加测试或证明数量。

  • RR01：旧观察晚到与新 ID 重新抽取是两种入口。观察 ID 的撤回只挡前者；案例另假定冻结政策限制 source v1 对命题 k 的当前使用，才拒绝后者。未扩成全来源禁用，替代来源 b 保留；替代项验证与撤回不产生反证的边界一致。
  • RR02：只取得 blob ACK 而 cache/inline receipt 尚存，不能满足五项受管范围的清理结论；尚有旧生产者时即使当前五项都查过，也不能把历史扫描当未来写入屏障。它明确区分 blocked delivery 和 storage removal，而非把一个布尔 epoch 当认证或围栏证明。
  • RR03：GA 撤回与 D2 处置摘要作用于不同依赖。第一次变化可保留 RB；第二次只有明确范围、有效处置权及政策优先关系成立才限制 RB。独立性/优先关系未知时 oracle 保留 UNKNOWN，而非默认全删或全留。
  • RR04：snapshot20 缺 D3/cut21 时，旧 requestId 命中旧 payload 缓存也不能跳过当前披露规则。D3 状态缺失或寿命结束而旧快照仍可回流时，不能把“没找到 tombstone”解释成“没有删除”。新受限表示不宣称逐字原日志重放。

这四例仍为 PROPOSED_NOT_RUN。其 SUCCESS 表示未来验收应观察的接口区分，不表示真实删除、全世界清除、业务完成或一般定理已经成立。
