# M12 · Record 内容处置与重处理契约 v0.1.0

2026-11-08 · 纸面提案 PROPOSED_NOT_RUN · 未实现采集器、删除器或迁移器

**删除要求不能被“原始事件不可变”覆盖；可审计也不等于原文永远可读。** 本稿只约束明确有限的受管对象、表示及操作，不证明全世界副本清除、语义无泄露、存储介质擦除或模型遗忘。旧底座要求检查摘要/索引/缓存残留，Record 原稿要求重处理不无声复活；本稿把它们接到当前模型。读取版本与范围见 [sources.json](sources.json)。

**六种操作分开**

| 操作 | 改变什么 | 不自动改变什么 |
| --- | --- | --- |
| 证据撤回 | 指定 observation 不再参与相应评估 | 不新增反证，不删除正文或其他来源 |
| 更正 | 验证替代项后接纳旧→新关系 | 不把最后到达当最新真值；旧内容能否保留另判 |
| 单主体撤权 | 该 Grant 及实际依赖它的消费/委派 | 不使全局产物消失，不撤销 B 的独立权利 |
| 指定内容删除 | 政策指定版本、表示、副本及传播路径的保管/交付 | 不证明原断言为假，也不自动撤销全部派生物 |
| 审计元数据保留 | 仅保留政策允许的发生事实、处置与收据 | 标题、ID、摘要、散列并非天然无敏感性 |
| 独立发布的派生物 | 按 releaseDecision 及当前有效政策消费 | 曾合法发布不等于永久豁免；无需强制每人可读全部祖先 |

四态仍按合格正/反证分别计算。原件被删是否影响证据资格，由评估政策决定；不能因反证不可读就宣称争议解决，也不能因没有支持就制造反证。所需原件无法复核时，保留缺口及不能重新核验的边界。

**最小处置记录**

处置决定应携带：decisionId/revision、经认证主体及权限依据、操作种类、政策版本、有效切点/期限；目标 namespace、对象/内容版本、必要别名与来源关系；受管存储/索引/缓存/日志/输入包域；对各项要求删除、阻止交付、重算或允许保留的规则。允许保留须列字段、接收范围、用途与期限，不能由执行者临时删掉难处理的分母。跨日志切点保留 history/incarnation，不能只比较序号。

来源删除、局部副本删除、当前解释更正的范围不能互换。范围/处置权不明时报告待定，不能把请求已收等同已授权、已阻止读取或已清除。

**生效、清理与重建的顺序**

1. 核验决定，冻结有限对象/表示清单和可核枚举依据。登记其生效边界后，先阻止政策禁止的新读取、注入和发布；随后清理或重算。不能等待后台索引扫完才处理已知禁止交付。
2. 正文、摘要、向量/全文索引、缓存、内联事件 payload、工具回执、ContextManifest 和备份按纳入的范围逐项处理。记录目标版本、执行方法、后端确认、核验时点及未核项。删掉 blob 不证明其他表示消失；unlink/删除 ACK 也不证明介质不可恢复。
3. 生产者保存来源版本/lineage 和处置水位；受管写入/发布核 sourceVersion 与 dispositionRevision，并与新处置有共同顺序或等价可核拒旧机制。只在开工时查 epoch 不够。删除确认后，旧 worker 的迟到摘要不得换新 ID 再注入；若只能拦输出、不能阻止旧 worker 重新落盘，只能报告交付隔离，不能宣布存储删除完成。只挡原 observationId 也挡不住从旧来源重新抽取。
4. 恢复旧快照、回灌备份及重放前，先取得该域有效处置控制状态，并补齐相关尾部；无法确认则不对外开放旧内容。处置标记的保留许可、寿命与旧快照/队列可回流窗口要匹配，不能假设标记永久存在。恢复和新 ID 都不能重新授权。更正后的旧版本如仍获准保留，只能按明确历史语境使用，不能静默成为当前事实。
5. 清理结论用 M10 的固定域和逐项收据推导。未知副本、未完成备份处理、未确认在途生产者仍列 gap；不得返回全局“已彻底删除”。范围后来扩大形成新版本，旧结果只说明旧范围。

上述顺序是接口条件，不规定新增中心服务，也不要求无关工作停下。完整 lineage、受控入口、可信枚举及声明的生效一致性仍需宿主落实；已发送到外部或已进入模型的内容不能靠本地标记召回。

**审计、回执与重放**

可以把允许保留的最小控制记录与受处置的正文分开，但不能默认所有元数据都可保留。历史查询和同 requestId 回执重送也检查当前披露政策；需要裁剪时返回明确的受限历史表示，不暗称逐字原回执。若连某事件的存在性都不允许保留或披露，不能承诺该审计事实仍可提供。

P1 的同日志确定重放只适用于原前提。删去 payload 后，应明确新表示/投影版本、缺口及允许的检查点；没有兼容依据就不声称重建原状态。P3 的审计单调只覆盖仍获准保留、继续只追加的控制范围，不能成为拒绝有效删除的理由。证据不可再读时，可能仍可核“当时接纳过处置”，未必能重新证明旧业务结论。

派生摘要另核输出版本、转换、接收人、用途及 validityDependencies。撤销 A 的读取权不自动删除 B 的独立摘要；有权新删除决定若明确覆盖该摘要，则旧发布决定不能挡住它。canConsumeResult、canReadEvidence、canRevalidate 分别说明。
