# 研究成果导读与待决策事项

这轮把工作台、Coding、Record、DAG、远程执行和长期改进连成一份可检验的工程方案，补上来源、条件证明、反例与实施依据。统一运行链路仍待接通。第一次阅读，先分清以下六项。

1. **已有代码：工作台与 Record。** 固定版本工作台代码已有项目、线程、原生会话和 worktree 关联，以及基本状态与差异展示。Record S1 研究内核在普通 PR 合并的窄场景中已有确定性重放、普通命令精确重试和版本绑定验收等能力；它处于草稿 PR，尚未接入工作台可信命令入口。这些是本轮研究的固定输入。
2. **新增设计：把交付路径连起来。** UI 选择形成稳定引用，改动前看影响，执行后按当前版本验收；Record 为下一步提供依据，DAG 指出受影响部分，远程未知效果保留责任与费用负担。新资料还可形成“保持、小修、替换，以及何时采用”的工作方法提案。整体属于待实施设计。
3. **已完成两项条件证明。** 在明确的有限无环依赖等前提下，局部重算与全量重算一致；在预算模型的合法转移规则下，有限执行轨迹不突破约定上界。证明已编译并经复核，真实系统是否满足前提仍须工程验证。
4. **已运行有限检查，保留反例。** 证据冲突、更正、取消、迟到消息、接管和资源等模型，连同固定源码探针，帮助找出不能混用的状态与边界。它们检查声明模型或隔离输入，尚未证明真实宿主中的完整恢复与交付。
5. **已有实施和评价方案，尚未执行。** 七个 I 切片从可信入口与正确状态显示逐步扩展。小规模试点评价任务成功、人工负担、连续性、恢复和全部成本，先校准观察链；复杂记忆、多代理或工作流尚无本项目收益结论。
6. **已有可讨论的对外材料。** 机制对照、来源册、复核与复跑入口、假想交付例子及登记简介已经整理。登记文案仍待讨论，未提交；未来适配器与统一产品不能列成已交付成果。

**建议阅读顺序：** 先读[链接检查器例子](../worked-example/EXAMPLE.md)，理解正向交付与两种收尾；其中角色、产物和权限均是假设，未运行。再读[决策摘要](../decision-brief/MEMO-v0.1.1.md)和[统一主稿 v0.1.6](../../统一Harness工程与形式化基础讨论稿-v0.1.6.md)，讨论结构与取舍。需要核对成果时，按项打开[证据页](../../EVIDENCE.md)及[复跑说明](../../REPRODUCE.md)；全部专题保留在[完整索引](../../README.md)。

**实施顺序保留：先完整通用面板 P01–P15，再工作台 B01–B12。** H/I 是研究验收路径；不能自行替换原排期。进入实施前，需要用户明确五项：

- **首批范围与验收人。** 阶段 A 冻结哪些卡片、接口与完成条件；若提前做 I01 的独立验证，明确它如何回到 P/B 计划。
- **首个宿主与入口。** 先支持哪个宿主版本、哪条受信入口及何种身份粒度；实际身份能力另行核验，不能由请求正文自报。
- **远程采用方式。** 首次接真实目标时选本地 Agent 调远程工具（A）还是远程 Agent（B），以及断线后的责任者。首片只验证命令与状态，不必提前承诺远程产品形态。
- **交付及收尾标准。** 首个演示任务允许哪些动作，谁验收当前版本；产物可审阅而动作、费用仍未知时，哪些义务必须保留。
- **是否继续增加复杂度。** 最想减少哪种人工负担，需守住什么质量与总成本边界，得到什么证据才扩大 Record、DAG 或自动改进。先冻结评价办法，不预设复杂方案必胜。
