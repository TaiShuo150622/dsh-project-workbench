# 统一 Harness 工程决策备忘 v0.1.0

2026-11-08 · W-08 · 仅依据本轮已核材料，不新增产品调研

**建议保留的是一个可逐步检验的完整工作系统方向。** 用户应能从选中需求、引用讨论、改动前看影响，一直走到实际交付与版本验收，再判断经验是否值得复用。三个取舍如下，均为研究主张，尚未证明整体收益。

1. **统一工作契约，让执行宿主可替换。** 共同定义任务、历史、尝试、效果、证据和验收，模型循环、工具执行和环境继续用各宿主擅长的实现。代价是需要明确适配及版本维护；价值假设是减少跨插件误解并降低更换宿主的成本。首片只做可信历史入口与准确状态，后续按 I02–I07 解锁，不能由“大工程”推导出必须先重写底座。

2. **保留原始依据，让上下文和图成为可重建的工作视图。** Record 的轮后摄入、后台整理、调用前选材分别优化；近期纠错与当前权限必须进入实际调用。DAG 帮人看影响，证据支持关系另按类型判断。代价是来源、版本和消费范围要维护；自主本体、独立选材模型与全历史常驻都须和简单检索比较，不能成为先验必选项。

3. **以有效交付和人的负担约束自治与成长。** Coding 的预测、检查、诊断和经验循环应推动下一项工作；每加一个规划器、评审者或记忆步骤，都要计入失败、等待、维护和人工成本。保留适用范围明确的经验，隔离留出反馈。模型升级后重新消融；既有 12-run 方案只校准测量，不能证明有效或无效。

**应借用的轮子。** 优先复用 DSH 的插件、会话、工具流水线与现有工作台壳；接 OpenAI 时使用其 Codex/SDK 会话与执行接口，接 Anthropic 时使用已有工具发现、工作流和记忆接口，不再各造一套。Qwen 的原始工具来源分型、腾讯 tRPC 的图/checkpoint 机制可作为适配和验证参照。需要持久编排时，先比较 LangGraph、Temporal、DBOS 等现有机制；不默认同时引入它们。其恢复、保存失败、取消和外部效果边界各自不同，不能仅凭功能名互换，也不能继承未覆盖的保证。具体底座未选定。

**可以独立交付什么。** 候选差异是把已有机制接成可检验的工作契约；没有证据称其为已证实创新。

| 独立成果 | 当前状态 | 外部如何验证 |
| --- | --- | --- |
| 条件证明、有限反例与来源包 | 已有材料和回执 | 固定输入复跑，核对假设及反例边界；不能替代产品测试 |
| Record 窄域内核与映射说明 | 已有固定代码、合成检查；Draft PR 未合并 | 重放短轨迹，核对历史/支持/验收差异；可信入口仍待实现 |
| 宿主适配契约与行为样例 | 16 场景/43 变体为未运行提案 | 后续至少两个真实适配器运行同一场景，保留目标读回与失败 |
| 工作台闭环、上下文与改进插件 | 七片任务书及评价设计；未来产品 | 实际走完选择→引用→影响→执行→验收；冻结扰动/交接后判终点，测质量、人工及全部成本 |

**哪些结果促使收缩或换路线。** 若后续冻结对照中，复杂记忆或编排没有达到预定收益却增加总成本，收缩该组件；若共同契约总需宿主特例才能工作，缩小公共内核，保留宿主专用适配；若首个真实闭环缺可信身份、效果观察或可理解的验收，先停在对应切片修补，不能靠增加功能或证明数量宣称进展。安全早停、资源截断和正确保留 unknown 都不等于交付成功。

下一次投入讨论应由这些证据驱动：首片能否真实落地、共同契约能否复用、用户完成工作是否更省心。它们支持调整组件和实施顺序，不替用户决定换底座、总投入或放弃已采纳的长期方向。
