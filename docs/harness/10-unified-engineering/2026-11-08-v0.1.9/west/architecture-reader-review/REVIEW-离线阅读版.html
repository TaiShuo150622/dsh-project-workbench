W-06 主稿读者与架构审查

2026-11-08 UTC · 审阅对象：统一 Harness 主稿 v0.1.1 · 状态：只读文档审查，未运行产品或重新验证上游服务。

结论：主稿已经形成完整工程的骨架，工作决策、工具发现和方法改进也已进入正文；现在最需要补的是几条产品路径之间的连接。 不建议再增加一轮模块盘点。建议用一个可理解的 Coding 交付故事牵引全文，把已存在于专题里的交互、记忆和远程意图接入；把精确契约与证明展开交给附录。

本次没有发现需推翻主架构的明显矛盾。以下 7 条都是实质修改建议；“未在主稿充分表达”不等于专题不存在或用户此前未讨论。

7 条发现

编号 / 优先级具体位置与问题已有材料支持什么最小修改建议
R01 / 高主稿 34–40、286–290 行：“为什么值得做”主要通过完成、纠错、断线的异常解释；首个闭环仍只说“一个 Coding 任务”和“一次外部动作”。读者知道系统如何防止误判，但不容易说出自己借它完成了什么。201–237 行已有正向工作选择；ARCHITECTURE §11 已列可独立使用的作品，H03 已具体到一个 GitHub PR 动作。无需新增架构。在动机后先放一个贯穿故事：公开演示仓库的一项明确小变更，从输入资料、计划、选材、实现、检查、交付，到一次可复用经验。保持规格变化和断连作为故事中的扰动。首轮任务卡再锁定具体交付物、验收者、必要环境和可见结果；目前没有选定的部分明确写“待实施任务书锁定”。这只是收拢已有示例，不增加实验组或默认任务。
R02 / 高主稿 103–130 行清楚讲了证据/权限/编译，却把旧 Record 的关键产品设想缩成“左侧选材可以使用模型”。读者可能误以为独立选材、后台整理已被放弃。公开 Record v0.1.2 第 10、50–83 行明确三条时序：轮后增量摄入、后台低频整理、下一次执行模型调用前独立组装；未完成整理以水位线后原始增量补齐。首轮 prefill 改善是待测假设。加一个短段保留三条路径，并将“独立模型选材”标为可替换研究策略。区分“保留待验证方向”与“本体必须成为基础设施”；保留现有简单检索、全历史和成本对照，不把历史设想升格为有效方案。
R03 / 高主稿 77、150–174 行把工作台写成状态呈现，把 DAG 主要写成支持关系计算。ARCHITECTURE 145 行有需求影响，仍没有让用户看到完整的“看对象→选中→引用讨论→决定改什么”路径。通用面板 overall-discussion 第 47、94–101 行有桌面/TUI、稳定实体选择、引用和模型读取选中；DAG 第一屏收口计划明确“改之前看影响”。这些稿件仍是公开设计/摘编，不能称完整产品已实现。在架构工作台行和 DAG 段各补一小句：工作台承接可交互产物，用户可把选中对象带入讨论；变更前沿有类型关系看影响，再决定检查/修改范围。与知识本体图、执行依赖图、证据支持图保持区分。展示契约、renderer、背压和 TUI 留面板专题。
R04 / 中主稿 176–199 行和 ARCHITECTURE H06 主要解释恢复与效果；“远程执行为什么是用户需要的产品能力”被藏起来。远程 v0.1.1 的入口是每会话选择环境：本地执行、A 本地 Agent 操作远端文件/命令、B 远端 DSH 执行。会话绑定、文件、终端与审批归属要一致。它不承诺目前已完成多 Host 验收，也不把 UI 断连写成任务终止。在执行章开头用一段交代三种入口和 A/B 的区别，再进入恢复契约；长任务的用户收益是选合适环境、保留进展并可重新查看，不是“断网时一律继续”的保证。接入协议和具体 SSH/版本问题仍放远程专题。
R05 / 高主稿 36 行“零件与设计”、13 行实现基线、257–260 行本轮成果分散；294–297 行又把已经完成的有限模型反例写成待做步骤。用户难以区分旧插件、历史设计、未合并 Record、已完成研究和下一轮集成。公开稿自身已保留这些状态：面板尚未实现；远程材料只有历史本机兼容结果而非远程组合验收；Record 输入为未合并 Draft PR；本轮完成条件证明/有限模型，真实适配和 12-run pilot 未执行。增加一个 4–5 行状态表：“公开设计归档 / 固定代码输入 / 历史有限验证 / 本轮研究成果 / 尚待真实闭环”。真实已做插件清单引用既有核验入口，勿仅因被主稿提到而算本轮验收。将任务书第 2 步标成“已有基线，按新契约增补”，下一步直接指真实效果适配和测量校准。
R06 / 中主稿 82–101 行连续引入 TaskDefinition、Attempt、Session、Host、Environment、Usable_L；随后又有 ContextManifest、准入、支持公式、fencing 和 P1–P15。定义大多必要，但先于具体工作故事，容易使全文像控制系统说明书。ARCHITECTURE §9 已有按用户问题组织的视图；DESIGN_RECONCILIATION 已把预测、检查、纠偏及经验与历史方向对应。形式化专题已有精确词义和假设。主文首次出现用“任务定义 / 一次尝试 / 会话 / 执行宿主 / 环境”等中文，并保持一物一名；“完成、可取/可用、验收”用表解释，公式转附录引用。正文保留一幅总体图、一条用户路径、三类必须区分的状态和条件证明结论；完整对象字段、P1–P15、假设清单、形式输出转附录。没有建议删除语义，只调整阅读层次。
R07 / 中主稿第 280 行把 Tianyi Cui、wenshao、汪晟杰与西方作者并列，末尾唯一“观点与身份研究”链接只到 west/practitioner-views，那里不含这三项。可复核性不足。三项实际收在 china/中国Harness机制核查讨论稿-v0.1.0.md 第 170–180 行，原文及身份入口和来源 JSON 均在。west 文件收录 Bolin、Rajasekaran、Lopopolo、Young、Cordis 联合论文及身份未确定的个人文章。拆成“西方署名工程讨论”和“中国作者原始观点”两个链接；继续保持个人观点、团队署名报告、产品契约分型。这是引用路由修复，本审查没有据此认定三项来源错误，也没有重复上游身份核验。
