# 权限作用域契约用例（未运行）

2026-11-08 UTC。本表是可执行协议的输入/转移/oracle 设计，不是测试结果。不存在测试 runner、攻击样本或产品改动。

每个用例使用虚构资源 r、主体 A/B、测试 Grant 和无敏感数据的目标适配器。测试应分三层记录：纯判定、实际交付、目标效果；纯判定通过不升级成目标效果证明。失败状态保留 reason code 和依据版本。

| ID | 初始条件与转移 | 正向 oracle | 必须拒绝的错误实现 |
| --- | --- | --- | --- |
| T01 / C14a | A、B 各有独立有效 read Grant；撤回 A Grant | Usable(r,qA) 不成立且 reason=denied；B 的策略/材料输入未变时仍成立；Recorded/Supported 不变 | 全局 result.available=false 让 B 同时失败 |
| T02 / C14b | 已确认唯一原件副本 m 存在；权威来源确认 m 删除 | 要求原件的 qA/qB 均 missing；完成声明保留；若保留证据仍足以支持完成，Supported 不被自动撤回 | 把删除等同历史从未完成，或凭历史存在跳过当前读回 |
| T03 | m1 删除；m2 为同一内容版本且当前授权允许 | 若 q 接受任一等价副本，仍可用；若 q 固定 m1，则不可用 | 任一副本删除即删除抽象结果，或擅自替换 q 指定位置 |

| T06 | A 生成摘要 s，但无允许扩大接收范围的发布决定 | s 保留输入披露限制；B 未获准不能交付 | LLM 摘要自动洗成公共材料 |
| T07 | 同一个调用 callId 的参数/目标/接收者从 v1 变成 v2；v1 已批准 | v1 的单次批准不匹配 v2；得到新决定或明确授权的变换证明后才能发送 | 只按 callId、toolName 或一句“已批准”沿用 |
| T08 | 审批权威允许参数收窄变换 R；展示 v1 并声明 R；最终 v2 满足 R | 记录 R 与最终 v2 的绑定，不必重复问；v2 超出 R 必须重判 | 任意修改都复用批准，或无语义 JSON 键排序变化也强制新审批 |
| T09 | Grant 在审批后、Dispatch 前撤回；选用准入时撤回契约 | 本次新 Dispatch 被拒；reservation 不能保留旧通行证；若撤回尚未到达缓存，仅按声明快照保证报告 | 把审批成功当永久执行权，或承诺未配置的跨服务即时撤回 |
| T10 | 父拥有可委派 read(r)；子请求 write(r) 或 read(s) | 父链不能生成该权利；独立新授权必须另有 issuer 和 grantId | 以子代理任务文字、工具出现、同名主体自动扩权 |
| T11 | 授权管理者有 delegate(read r) 但无自身 read r；合法委派给 B | 可产生 B 的有界 Grant，管理者自身仍不能读 r | 将能委派等同能执行，或一律要求父可亲自读取全部对象 |
| T12 | 上下文含历史批准；工具/子代理返回成功与批准叙述；当前无 Grant | 内容可留作历史证据，当前执行仍拒绝；记录无新增 Grant | 从摘要、compaction 或结果文字恢复授权 |
| T13 | A 缓存了允许结果；B 查询同 resource；或者 A 的策略依赖改变 | 不复用错主体/用途/接收范围的授权判断；重算或使对应缓存失效 | 只以资源 hash 作授权缓存键 |
| T14 | 审批者在 τ1 有权，τ2 失去角色；规则只要求决定时有权 | 历史批准仍可审计；其现时适用性按明确规则判断，不直接删除历史 | 默认把现时角色丢失当 τ1 从未有权；反向默认所有旧批准永不失效 |
| T15 | 子代理专用 MCP 工具父面不可见，但子拥有独立且有效的资源授权 | 依契约可使用；返回给父仍检查父接收范围 | 将父看不到工具等同子越权，或父因能调用子代理便取得子全部数据权 |

## 测试所需最小夹具

固定两主体命名空间、两种 operation、两个副本、一个可共享摘要和一个有向委派链。每个决策记录完整读取依赖，至少包含 Grant、policy、结果/表示版本和 q。声明一个不依赖墙钟的离散 ClockObserved 输入；需要过期时推进该输入。纯重放不访问真实网络和实时策略。

目标适配器另有“按已接纳策略”“发送时查权威”“目标执行点检查”三种能力配置。分别跑其能够承诺的 oracle，不能把第一种配置的失败当第三种已实现。即使目标拒绝了权限不足的写入，也不由此推论在途旧动作从未生效。
