有限 DAG 局部重算：Lean 一般证明

在下述假设成立时，只重新计算完整影响集合内的节点，与从头计算新图得到相同结果。IncrementalDag.lean 已由固定 Lean 4.35.0 编译通过；这是关于抽象算法的一般证明，节点数没有固定为某个小整数。不同模型已独立编译冻结源码，并逐项构造满足前提的非平凡实例，见陈述审查。

本证明对应形式模型 P5 的算法推论。它不证明依赖提取器、真实 Record、DAG 插件、外部工具或并发存储满足假设，也不证明重算的实际性能。

定义与假设

Lean 对象/假设含义在工程中的义务
Values α节点编号到任意类型 α 值的函数真实输入、版本和状态要能被明确表示
Rules α每个节点由完整状态确定性计算一个值不允许未表示的墙钟、权限或网络读取
Topological deps每条读取依赖 j→i 均满足 j<i先给出合法拓扑编号；本证明没有实现拓扑排序
Local newRules deps两状态在全部声明依赖上一致，节点输出即一致依赖集合必须覆盖新规则实际读取的全部输入
Closed selected deps被选中的节点之任何依赖后继也被选中selected 可多选，但不能漏掉受影响后继
oldConsistent旧值满足旧规则的所有节点方程不是任意陈旧缓存；旧输入版本必须一致
sameRuleselected 之外的新旧规则对任意状态相同所有规则/根输入变化都应进入影响集合

图的研究范围是编号小于 n 的有限前缀；定义使用自然数编号方便归纳，但结论只对这个前缀负责。依赖只能指向更小编号，所以范围内不会隐式读取范围外的节点。

外部根输入通过无依赖的常量规则表示。例如根值从 10 改为 20，就是该根节点规则变化。若真实实现另有输入存储，需建立它与这种表示之间的映射。

算法与结论

sweep 按 0、1、…、n−1 的拓扑顺序扫描。selected 为真时，用目前状态计算该节点并更新；否则保留旧值。完整重算把所有节点都选中，初始 seed 可以任意，因为每个范围内节点最终都按合法依赖重算。

主定理 incremental_equals_full：

对任意 n、任意值类型及满足上述条件的新旧规则，局部 sweep 的每个范围内节点，等于新规则完整 sweep 的对应节点。

证明没有假设局部结果已经等于全量结果，关键步骤如下：

  1. sweep_unvisited：尚未扫到的节点仍保持初始值。
  2. sweep_preserves_prefix：之后的更新不改变已经扫过的节点。
  3. full_sweep_consistent：根据拓扑读取限制，完整 sweep 满足全部新节点方程。
  4. outside_affected_unchanged：按拓扑强归纳，影响集合外的新旧值一致。
  5. selected_sweep_correct：按扫描长度归纳，已处理前缀与完整新状态一致。
  6. incremental_equals_full：将这些引理组合，得到主结论。

允许任意确定性局部函数，不要求节点单调，也不局限于 AND/OR。正递归或含否定循环没有本定理要求的合法拓扑，不能直接套用。单次 sweep 期间规则/依赖变化，或两轮更新后尚未重新建立完整依赖、合法拓扑编号和影响集合时，也不能套用。两轮之间可以改变读取集合，只要新图仍满足全部前提；审查实例已证明节点 2 从读取节点 0 改为读取节点 1、仅选择节点 2 的情况。

算法扫描整个编号前缀、只重新求值被选节点。因此本证明不声称总运行时间只与影响子图大小有关；真实索引、工作队列、函数求值代价和并发执行都需要另行分析。

复跑与可信边界

在提供 Lean 4.35.0 的环境中执行：

lean IncrementalDag.lean

编译退出码必须为 0，且输出的公理依赖不得出现 sorryAx。本轮命令输出见 compile.log，完整源码散列与工具版本见 compile_receipt.json。

  • incremental_equals_full 使用 Lean 标准基础中的 propext、Classical.choice、Quot.sound。
  • full_sweep_consistent 使用 propext、Quot.sound。
  • 源文件没有自定义公理、未证占位或外部判定器。
  • 工具采用官方 v4.35.0 arm64 macOS 发布归档，SHA-256 与 GitHub 发布元数据一致。没有对编译器本身作独立验证。

编译器核验的是形式陈述。自然语言目标是否被正确形式化、假设是否适合真实系统，仍需陈述审查与实现精化证据；不同模型审查也不等同人类审核。
