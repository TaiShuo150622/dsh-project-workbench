C10：R12 责任接管与负担连续性独立复核

结论：R12 的原有限模型结果可以复现；预算覆盖的论述在原前提下未发现反例。合并时应补清两处范围：授权检查仅覆盖终态观察，收尾预留没有进入这个模型。 跨预算费用重归属、持久占位和权威提交均是前提，不能因模型通过就称现实条件已成立。这里的“独立”指不同研究线重新阅读、运行和编写检查器；不是独立重写全部转移，也不是新的 Lean 证明。

主稿冻结 SHA-256：905ba62b10901fe4c9925165d7fb8fb575b2dbf3e9f4389a09497e1a97114b75。输入清单见 inputs.json。源作者文件保存在 inputs/ 所指原样快照中；副本明确属于旧输入，不作为新稿或新文献计数。

1. 复跑与独立检查采用了什么方法

先在本目录 rerun/ 运行原 check_handoff.py 与 verify_handoff.py。两份源码 SHA 与作者版本一致；复跑 results.json 的 SHA 仍为 2222388828c09944ed12ea95f8fa7e02d19c99293dd7ce370c31abbd14f1cde4。原第二检查器的结果也逐字一致。作者已正确注明该检查器与模型共享转移。

本线另写 audit_handoff.py，仍共享冻结的 successors，但不调用作者的 liability、ledger_admits、direct_invariants 或 explore 来计算审查性质：

  1. 由每条消费事件单独累计旧消费、新消费和旧费用入账历史；转移预算不改变这些历史计数。
  2. 用历史计数重建每预算 U、实际政策归属成本和总世界消费，检查守恒、隐藏消费一致性、旧费只入账一次，以及原 6 个不变量。
  3. 单独检查每条边：接管不改负担/预算、不产生 Grant；提交保留费用并具有目标占位；源释放发生在提交后且目标仍覆盖；中止只发生在提交前。
  4. DFS 建可达图，再从全部失败状态做反向多源 BFS，求从初态到任一失败的最短事件数。未复用作者正向 BFS 存储的路径。负对照可产生不同的同长最短轨迹。

这能交叉核查记账和最短反例，不能发现所有共享转移的遗漏。程序未模拟真实账单、磁盘、身份认证、跨服务事务或外部效果。

3. 应补清的范围与精确位置

C10-01：授权不变量只覆盖 ObserveAuthoritativeTerminal

建议限定，非原预算不变量缺陷。 原稿 :84、92、110 提出每项当前操作的 q/Grant 检查，属于设计要求；代码 :61–67、107 仅记录/检查终态观察的越权。SettleOnce（:68–72）没有独立 Grant 条件；CommitTransferWithDestinationClaim（:86–87）也没有转移授权位或授权撤回。

原保守图里存在这些合法路径，且所有原不变量通过：

  • 4 步：Offer → AcceptCustody → ReserveDestination → CommitTransfer。receiver 的 resolve Grant 一直为 false。
  • 5 步：OldEffectConsumes → sender 的权威终态观察 → Offer → AcceptCustody → SettleOnce。接收者是 custody，resolve Grant 为 false。
  • 7 步：Resolve 接纳并取得终态后撤销 Grant，随后 SettleOnce 仍可执行。

这些路径不证明真实操作越权：转移/结算可能由另一个可信后台主体执行，也可能拥有独立授权；程序没有建模它们。它们只证明 authorized_resolution 不能被读成“所有相关操作均检查授权”。Grant 也不证明终态内容真实；真实终态是该动作的独立原子前提。

建议在原稿 :132 检查范围与 :160 HC3 后补：

本模型的授权不变量只覆盖 ObserveAuthoritativeTerminal。提交转移与 SettleOnce 的操作级授权由环境假设承担，未建模其 Grant、执行主体或撤回。当前 q/Grant 的完整要求仍属待实施契约。

C10-02：R12 未带入 P13 的 closing/R_remaining

需要映射条件，不能把 R12 称为完整 P13 组合证明。 原稿 :51 和代码 :37–38、104 使用 U+claims≤B，状态 :17–32 没有 closing。冻结 P13 的 BudgetSafety.lean:76–89 明确使用 settled+reservedTotal+closing；其 Close 转移及 Reserve 的 extraClosing 也未进入 R12。

最小范围反例：让目标 B 另有固定收尾预留 1、总容量 2。初始 B 的总负担为 1，原模型仍允许第 3 步 ReserveDestination 把 claim_B 设为 2，于是完整负担为 0+2+1=3>2，而 R12 原检查均通过。这是额外收尾前提未被模型表示，不是其已声明六项不变量失败。

建议在原稿 :51、116、158–159 限定任选一种：

  • 本模型专门取 R=0，不声称覆盖非零收尾义务；或
  • B_j 表示已经扣除独立收尾占位后的可用额度，收尾账本及增量准入由另一个明确契约保证；或
  • 未来把 R_j 及新接管增加的收尾义务纳入转移和准入后另行验证。

固定余量投影不自动处理动态增加的收尾成本。P13 Lean 也没有跨 budgetId 的 α 迁移 Step；HC2 需要独立模型/精化，不是把一般 Run 定理直接套到 CommitTransfer。

C10-03：不可重归属旧账是另一种预算语义

原稿 :53、141 已明确限制，建议保留。独立历史账本把旧物理消费固定记在 A，另计算不受 α 变化影响的 oldSpend+freshA。在原 conservative-cross 图中，最短 8 步可到：

Offer → AcceptCustody → OldSpend → OldSpend → ReserveB → CommitB → ReleaseA → FreshA

此时政策归属为 A 实际 1、B 实际 2，均不超 2；但不可重归属的原成本中心 A 实际为 2+1=3。没有费用凭空消失：世界总消费仍为 3。这个反例反驳的是“政策额度安全也证明原付款约束安全”的扩展解释，不反驳原模型。可重归属性、预算政策版本、允许迁移的全部未结算部分及唯一有效归属，必须由真实政策和账单身份判断；本审查不作法律判断。

4. 占位过期负对照与提交重检

在原转移之外，只增加一条“把目标 claim 清零、保留 phase”的事件；这是故意删除作者前提的扩展，不是原图路径。原动作和检查器不变。

扩展状态 / 边最短覆盖失败最短实际政策成本超额
prepared 目标占位可以独立过期1692 / 48695 步，过期后仍 CommitTransfer8 步
committed 目标占位可以独立过期1584 / 44735 步，提交后占位过期即失覆盖8 步

第一条：Offer → AcceptCustody → ReserveDestination → ExpirePreparedClaim → CommitTransfer。代码提交分支只检查 phase；在原封闭状态机里，phase 蕴含 claim 仍为 2，所以未构成原图漏洞。若真实存储允许 TTL 或另一清理者改动 claim，此蕴含就不再成立，提交必须对同一 boundVersion 的占位与取消建立原子排序。

第二条表明：仅在提交瞬间重查占位还不够。提交后目标 claim 必须继续承担未结算负担，不能被独立超时释放。源释放前临时再查，也不能修复目标归属已经无覆盖的中间状态。原稿 :59、61、78 已提出这些条件；负对照为其必要性提供此小域中的可打印见证，不证明特定事务方案唯一必要。

5. 阅读主稿与集成建议

本次还检查了 integration 主稿 v0.1.3（SHA 7841cff2ef2d67419524abfbedcdbf3fa0d9d1ec881af36041aa20c2763eb4d1）。其 :218 仍保留收尾预留，:280 将一般证明限定为既有 DAG/预算规格；没有发现把 R12 全部操作或跨预算协议已经证明的直接句子。需要补的是 R12 自身与未来入口汇总的范围，无需把一般主稿结论改成已证跨预算接管。

建议对外/总览采用：

R12 的责任与费用连续性在列明有限域中完成不同研究线复核；原 5 配置结果及最短反例复现。预算归属迁移依赖可重归属政策和持久占位，授权检查仅覆盖终态观察，非零收尾预留尚未在此模型表示。未形成一般组合证明或真实宿主验收。

同 budgetId 只换 owner 是较小方案，但同样要保持义务/动作身份、代际、水位、unknown 与原预留，并按实际操作验证权限。C10 没有新增实施片、运行产品或扩大 I01。

6. 限制与可复核材料

  • 原模型一个义务、两个 actor、两个容量 2 的预算、hidden 0..2；管理动作串行原子；crash 全部状态保持；无多接收者、部分结算、并发账单、证书重放或可变上界。
  • 枚举无 fairness、期限和最终交付保证；有安全等待不表示持续推进。C08 的责任接收语义不能单独充当成本解除证明。
  • 本线并未独立重写转移；新增事件历史观察器、逐边检查和反向最短路径能发现账目/范围问题，不能提供实现精化或无限状态证明。
  • 源稿两处范围建议未代作者修改；原检查器和所有输入保持原样。原始 inputs/inputs.json 含作者原本的本机来源路径，仅作为本机证据副本；分享包可改留文件指纹和本审查的相对来源索引，不应把它当读者入口。
