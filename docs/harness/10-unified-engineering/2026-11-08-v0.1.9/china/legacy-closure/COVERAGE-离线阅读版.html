不能倒着继承的历史表述

  1. 同文晚决定优先于旧待拍占位。 凭据稿 L93、L331 仍写长度可选/待拍，但 L384 已明确不给模型；L265 的旧迁移待拍标题，须结合 L386、L412 的先验证再迁移，不可取一句就执行迁移。
  2. 旧发现不是当前缺陷。 多实例稿 L292–304 的未实现清单，部分已经被文末 L958–981 的修订记录改变。C13 只用它解释当时的主体与资源问题；没有重新判断当前并发、登录或引擎能力。
  3. 命名相同不等于同一代实现。 H0 的账本、记忆 Record 与当前 S1 状态内核各有用途；原稿写过单写入口不证明现在已持久、原子或跨进程安全。原生面板稿 L6–8 只记录 A0 的一个组件，不能替 A/B/C 主体或当前认证/多会话接线作证。
  4. 旧边界不擅自扩成全局约束。 Workflow 的窄 Agent 三层是策略主张；设置 MVP 不做大 UI 不禁止其他功能的 client bundle；凭据方案并入浏览器不代表所有 Harness 数据统一存浏览器插件。当前统一内核仍可连接多个独立模块。
