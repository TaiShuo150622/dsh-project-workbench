四类 Harness 规格的有限状态检查 v0.1.0

本轮检查支持四个结论：发送点重新检查冲突是必要的；递归支持撤回不能从旧真值继续自支持；未上报费用仍必须占用预算；验收应绑定相关版本和适用性输入，无关备注不应使其失效。正确规则在下述有限域内未发现违反，故意削弱的变体均产生了反例。

这是规格模型检查，没有调用产品代码、模型 API、生产任务、外部工具效果或远端资源。没有证明实际实现满足这些模型，也没有证明无限状态系统的安全性或活性。

文件与复跑

  • model_check.py：Python 标准库程序，包含状态域、转移、BFS、公式枚举、独立 oracle 和变体。
  • results.json：完整计数、转移覆盖、最短反例、输入和程序 SHA-256。

  • inputs.json：规格身份；FORMAL_MODEL.md、ARCHITECTURE.md 是读取时的原样快照。
  • execution_receipt.json：本机执行回执、Python 版本及产物散列。

枚举方法与结果

BFS 从明确初态出发，保存每个首次到达状态的父边。没有深度截断、随机抽样、对称消减或偏序消减；达到状态上限会失败，不能作为通过。所有已发现失败后仍继续穷尽可达图。第一条违反边的路径因此是在该模型、初态与原子事件粒度下的最短轨迹。

完整操作分布保存在 transition_coverage，包括 reserve、send、success、no-effect evidence、unknown、撤回、cancel、未发送放弃和 sender termination。支持模型的聚焦 BFS 则另给出指定递归例子和 AND/OR 例子的最短轨迹。

模型一：准入时无冲突，不等于所有时刻 active 数量至多一

状态域为两个相互冲突的动作 A/B，每个动作有阶段 idle / reserved / dispatched / success / not_applied / unknown / abandoned，以及独立的 cancel_requested、sender_stopped 位。初态均 idle。每个动作最多发出一次；证据可以反复撤回和重新确认，循环历史按相同有限状态合并。

reserved / dispatched / unknown 是该模型中的未解决占位。所有 reserve 和 send 都处在同一个串行权威状态边界；正确规则的 send 再检查另一动作的当前占位。模型假定其他授权、定义和预算条件有效，取消请求仍会阻止尚未发送的本动作。它没有模拟真实的数据库原子实现或目标端 fencing。

正确模型主动反驳了错误猜想 active <= 1，最短 5 步：

reserve A → send A → success A → reserve B → withdraw evidence A
最终：A=unknown，B=reserved。

这时应保留两个事实，禁止 B 的后续发送。省略 dispatch 重检的变体在上述轨迹追加 send B，第 6 步失败。正确与坏变体恰好具有相同的可达状态数量，但转移边不同；仅比较状态数或最终看板不足以验证此性质。

第二个变体将 cancel A 直接写成 not_applied，最短为 reserve A → send A → cancel A。检查器指控的是“仅取消事件不能提供效果解决证据”这个规格违反；它没有凭空观察一个真实远端提交。sender termination 也不修改效果阶段。未发送的 reservation 可以通过单独 abandon_unsent 结束，因为在此模型中尚未发生 send。

限制：success/no-effect evidence 先作为被接纳的观察输入；模型允许后来撤回它们。它不证明观察真实、不证明物理世界任何时刻没有两个效果、不涵盖绕过权威控制器的发送者，也不涵盖同一逻辑动作的多次网络尝试。P7 检查的是准入点的账本谓词。

模型二：AND/OR 与递归支持撤回

三个根事实 a,b,c 为独立布尔输入，两个派生结论 y,z。每个结论公式是最多两个 AND 分支的 OR；每个 AND 有 1–2 个原子，原子可来自五个事实/结论。空公式代表 false。不含否定、概率、时间、信任等级或无限证明树。

正确算法从 bottom (false,false) 迭代。独立 oracle 不运行这套迭代：枚举派生结论的全部四个赋值，找出所有满足方程的固定点，再按分量偏序寻找最小固定点。对每个正确稳定状态检查全部单根增加与撤回，这给出该有限域内的逐步保持检查。针对两个指定网络另做完整 BFS，避免只展示手写例子。

必须保留的循环反例是：

y = a OR z
z = y

初态 a=b=c=false，y=z=false
add a      → y=z=true
withdraw a → 旧值初始化仍为 true,true；最小不动点为 false,false

该聚焦 BFS 最短 2 步。旧值不是假的计算缓存而已：它选择了另一个固定点，形成无根自支持。整个公式域中还会发现更小结构的自环 z=a OR z，同样为 2 步，两个例子都保留。

AND/OR 网络 y=(a AND b) OR c, z=y 中，撤回 a 属于影响范围，但 c 仍可支持 y、z。直接清空后代的变体最短 3 步：add a → add c → withdraw a，把本应由 c 支持的 y/z 错清空。若希望 AND 分支也曾被满足，可先令 a=b=c=true 再撤回 a；结论同样保持，但这条路径不被称为最短。

全公式域反例不是把所有网络混在同一张 BFS 图里，而是枚举正确稳定状态及一步更新后，选择最少根添加前缀。这里的 2/3 步最短性另有简单下界：初态没有真根，第一次增加从 bottom 出发不会出错，所以旧值自支持不可能少于一次增加、一次撤回；清空后代要错误删除替代支持，至少需要两个真根，否则撤回唯一真根后正确最小不动点也全为 false，因此至少两次增加、一次撤回。聚焦 BFS 独立确认所列具体网络的长度。

当前规格第一版验收支持公式限定无环；本模型中的正递归部分是验证未来扩展的边界和反例，不是声称首版已经采用正递归。含否定循环须另设语义，本轮没有检查。全域计数只覆盖所列 DNF 形状，不能推出任意大小公式、任意 SCC 更新算法都正确。

模型三：费用上报延迟不释放负担

物理 oracle 记录每个动作已花未报的 h 与仍可能消费的 f；账本记录预留 r，另有已结算 U 和收尾剩余 R。硬预算准入检查 U + Σr + R + r_new <= B。正确动作实际消费只把 f 转入 h；收到费用结算时才把 h 转入 U，并原子减少对应 r。停止必须提供可信的未来负担解除，才能释放那部分 f，已经消费的 h 保留。

枚举域：两个动作各最多预留一次；整数费用、每次预留 1..B；消费量覆盖每个 1..f 的选择；结算本次所有已报费用；显式停止可解除尚未消费的剩余额；收尾费用从 R 转入 U。全枚举使用 B=4、初始 R=1。另用同一转移函数重放所要求的 B=10 特定场景。

四个观察性质分别是：r_i >= h_i+f_i、账本总额不超 B、物理最坏总负担不超 B、所有动作与收尾结束后的最终 U 不超 B。后两项读取模型中的物理负担，不能只靠被变体破坏的账本自证。

错误变体把 r 改成 f，等于释放已花未报费用。指定反例如下；R=0：

步事件UA: r/h/fB: r/h/f账本 U+Σr物理已花及可能花 U+Σh+Σf
0初态00/0/00/0/000
1A 预留 10010/0/100/0/01010
2A 已花 8，未上报010/8/20/0/01010
3错误释放已花的 802/8/20/0/0210
4B 再预留 802/8/28/0/81018
5A 再花 202/10/08/0/81018

7A 结算 10100/0/08/8/01818
8B 结算 8180/0/00/0/01818

正确规则在第 2 步仍持有 10，不允许 B 的预留。18>10 是指定的 8 步场景，不称所有超支中的全局最短。B=4、R=1 的坏变体由 BFS 给出另一条最短 8 步最终超支轨迹，结算总额 5>4；失去负担覆盖本身在第 3 步已经可检测。

限制：h/f 是模型为判断上界是否真实而保留的 oracle 信息，生产控制器未必能直接读取；模型假定工具不能超过已预留上界，价格不变、没有未计入的子任务和保活费用，收尾义务确实被 R 覆盖。停止释放使用可信的剩余负担解除，不是取消信号。没有建模每条日志的真实费用或成本预测误差。真实上界取不到时，不能套用这个条件性结论。

模型四：绑定版本、适用性输入与备注

枚举 P4 的九个绑定分量：historyId、taskId、specVersion、witnessId、resultId、artifactVersion、availabilityRevision、acceptancePolicyVersion、decisionRevision。每个分量最多从 0 更新为 1；备注也最多更新一次；每条运行最多接纳一次验收。这里更新的是当前待判断对象的引用/版本；historyId 等身份变化表示判断上下文切换，不允许原地改写历史对象的不可变身份。

D_valid 抽象规则实际读取的权限、证据有效性、显式时钟、新鲜度等输入的合取。四类 invalidation 事件都可触发 D 从 true 变 false，但多个 false 原因合并为一个抽象状态；本轮没有枚举全部 ACL、时间数值和失效原因组合。另有显式验收撤回位。

正确判定比较完整绑定向量并检查 D 和撤回。独立事件 oracle 在接纳时置有效，只在绑定字段更新、读取输入失效或验收撤回时清除，备注更新不清除；它不比较版本向量。整个可达图对照这两种表达。

  • 漏绑 specVersion 的变体：accept → update specVersion，2 步错误保留旧验收。
  • 绑定全局 revision 的变体：accept → update unrelated note，2 步错误废止仍适用的验收。

“无关备注”是规格声明的条件，不是对任何自由文本都成立。用户在备注中改变约束、引入撤回或让规则读取新字段，应进入相关输入更新。模型不覆盖 ABA 版本复用、恢复失效后重新验收、未建模的业务绑定分量或真实时钟误差。

怎样审读和怎样使用结论

建议先读 action_steps/dispatch_conflict_free，再读支持公式的迭代与枚举 oracle，接着检查预算中的 h/f/r 分离，最后核对验收字段列表和 D 抽象。运行程序后可以从 TRACES.md 逐事件核算；完整 JSON 保留计数，不将文字描述作为测试通过证据。

值得进入总稿的结论是已有错误猜想和削弱条件被明确反驳，以及正确有限模型在声明边界内保持了性质。尚不能推出：实际 Record 内核已实现这些转移、持久化和准入是线性化的、授权来自可信主体、工具返回是真实世界事实、真实费用有硬上界，或任意长期任务最终完成。

后续实现精化应把每个模型事件映射到产品的命令/收据/持久化点，并注入重复、崩溃、迟到、认证失败和真实工具不确定性。此处没有替产品提前签署这些验收。
