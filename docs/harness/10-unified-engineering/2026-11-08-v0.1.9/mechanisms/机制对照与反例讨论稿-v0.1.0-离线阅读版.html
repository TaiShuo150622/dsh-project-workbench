版本与范围

这 8 个样本提供了互补的机制，但没有一个样本的局部持久化、取消或审批能力，能直接替代统一 Harness 对外部效果的证明。最值得吸收的是明确的效果边界、恢复身份、迟到证据保留、请求快照和分层资源预算，而非把某个框架整体选作事实来源。

  • 版本：v0.1.0 为首轮源码核查稿；后续修改按补丁号递增。
  • 主线：S1 基线 → 分层机制 → 8 个互补样本 → 反例 → 待证命题。
  • 状态标记：源码事实表示固定提交正文可见；文档承诺表示官方接口说明；推断表示本稿给统一 Harness 的设计含义；未验证表示没有运行上游或真实宿主。
  • 检索日期：2026-11-08 UTC；作者日期按工作区洛杉矶日期。固定提交、文件、行段、作者归属、限制见 sources.json。
  • 范围：公开资料；未复制公司、量化或个人原始会话。仅静态阅读，未跑上游测试、真实 DSH、远程执行或生产任务。

动机

我们需要补的是纯状态核与真实执行世界之间的证据链，不能用“支持恢复”或“任务已取消”填补它。

Record S1 和 S1 对抗核查说明 已把动作保留为 reserved → sent → succeeded / not_applied / unknown，并让未知效果继续占位。取消或撤权只能直接阻止尚未发送的动作；负面释放证据要求发送者确已终止并确认未生效。这些是内核规则，实际身份认证、发送端截获、事务存储、跨进程互斥和目标端核验还在核外。

本研究因此优先找能回答以下问题的实现：取消后还有谁能写？恢复时什么身份继续有效？记录拒绝旧结果后，旧工具是否仍会生效？消息历史能否带回预算？一个结果曾经存在，是否足以支持现在的依赖验收？

总体架构

统一 Harness 应把调度、对外效果、事实记录和展示拆成可独立核验的边界，再明确哪种证据允许越过每一道边界。

图 2　机制分层 · 四种不同的容量或权利

worker slot、业务资源占位、消费预算与授权是四套不同的账。执行协程退出可以释放某类本地容量，却不足以释放未知外部效果占位。

三个谓词应显式区分：cancelRequested 是意图，senderTerminal 是发送者生命周期观察，effectResolved 是目标效果结论。前两者都不能单独代替第三者；senderTerminal 还必须明确是否包括工具创建的子进程、后台任务和远程代理。

可直接借鉴的机制与隐含条件

源码里最有价值的共性是“将相似外观拆成不同状态”，同时把这些状态的作用域写清楚。

样本可借鉴机制隐含假设与我们要补的契约
Pi初次调用跑 hook、重验参数、持久化 execute 意图后才执行；重启要求已存策略与当前工具均为 replay-safe。PI-02replay-safe 是工具作者承诺；若授权只放在 beforeTool，恢复直接 run 的路径需要另设 dispatch 授权复核。当前工具可用性检查本身仍可拒绝已移除工具，不应把这个条件性反例说成漏洞。
Pibatch 原子、可接收已提交前缀；耐久回执与发布分离。deferred progress 可先内存可见。PI-03UI 要标出暂态进度；不能因订阅看见进度就声称 crash 后还在。Session 序列化也不自动授予分布式 writer 所有权。
OpenCodeinterrupt 接受与 awaitIdle 分开；pendingWake 为取消清理期间的新意图保留入口。OC-01确保一个 session 的进程内协调，不证明远端 sender 停止。新意图应获得新身份，不能复用旧取消边界。
OpenCodeselect 固定 session/agent/工具/指令，load 组装该选择的历史和模型；权限收窄发现面。OC-03这是请求快照；有效权限仍应在实际副作用入口重评。保存 allow、配置 deny、pending response 的作用域要明确。OC-02
LangGraph同步、异步、退出时才持久化是显式模式；任务 pending writes 与 superstep checkpoint 分离。LG-01“可恢复”必须附 durability/backend 条件；interrupt 恢复从节点开头，前置效果应放入可重放边界。
LangGraphclose 与 guarded writes 使用同一锁；过期尝试不能再沿该路径落状态；LastValue 同步多写直接拒绝。LG-02围栏覆盖图内部写入；stream callback 有更弱保证，外部 I/O 更不受此锁保护。reducer 是业务合并规则，不是全局资源锁。
PydanticAI工具审批与身份授权分开；历史、usage、deferred calls 是不同恢复对象。PA-02PA-04审批展示参数可能在恢复 hook 中改变；授权应绑定最终参数。仅回填消息历史会重置累计预算，提示词里的 provenance 不构成证明。
Letta Code保留已完成 partials；取消 grace 结束允许调用者先退出；lineage 的迟到结果与 successor 当前快照分离。LT-02LT-06UI 结束不意味着工具结束。sidecar 精确保存“哪个调用返回了什么”，仍不能由输出文本推断独立目标事实。
Agnoworker-owned 持久化带 attempt；Postgres 行锁同时保护 run 与 session metadata，拒绝旧 attempt 后不绕回无围栏覆盖。AG-04需要支持该原子 primitive 的 backend；写入 fencing 保护记录，目标系统必须有自己的 fencing/幂等能力。
TemporalABANDON、TRY_CANCEL、WAIT_CANCELLATION_COMPLETED 分别表达不传播、发请求后返回、等待活动结束。TM-01普通 activity 接收取消依赖 heartbeat；实际 worker 只发 signal，仍 await 执行结果，signal 被忽略时可以成功完成。TM-02TM-04
DBOS重新排队再原子 claim；terminal update 以 owner_xid 拒绝旧 owner；取消监测先快照旧 waiters。DB-01DB-03owner_xid 必须传入且只保护数据库结果。异步取消要等 step 清理；无 step 结果的重放仍可能重复外部效果。

经典 Pi Agent 的 context transform、并行工具执行与 hooks 适合做宿主扩展点；其事件顺序和 hook 并不自动获得同仓 durable package 的持久性。框架、子包、宿主和部署必须分别命名。

反例与证据失效

有用的反例要指出“哪条证据无法推出哪项结论”，而不是把所有框架的问题概括成不可靠。

图 3　未知效果窗口 · 两个控制端不可区分的世界

读图时固定 Harness 的观察历史：若目标既无幂等键也无法查询效果，恢复侧不能仅凭相同观察同时保证“永不重复”和“总能继续”。这是本稿的条件性不可区分反例，不把它命名为 FLP 的泛化结论。

资源与上下文的计量边界

每种资源机制都应标注它限制的是排队、执行、消费、占位还是可用结果，避免同一个“并发数”掩盖不同风险。

worker 执行槽Temporal reserve → used → release；预取可已 reserve 但尚未执行。TM-05本地执行槽释放与业务效果占位释放使用不同事件。
background 并发Agno 默认 cap 在 event loop 范围，接受/PENDING backlog 仍无界；排队取消轮询与 backlog 成正比。AG-03admission、排队内存、running 上限都要单列；多进程部署需共享额度或明确拆分。
队列份额DBOS 接口区分 global、worker、partition concurrency 与启动 rate。DB-04先明确租户、主机、资源池和目标服务的预算域；本轮没有验证全部队列算法。

风险与开放问题

目前结论足以约束后续原型，却不足以做生产选型或宣称端到端安全。

  • 固定版本的范围：本轮 pin 是访问时默认分支，不等同正式 release；近期大重构可能改变结论。
  • 文档与源码层级：源码注释能说明接口契约，测试源码能说明防回归意图；两者都不是本机已运行结果。
  • 本地锁与多主机：Pi Session、OpenCode Map、Letta 文件锁覆盖不同作用域，不能统一标成 distributed lock。
  • 终止对象不完整：协程结束后，子进程、远程任务、后台工具和目标队列可能继续；senderTerminal 的适配器定义尚待落地。
  • 授权与恢复的时间关系：最终参数、tool version、policy revision 与恢复身份的绑定，是我们设计推断而非已实现能力。
  • 未知效果的运营成本：保留占位可能长期阻塞；要有核验、补偿和人工裁决路径，不能用固定超时自动“证明”未生效。

开放问题：

  • Pi 当前 durable Storage 是否规定或实现跨进程 session ownership；现有原子提交检查能解决哪些多写者冲突？
  • Letta recovery lineage 的证据保留是否覆盖所有工具与外部工具回调路径？
  • Agno 不同数据库 adapter 的 fencing 支持清单，以及队列接管时存储状态与外部 sender 的关系。
  • Temporal server/Core 对等待取消、worker 丢失和 heartbeat timeout 的完整协议，哪些结论超出 TS SDK 已核范围？
  • 最终 dispatch 中的权限撤回如何与目标端接收竞争；哪些工具支持原子撤回，哪些只能记录未知？
