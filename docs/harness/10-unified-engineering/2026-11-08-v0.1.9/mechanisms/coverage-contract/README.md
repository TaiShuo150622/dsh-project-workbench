# M10：有限声明域 coverage 契约

本轮把 M09 的 coverage 缺口收窄成一个可讨论、可继续精化的有限域合同。没有实现产品 collector/validator，没有执行覆盖算法、模型/API 实验或真实宿主测试。

阅读顺序：

1. [讨论稿 v0.1.0](有限声明域覆盖契约讨论稿-v0.1.0.md)：纸面条件、尾部与并发、授权摘要、三个构造反例。
2. [contract.json](contract.json)：8 条约束及建议字段；PROPOSED_NOT_IMPLEMENTED，actual_execution=false。
3. [counterexamples.json](counterexamples.json)：3 个 CONSTRUCTED_NOT_RUN 纸面案例；合成条件不是生产输入信任格式。
4. [sources.json](sources.json)：8 份既有个人研究材料，2 份此前已核并在本轮重开的原始来源；无新增论文。
5. [validation.json](validation.json)：仅文档结构、JSON、引用和状态标记检查。

complete 必须由冻结域、快照/切点、合格处理收据和缺项导出，不能由调用者传入 flag。其依据始终只限明确声明域；目录选择是否充分、枚举与认证是否真实、评估是否正确，仍是要落实的外部条件。

特别保留三点：

- 完整覆盖可以得到负面或冲突结果；它不产生正支持、任务完成或执行许可。
- 来源不可访问不得静默删分母；后台索引的旧水位也不能代表调用切点，原始尾部必须核对身份、连续范围及实际处理。
- 合法的限定评估摘要可供无原文权限者消费，但须有独立发布依据，并且不能改称原文字节已被注入。隐藏来源、数量、冲突和 gap 的存在性均按披露政策输出。

HTML 是生成阅读视图，未做浏览器视觉验收。本轮不使用一个小型模拟器来冒充已经获得真实枚举/授权/输入捕获能力；三个反例保持纸面状态。

只有讨论稿与其结构化合同为本轮新提案。原 Record 材料维持历史提案性质，W11 的小模型仍不计算世界真值或行动权限，W04/context 原实验仍未运行。
