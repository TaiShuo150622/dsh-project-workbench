# 统一 Harness 形式模型工作稿

2026-11-07 · 七小时研究内部工作稿 · 状态：定义与证明草案，尚待反例审查。

本稿试图给现有工作台、Coding、Record、DAG、远程执行和长期任务共同使用的语义。下列命题不宣称系统已经实现；它们只在逐条列出的假设成立时成立。小规模状态枚举只能检查指定模型和边界，不能代替实现精化证明或生产验证。

## 1. 要建模的对象

Harness 负责把人的意图转成受约束的工作，保留每次判断和效果的依据，再将经验用于下一次工作。模型输出只是候选行动与解释的来源，不能直接成为所有状态的权威写入者。

| 对象 | 身份和关键版本 | 语义 |
| --- | --- | --- |
| Goal | goalId、goalVersion | 人希望改变或了解的状态；可以探索、变化或无法完全机械判定 |
| TaskDefinition | taskId、specVersion | 一个可分派工作单元的输入、边界、验收规则和允许效果 |
| Attempt | attemptId、taskId、specVersion | 一次尝试；重试、换模型和换宿主产生新尝试，不自动产生新目标 |
| Session | sessionId、historyIncarnation | 可续接的交互与工作历史；不能等同进程或沙箱 |
| Host | hostId、hostIncarnation | 执行控制器实例；进程重启后旧消息不自动获得新实例权限 |
| Environment | environmentId、environmentGeneration | 文件系统、依赖、凭据和进程所在环境；可与会话分开销毁或恢复 |
| LogicalAction | actionId、businessIntentId、parameterDigest | 业务动作意图；重试同一动作要复用身份，两个内容相同但独立的目标不能只按内容散列合并 |
| ActionAttempt | actionAttemptId、actionId、senderId | 一次可能到达外部系统的发送；超时、取消和断连都不自动说明它未生效 |
| Observation | observationId、issuer、subject、observedVersion、observedAt | 某来源对某事实的观察；来源与完整性可验证，不意味着内容必然正确 |
| CompletionWitness | witnessId、taskId、specVersion、evidenceRefs | 在指定判据下支持某次完成判断的证据束，可被撤回或反驳 |
| Result | resultId、artifactVersion、availabilityRevision | 产物及其当前可取得、可使用的状态；同一产物可支持多个任务 |
| Acceptance | acceptanceId、principal、policyVersion、binding | 有权主体对指定定义、证据和产物版本的判断，不是无版本的永久布尔值 |
| Grant | authority、subject、resourceScope、operationScope、epoch、expiry | 可执行何种动作的授权；模型提供的 actor 字符串不是认证依据 |
| ContextManifest | manifestId、sourceVersions、watermark、obligations、gaps | 一次模型调用实际得到的材料和缺失项；它解释信息来源，不授予权限 |

最小主体引用应为 `(authority, subject)`；角色、代理关系、会话和人类/服务类型另列。是否需要全球唯一主体由认证部署决定，不能仅因字符串相同就把不同命名空间的主体合并。

## 2. 世界、观察、账本与投影

区分四个层面：外部世界状态 `W`、观察集合 `O`、被系统接纳的事件日志 `L`、由日志计算的工作状态 `S`。系统不能直接读取完整 `W`；它只能经由观察形成有条件的判断。

令历史身份为 `h = (projectId, historyIncarnation)`，接纳事件序列为 `L_h = (e₁, …, eₙ)`，初始状态为 `S₀`。在固定解释器版本 `v` 下：

`Sₙ = fold(δ_v, S₀, L_h)`。

事件至少包含 `eventId, historyId, sequence, kind, payload, commandId, schemaVersion`。需要因果关系时另列 `causedBy`；sequence 只表示该日志的提交顺序。观察发生时间、收到时间与提交顺序是不同字段。跨宿主事件不能只按客户端时间排序就称为因果顺序。

Lamport 的 happens-before 给出因果偏序；逻辑时钟能保持该偏序方向，但时钟值大小本身不能反推出因果关系。[原始论文，1978](https://lamport.azurewebsites.net/pubs/time-clocks.pdf)

**P1：确定性重放等价。** 假设初态、完整事件序列、解释器/模式版本相同，且 `δ_v` 为确定性全函数，那么从头重放得到的状态相同。

证明：空序列时两者均为 `S₀`。假设前 k 个事件后相同，对同一 `eₖ₊₁` 应用同一确定函数，下一状态仍相同。归纳得证。

边界：P1 不证明日志持久、事件真实、事件未被恶意替换、外部动作只执行一次，也不证明更换解释器后的重放等价。读取当前时间、调用模型、访问网络或执行工具必须放在决定事件之前或独立效果执行器中，不能成为重放函数隐式输入。历史缺失事件不能用“模型大概能补全”恢复。

**P2：日志内容完整性不等于来源认证。** 对任意无密钥散列 `H`，能替换日志的攻击者也能重算 `H(L')`；因此散列相等至多检查指定内容的一致性，不能仅凭它证明谁授权了事件。认证存储、签名/MAC、签名密钥归属和防重放是另一个证明义务。

OpenAI Agents SDK 也明确将快照反序列化、快照完整性、提交者身份和应用授权分开；本稿沿用这一边界，不把序列化对象当权限凭证。[固定版本 HITL 文档](https://github.com/openai/openai-agents-python/blob/27c75c5f9c5fd957d28c04fb7e9eeacaad4630a9/docs/human_in_the_loop.md)

## 3. 完成、可用与验收的四个谓词

对任务 t 和历史前缀 n，定义以下**账本谓词**。它们表示截至该前缀已接纳观察的判断，不直接等于外部世界此刻的状态：

- `Recorded(t,n)`：前缀中存在一个完成声明事件。它只是审计事实。
- `Supported(t,n)`：当前有效证据仍支持该定义版本的完成。撤回错误证据后可为假。
- `Usable(t,n)`：截至该前缀，绑定结果的有效观察满足所需的存在性、访问性和适用性条件。
- `Accepted(t,n)`：有权主体的当前验收仍绑定当前定义、证据/结果及规则版本，且未被撤回。

不要预设四者等价。定义不同的任务可以要求 `Supported`、`Supported ∧ Usable`，或 `Supported ∧ Usable ∧ Accepted` 才释放某条依赖。Acceptance 的绑定规则必须明确，不能把任何历史好评转成当前验收。

另记世界谓词 `Usable_W(t,τ)` 表示真实时刻 τ 的外部可用性。相同日志 L 可以对应“产物仍在”和“产物刚被删除、通知尚未到达”两个世界，所以一般不能推出 `Usable(t,n) ⇒ Usable_W(t,τ)`。界面应显示最后核实时间和来源。即使观察足够新，也不能排除核实后立即发生的改变；需要实际使用时检查、目标端条件操作或明确的稳定性假设才能获得更强结论。水位不是世界时钟。

**P3：审计单调不推出完成单调。** 在只追加日志的假设下，`Recorded` 对前缀扩展单调。`Supported` 不单调，因为追加一条可信的证据撤回即可使其从真变假；`Usable` 和 `Accepted` 同理。反例：PR 合并判断后来被发现指向错误 source SHA；或者合并本身真实，但产物后来不可取得。这是两种不同撤销原因。

现有 Record S1 的 `historical-completion` 检查的是“当前仍受支持的完成”，不是“某个完成事件曾经存在”。正式 API 应通过名称或说明消除这个误读。当前实现把结果不可用与错误完成撤回分开，正是本模型的一个局部实例。

**P4：无关版本变化可以不废止验收。** 设验收绑定向量为 `B = (historyId, taskId, specVersion, witnessId, resultId, availabilityRevision, acceptancePolicyVersion, decisionRevision)`。如果一次更新不改变任何绑定分量、不改变主体权限/验收适用规则、也未引入撤回证据，则按此契约验收仍适用。

证明：适用性谓词的全部自由变量保持不变，谓词值不变。边界：这是给定绑定契约的性质，不证明这些分量在业务上足够；漏绑定输入版本、单位或有效期会使契约本身错误。任务备注变动不必失效，任务规格变动通常必须重判。短向量优于“任何事件都使验收失效”的粗粒度全局版本，但需要明确依赖分析。若规则含有效期，判定使用的时钟必须成为显式输入或时钟观察事件；不能在纯重放函数中隐式读当前墙钟。执行点仍需按约定的时钟误差和授权规则重新检查。

## 4. 图是一组带类型关系

同一工作台至少需要下列关系，而不是一个无类型的 `dependsOn`：

| 关系 | 边的含义 | 是否天然无环 | 更新后的动作 |
| --- | --- | --- | --- |
| 任务准备关系 | 开始 B 需要 A 的某个谓词成立 | 一次具体分解可要求无环 | 重算 readiness，识别无法满足的循环 |
| 尝试/事件因果 | e₁ 导致 e₂；新尝试继承旧尝试的输入 | 有真实先后关系的有限事件可构成 DAG | 追加，不覆盖旧尝试 |
| 证据支持关系 | 证据束支持某个判断 | 推理系统可能有递归 | 重算受影响判断，保留替代证据 |
| 产物依赖 | 构建/报告使用某个版本 | 常有 DAG，但外部数据可循环演化 | 标记待复核，不自动宣称全部无效 |
| 资源冲突 | 两个效果争用同一语义资源 | 通常是无向或对称关系 | 准入与执行隔离 |
| 本体/经验关系 | 相似、属于、否定、替代、使用经验 | 可有环 | 查询与修订，不强制拓扑排序 |

**P5：影响闭包不是失效闭包。** 令结论 y 的证明条件为 `φ_y = (a ∧ b) ∨ c`。a 被撤回时，y 属于其可达影响集；若 c 仍真，y 仍受支持。因此将某节点的全部可达后代一律置失败不保真。正确策略是先找影响集，再按每个结论的支持公式重新求值。

正查询中的 provenance semiring 区分合取使用与替代来源，为这种表示提供数学参照；本稿还涉及否定、撤回与时态，不声称正查询代数已经解决所有非单调情况。[Tannen，2017，作者回顾演讲](https://www.cis.upenn.edu/~val/15MayPODS.pdf)。后续研究也已讨论否定与一阶逻辑的 provenance，不能把“早期框架限于正查询”说成整个领域未处理否定；本稿尚未证明它们与本系统撤回/时态规则的对应关系。[Grädel、Tannen，2024](https://arxiv.org/html/2412.07986v1)

**P6：循环工作流可以有无环的已发生事件图。** “执行—验证—修复—再执行”在工作流定义中有环，但每个发生实例带递增尝试身份和指向过去实例的因果边时，有限实际事件图无环。

证明：若每条边从较早发生实例指向较晚实例，沿有向环会导出某实例严格早于自身，矛盾。边界：不能用这个事实禁止工作流循环，也不能仅靠接收顺序给并发事件伪造真实因果。

## 5. 准入、取消与外部效果

把动作状态与任务状态分开。动作尝试可处于 `reserved → dispatched → {confirmedApplied, confirmedNotApplied, unknown}`。取消请求是独立事件；发送者终止、效果已解决分别是独立证据。`cancelRequested`、`senderTerminated`、`effectResolved` 不能共享一个布尔变量。

准入谓词可以写为：

`Admit(a,S) = AuthValid(a,S) ∧ DefinitionCurrent(a,S) ∧ EvidenceSufficient(a,S) ∧ BudgetAdmissible(a,S) ∧ NoUnresolvedConflict(a,S)`。

“检查谓词 + 接纳动作”必须在一个串行化边界内完成，或使用能提供等价保证的事务/CAS。原子性究竟覆盖哪些资源由实现决定。Herlihy 与 Wing 的线性化定义适合描述单对象操作似乎在调用和返回之间某点生效的契约；它不自动让外部网络效果进入同一事务。[原始论文，1990](https://cs.brown.edu/~mph/HerlihyW90/p463-herlihy.pdf)

需分别定义 `Reserve` 与 `DispatchIntent`：预留只建立计划占位；发送意图转移须重新检查会变化的定义、授权、证据、冲突与预算负担，然后持久化这次准入依据。即使两步各自原子，预留成功也不是永久发送许可。网络发送与目标提交仍在此局部原子边界之外。

**P7：原子准入可以保证准入时无未解决冲突。** 假设所有冲突动作都通过同一权威状态，冲突判定完整，检查和接纳原子，接纳后在同一状态中立即建立占位。则每次准入的线性化点均不存在另一个被该谓词定义为冲突的未解决动作。

证明：准入只能在 `NoUnresolvedConflict` 为真时转移；原子转移排除两次检查同时读取同一无占位状态的窗口。性质只约束该转移时刻。

边界与必要修正：不能由 P7 推出“系统任意时刻最多只有一个 activeAction”。例：A 被认为成功后 B 已预留；随后 A 的完成证据被撤回，A 回到 unknown，此时两条活跃记录可以共存。安全动作是阻止 B 的后续 dispatch，而不是删掉 A 的未知事实。若 B 已经发送，后来的纠错也无法把历史变成从未并发。真实物理效果的更强保证需要可信终态证据、目标端幂等/排他或 fencing。

**P8：取消确认不推出效果未发生。** 设发送者收到取消信号前已把请求发送给外部目标，目标可以在信号到达后提交。取消信号 ACK 与效果未发生可以同时为假/真组合，因而前者不蕴含后者。关闭调用方 Promise、父进程退出、读取不到结果或心跳消失，也不足以证明所有远端写入者已经停止。

对授权撤回也必须选定语义：

1. **准入时有效**：撤回阻止新准入，已准入动作允许完成；可以由入口控制器实现。
2. **执行点仍有效**：目标在发生效果时检查最新授权/代际；需要目标配合，入口已批准不够。
3. **效果撤销**：另一个补偿或回滚工作流，可能有成本、部分失败及不可逆作用；不能混作前两者。Sagas 原文已讨论补偿事务、可靠保留恢复代码及难以逆转的现实动作；这不是新问题，Harness 需要把相应责任落实到工具契约。[Garcia-Molina、Salem，1987，原始论文](https://www.cs.cornell.edu/courses/cs530/2005sp/papers/sagas.pdf)

租约过期也不会使暂停的旧执行者物理消失。fencing 需要单调 token 以及真正拒绝旧 token 的下游资源；只把 token 记在日志里没有隔离效果。[Kleppmann，2016，原始工程讨论](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)

**P9：未知效果下的两世界不可区分性。** 假设系统只观察到“发送后未收到结果”，没有目标端幂等、没有权威效果查询、没有能排除旧请求未来提交的终止证据。世界 W₀ 中旧请求尚未生效且永远不会生效，W₁ 中旧请求已生效但响应丢失。两世界给恢复器同样的观察历史。若恢复器为保证 W₀ 最终完成而重新执行，W₁ 可能重复效果；若为避免 W₁ 重复而永不执行，W₀ 无法由此完成。因此仅凭该观察无法同时保证这两项性质。

这不是泛称所有 exactly-once 不可能，也不是 FLP 定理。稳定业务意图键与目标端原子去重、能判定实际效果并排除迟到写入的对账，或改变业务目标允许补偿，都会改变假设。普通查询返回未找到不一定具备这种权威性。

## 6. 上下文是一份有义务的编译产物

上下文服务分成候选检索/选择与确定性编译。选择器可用模型；编译器对来源、版本、权限、预算、必带项和缺失项做机械检查。不要让一个自然语言摘要成为任务状态的唯一存储。

设候选材料集合为 C，当前主体 p、目标 g、知识水位 w、权限状态 A、预算 b。编译器输出 `(context, manifest)`，其中 manifest 至少给出实际材料引用与版本、转换方法、相关时间范围、强制义务满足情况、删减原因、冲突和未覆盖项。

义务可包含：最新用户约束、适用任务规格、当前授权边界、未解决外部效果、与本次动作有关的反例、输出验收条件。这里“相关”仍含判断，应允许人工/确定性规则指定必须带入的项，不能只由选择器自评。

**P10：机械可追溯性不推出语义充分性。** 即使每段内容都能追溯到真实来源且未超预算，选择器仍可能漏掉决定性反例。因此编译验证只能证明它检查的义务，不证明模型拿到了世界中所有相关信息。可用对照任务测量遗漏率，并把未覆盖义务显式返回，不能把“编译通过”命名为“事实已验证”。

**P11：硬义务超预算时不能同时满足完整性和容量。** 若不可再分割的必带材料最低编码长度为 m，预算 b < m，则没有长度 ≤ b 的上下文能完整包含这些材料。系统应拆任务、分阶段检索、请求更大预算或报告当前不可行。若允许有损摘要，问题已改变，须另行评估摘要遗漏风险。

该命题刻意不假设信息价值可加或子模。两段材料可能只有合起来才有意义；把来源独立打分后贪心取前 k 条，不能在没有额外条件时声称有通用最优近似保证。

上下文中的文字也不扩大主体权限。曾经见过后来撤回访问权的数据无法从模型历史中物理“取消看见”；可执行措施是隔离后续会话、限制工具和输出路径、按数据政策重建上下文，并明确不可证明的遗忘边界。

## 7. 预算包含在途负担和结算空间

令总预算为 B，已结算消耗为 U，每个在途动作的**未结算负担上界**为 r_i，完成必要结果收集、持久化与安全停止的剩余预留为 `R_remaining`。r_i 必须同时覆盖“已经发生但尚未上报/结算的消费”和“仍可能发生的未来消费”；不能只看未来剩余费用。若每个新动作有可信上界 `r_new`，则硬上限准入条件可用：

`U + Σ r_i + r_new + R_remaining ≤ B`。

**P12：已消费阈值只能限制新准入。** 若只检查 `U < B`，然后允许一个尚未计价的动作，最终 U 可以超过 B。n 个并发动作的超额上界取决于它们的最大未结算成本；若该成本没有有限上界，仅从阈值本身无法推出有限超额上界。

**P13：保守预留可给出条件性总预算界。** 假设每个 r_i 是真实未结算负担上界、预留记账与准入原子、执行不超其上界、`R_remaining` 足以覆盖未完成的收尾，且释放预留不会先于负担解除，则上述准入规则保证最终消费不超过 B。

证明：初始不等式成立；准入保留新上界后不等式仍成立；结算时真实消费增量不超过其对应预留，原子地增加 U 并减少相应负担预留，故不增加总负担。收尾消费同样从 `R_remaining` 转入 U，剩余收尾义务必须继续被剩余额覆盖。归纳到所有动作结束即可。边界：预测均值不是成本上界，工具再发任务、价格变动和后台保活都可能破坏假设。

一个必须保留的反例：B=10，U=0，动作 A 预留10；A 已花8但尚未结算，未来最多再花2。如果误把 r_A 降为2，再准入最多花8的 B，则最终可花18。正确的 r_A 此时仍需覆盖未结算8与未来2，不能把“尚未收到费用”视为没有消费。

Claude Managed Agents 的公开预算语义是在新模型请求前检查；在途请求及其工具仍可完成，达到阈值后保留结果/确认等结算事件。这是“限制新工作”与“瞬间硬停机”的实际区别，并支持将结算通道单独设计。[官方 budgets 文档，2026-11-08 读取](https://platform.claude.com/docs/en/managed-agents/budgets)

对长期任务，还要区分安全性与活性。只要用户审批、外部服务或资源永久不可得，就不能无条件承诺最终完成。可承诺的是：在明确可用性/公平性假设下持续推进，并在假设失效时暴露可操作原因。不能靠频繁写“仍在运行”证明有进展。

## 8. 子任务通过不等于整体目标达成

设父任务契约为 `(A,G)`，子任务契约为 `(A_i,G_i)`。要从子任务完成推出整体完成，至少需要证明输入传播使每个 `A_i` 成立，并证明组合性质 `A ∧ ⋀G_i ∧ IntegrationConstraints ⇒ G`。仅有所有子任务测试通过不足以得出这个蕴含。

**P14：组合必须覆盖接口与整体语义。** 反例：数据组按美元输出，报告组把同一数值当人民币；各自单元测试在自己的假设下通过，整体金额错误。另一反例：代码修改通过测试，但部署目标仍运行旧版本。合并、发布、实际运行与用户验收应是不同节点和不同证据。

这一结构为 DAG 的验收提供方向：边携带有版本的接口假设，汇合节点检查组合义务。它也说明多代理分工需要一个能核对原始证据和整体验收的集成角色，而不是将子代理的“完成”文本直接相加。

## 9. 工作改进也需要独立的证据账

工作循环解决当前目标；改进循环比较下一次如何更好地做。候选 Harness 版本应绑定模型、提示、工具版本、任务分布和预算，避免把模型升级或任务变简单的收益算给某个编排组件。

设共同评估时域内基线期望效用为 J₀，候选为 J₁，迁移与新增验证成本为 C。只有对 `Δ = J₁ − J₀ − C` 的估计及不确定性才与是否采用有关。质量、时间、费用、人工负担和风险可以先保留为向量；没有共同价值函数时，不应伪造一个精确总分。

**P15：有限回归通过不推出所有未来任务更优。** 任意有限已测集合之外都可以构造表现更差的输入。因此“全部回归通过”只能支持指定回归域内未观察到退化。若需要概率性的采用条件，必须声明采样分布、置信方法、重复试验/选择规则和允许的失败代价；不能多次挑最好结果后沿用一次试验的置信界。

候选方向是维护两类证据：功能一致性反例集与成本/质量对照集。前者守住已知边界，后者衡量特定负载的增益。两者都不把自我评价当外部验收。
