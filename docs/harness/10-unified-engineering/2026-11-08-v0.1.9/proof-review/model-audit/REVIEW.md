## 唯一需修订的验证表述：MA01

**分类：共同语义依赖导致的检查边界；不是原解释器的已知语义错误。** 对应 `inputs/python/model_check.py:196–227` 和 README 对“独立 oracle”的描述。

迭代算法 `iterate_support` 与枚举全部固定点的 `least_fixed_point_oracle` 最终都调用 `step_support → formula_value`。两者能交叉检查固定点选择及旧值初始化问题，但不能互相发现共享解释器把 AND 写成 OR 的错误。

本线做了一个可重复的具体探针：只在审查进程中将每个合取分支的 `all` 改为 `any`，其他两套固定点算法均不变。

```text
公式 a AND b，输入 a=true、b=false：
规格期望 false；突变解释器返回 true。
完整 check_support() 仍无异常返回，遍历 14,641 个网络。
旧值初始化、清空后代两个指定坏变体仍有反例，故存在坏变体并不能排除共同语义错误。
```

这个结果没有证明原模型错；它证明原来的交叉验证没有独立检查这一层。为核实当前原文件，本线使用独立位掩码表达：每个 AND 分支是必须同时置位的 mask，OR 是存在某个满足 mask 的分支，不调用原 `formula_value`。结果如下：

- 121 个语法公式 × 32 个完整原子赋值，共 **3,872 项真值检查全部一致**。
- 14,641 个网络 × 8 个根赋值，共 **117,128 项固定点检查全部一致**。独立检查枚举四种派生位向量并以位包含关系选最小固定点。

建议把文案改成“固定点求解算法独立，公式解释器共享”；若将程序作为长期回归工具，纳入一个不调用原解释器的真值表/位掩码检查。无需废弃当前算法、否定现有结果或将这项问题称作产品缺陷。

## Python：忠实性、计数和最短性

| 部分 | 本轮判断及边界 |
| --- | --- |
| BFS | 使用 FIFO 队列与首次发现父边；每条出边均先检查再合并状态，故不会漏掉到达旧状态的坏边。失败后仍穷尽；达到状态上限抛异常。没有发现把截断当通过的问题。 |
| 动作 | send 性质读取原子转移前的另一动作占位。坏变体确实删除该条件。success/no-effect 是可撤回的接纳观察，模型没有假装证明世界真相。每动作只发送一次，不覆盖网络重试；文档明确。 |
| 支持 | 公式为正 DNF，不含空合取/常真分支，有限格上从 bottom 求最小固定点。独立枚举求解层有效；语义共享限制见 MA01。正递归是扩展反例，不误写成首版已采纳。 |
| 预算 | h/f/r 分开；坏变体损坏 r 时，h 和 f 不被同步改坏，物理性质仍能揭露超额。真实账单即使超预留也记入 U，不通过拒收账单隐藏成本。可信停止、固定价格和费用上界属于模型假设。 |
| 验收 | 版本比较与事件失效监视器是两种判定表达；不是调用同一个 applicable 计算两次。它们共享九字段及相关/无关事件分类，故不证明字段在业务上完备。D 只由 true 到 false、每次一次验收、无 ABA，文档均已限定。 |

计数核对不是只抄输出：10 个 BFS 图的深度直方图和均等于状态数，操作覆盖和均等于转移边数，反例数组长度均等于报告长度加初态。这里转移数是带事件标签的出边数，例如四个 D 失效原因可能指向同一后继；它不是不同状态对的数量。

支持域独立计算为 `1 + 15 + C(15,2) = 121` 个语法公式、`121² = 14,641` 个网络；根赋值 8 个、每次 3 种单根翻转，得到 117,128 项稳定输入及 351,384 次更新。语法不同但语义相同的公式可能被分别计数；报告没有把这些数称为互异布尔函数数或故障率。

验收状态数也可独立推导。存在验收时，每个当前/绑定字段有 `(0,0),(1,0),(1,1)` 三种组合；备注的验收时/当前值也有三种，D 和撤回各两种，共 `3^9 × 3 × 2 × 2`。尚未验收时有 `2^9 × 2 × 2`。合计 **238,244**，与枚举完全相同。

最短性结论限于模型事件数：

- 动作及预算、验收、两个聚焦支持网络的第一条失败边具有 BFS 最短路径保证。它不保证真实网络调用数、耗时或工具操作数最少。
- 全公式域的支持反例不伪装成同一 BFS。由于无真根时最小固定点全 false，旧值自支持至少需一次增加及一次撤回；错误删除替代支持至少需两个真根及一次撤回。所列 2/3 步达到该下界。构造前缀只有根增加，两种坏算法在该前缀与正确最小固定点一致。
- 指定 `18 > 10` 轨迹明确只是额外场景，未声称全局最短。一般预算坏变体在 `B=4,R=1` 中的最终超额最短为 8 步，且更早的负担覆盖违例在 3 步即出现。

没有从这些计数推出任意节点数、无限重试、任意费用或任意版本演化的正确性。README 中相应范围说明与程序一致。

## TLA+：动作赋值、有限性与效果语义

七个变量是 `targetEpoch, sent, messages, seenKeys, effects, cancelled, confirmed`。逐动作检查如下：

| 动作 | 更新 | 其余变量 |
| --- | --- | --- |
| Send | messages、sent | 全部 UNCHANGED |
| InstallNewEpoch | targetEpoch | 全部 UNCHANGED |
| Cancel | cancelled | 全部 UNCHANGED |
| Deliver 拒旧分支 | messages | seenKeys/effects 分支内 UNCHANGED，另四项共同 UNCHANGED |
| Deliver 去重分支 | messages | 同上 |
| Deliver 应用分支 | messages、seenKeys、effects | 另四项共同 UNCHANGED |
| ObserveSuccess | confirmed | 全部 UNCHANGED |

没有发现未约束的 primed 变量。Send 只读取旧 messages 的现有定义域，新增条目由单独分支提供；空函数初态与 `DOMAIN messages=1..sent` 相容。

六 cfg 都固定 `MaxSends=3` 和布尔能力值。targetEpoch 仅 1→2；消息 ID 至多三个、状态四种；key 范围有限；effects 从空集开始，仅加入有限 record 域中的元素；seenKeys 也是有限域子集。`[][Next]_vars` 可无限停顿，但不产生无限个不同状态。因此 stuttering 与未声明公平性不会破坏本次安全状态枚举的有限性，也不能据此承诺最终执行/确认。

目标去重将查询 key、记录 key 与增加效果放在同一 Deliver 原子步，这是模型的强假设，未被伪装成“检查器证明真实目标已原子”。effects 在应用分支增加与消息 ID 关联的 record，两个同 key 的不同发送可以明确记录成两个效果，因此集合存储没有偷偷吞掉重复效果。

需要保留的范围说明：Send 总是取当前 `targetEpoch`。旧 epoch 情形通过“先发送旧消息，再安装新 epoch，最后交付旧消息”产生；模型**没有**另设旧执行者在新 epoch 安装后继续生成旧 token 消息的 Send 动作，也不建模同一消息 ID 的再次交付。已有反例足以否定幂等等同 fencing，但不应把此模型称为完整旧进程接管或消息中间件重投模型。

NoStaleCommit 使用 `sentEpoch=commitEpoch`。在此模型中 token 不来自未来，故该等式正确表达未以旧 token 提交；对允许任意 token 或多个资源的扩展须重新定义，不直接搬用名字。

## 可选的下一步小证明

如果主线要补机器证明，优先以下两条，不让有限枚举代替一般证明：

1. **有限 DAG 局部重算等于全量重算。** 从旧状态全局一致、变更根集、完整影响闭包和任意拓扑序出发，证明闭包外结果不变，闭包内一次局部重算等于新输入全量求值。证明需真正使用拓扑顺序和依赖局部性，不把“局部结果等于全量结果”直接作为前提。此引理允许任意确定性局部函数；正性只在递归扩展中另需。
2. **显式费用转移的有限前缀预算安全。** 定义 settled、hidden、future、reserved、closing 的独立域，从各具体 Reserve/Spend/Settle/Release/Close 转移证明负担覆盖与总额不变式保持，再推出实际已花 `U+Σh≤B`。不要将“每步总额≤B”直接作为归纳假设之外的转移公理；应由准入、非负性、负担解除和结算转移推出来。一般化动作数与费用域时应保留有限求和的明确含义。

这两条分别保护增量更新算法与账本/真实负担的连接，比机械重述“相同输入的确定函数输出相同”更有价值。本线未撰写或运行上述机器证明。
