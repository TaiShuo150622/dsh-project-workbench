## 核心判断

“全”和“省”不冲突：全在捕获层做，省在理解层和读取层做。捕获是机械埋点，只花磁盘、不花 token，所以能一字不漏。token 只花在两处：把原始流蒸馏成结构化记录，以及把记录喂回以后的上下文。

前提是原始账本永远全量保留，蒸馏层省下的任何东西都能拿账本重做。work-record 的“过程中尽量记全、汇编时再挑”不变；常驻化只改一件事：“记全”不再靠主 agent 自觉，而是交给埋点。

覆盖五个场景：会话、代码任务、科学研究、读论文、AI 数据分析。它们共用一个公共层，各自再挂场景模块。

## “全”的验收尺子

记够没有，用四个检验判定；record-audit 按这四条抽查，阶段二的每个省钱配置也按它们回测。

| 检验 | 通过标准 | 用在哪 |
| --- | --- | --- |
| 可重放 | 凭记录能恢复当时的状态，并重跑出同样结果 | 复现、调试、事后核对 |
| 可追问 | 任何一个“为什么这样”，都能找到当时的备选、理由和拍板的人 | 以后的会话、人工回看 |
| 可学习 | 人的纠正和示范以“看到什么→做了什么→结果如何”的形式存在 | ds\_agent、skill 迭代 |
| 可审计 | 失败、放弃、试验次数、信息暴露都在，而且先后顺序无法篡改 | 预注册、统计预算、污染门 |

## 公共层：所有场景都记

每个场景都记下面五类内容。密钥在写盘前脱敏，“全”不包括存密钥。

| 类别 | 内容 |
| --- | --- |
| 原始流 | 每条用户消息、助手消息、工具调用参数、工具的完整返回、附件、子 agent 调用；每条带时间戳、因果父事件、token 与费用 |
| 人的信号 | 纠正、拒绝、回退、打断、接管、认可，也包括会话之外的终端、编辑器、notebook 操作 |
| 环境快照 | 开始、结束和关键节点的 git HEAD 与未提交 diff、锁文件哈希、数据文件哈希、环境变量名（不含值） |
| 信息暴露 | 每个行为者在时刻 t 之前看过哪些数据、文档和时间窗；污染门和时间纪律都靠这一项 |

### 两条贯穿规则

这两条决定了“全”存得起、用得对。

| 规则 | 做法 |
| --- | --- |
| 指针还是快照 | 不可变且有版本的源（commit、arXiv 的具体版本、冻结的数据集、带版本的对象存储）存指针加哈希；可变的源（线上表、网页、搜索结果、外部 API 返回）必须存快照，至少存当时实际用到的部分；模型输出不可复现，逐字存 |
| 来源标注 | 每条派生内容标明出处：用户说的、AI 提议的、工具观测到的、外部来源；AI 的提议在用户明确拍板前只是提议，两者一混，下个会话就会把 AI 当时的建议当成你的决定 |

## 各场景要加的

五个场景在公共层之上各挂一个模块；每个场景最值钱的，都是不可再生的内容。

| 场景 | 公共层之外必须记的 | 最容易丢、却最值钱的 | 重放锚点 |
| --- | --- | --- | --- |
| 会话 | 问题如何被重新定义；你给出的约束、偏好与判断；结论及状态（定论/暂定/被推翻）；分歧如何收敛；承诺的下一步；引用来源 | 结论被推翻的理由（不记，下次会重提已否掉的方案）；你纠正 AI 误解的原话 | 逐字原文 |
| 代码任务 | 任务与验收标准；起止 commit；每处改动的作者（AI 还是人）；接口与测试的变化；命令、退出码、耗时、输出；报错→根因→修复链；设计取舍；学到的代码库约定和坑 | 试过又放弃的方案及原因；被你回退或拒绝的改动，这才是真实的约定 | commit＋锁文件哈希＋命令序列＋环境 |
| 科学研究 | 假设登记（编号、从哪个结果派生、当前状态与三态判决）；看结果之前写下的预测和判决规则（预注册）；每次实验的配置、代码版本、种子、数据版本与时间窗、指标、原始输出位置；安慰剂检验；异常；替代解释 | 失败和中途放弃的尝试及总试验次数，没有它，统计预算和多重检验校正都无从谈起；发现循环里提议者每次看过哪段数据 | 代码版本＋配置＋种子＋数据快照哈希＋提议模型与提示 |
| 读论文 | 论文身份（arXiv 号与版本、PDF 哈希）；阅读目的；逐概念的理解状态；哪种解释有效、哪种无效；未解问题；你自己的批评和联想；AI 对论文的每个说法都挂原文位置（节/式/图/页），没挂的算无支撑 | 理解轨迹：卡在哪、哪句话让人懂了，这正是 paper-study 要交给下一个 AI 会话的东西；AI 的摘要反而最不值钱，论文不变，随时能重新生成 | 版本号＋原文位置 |
| AI 数据分析 | 问题与口径定义；数据源版本、行数、时间范围；每步变换及前后行数和理由；代码单元与输出（含图）；每个假设以及是谁做的；校验；最终数字→代码→数据的溯源；试过又弃的分析 | AI 默默做掉的假设（空值、去重、过滤）；你对口径的纠正；你示范时“看到了什么输出→做了什么→停顿多久” | 数据快照哈希＋代码＋环境＋种子 |

第三列的共同点：人的判断与纠正、失败与放弃、信息暴露的时间线都不可再生，AI 自己的解释和总结随时能重新生成。所以阶段二的 token 花在抽取不可再生的内容上，可再生的存指针就够。

## 阶段一架构：常驻 agent

主 agent 只干活、不记账；记录交给机械埋点，理解交给旁路的小模型和离线的大模型。不让主 agent 自己记，有三个原因：

- 会漏：模型自述时倾向于略过失败、死路和自己的错，这正是“示范而不是口述”要避开的。
- 贵：主模型的 token 最贵，它写下的记录会留在上下文里，之后每一轮都要重读。
- 分心：边干活边记账，会拖累主任务本身。

> 原稿图示：记录流水线 · 阶段一捕获，阶段二理解与读取（原平台嵌入图未随公开版收录）

上一排只花磁盘，token 都花在下一排；账本全量保留，所以下一排怎么省都能重做。

| 角色 | 做什么 | 用什么 | 何时运行 |
| --- | --- | --- | --- |
| 捕获器 | 把每个事件写进只追加的账本，大内容进 blob 库，写盘前脱敏 | hooks 与埋点，不用模型 | 常驻，每个事件 |
| 书记员 | 维护状态卡和段记录，每条挂账本事件锚点 | 规则抽取＋小模型，只吃增量 | 段边界触发 |
| 整理者 | 汇编成 work-record、paper-study 等格式的 md；跨会话合并实体；触发 record-audit 抽查 | 大模型，批处理 | 会话结束后或夜间 |
| 检索 | 新会话注入小索引，其余按“索引→记录→事件”逐层取 | 钻取工具 | 按需 |

捕获器和书记员都不在主会话的上下文里。hook 只做写账本、投递队列这类毫秒级的事（Claude Code 的 hook 支持异步）；书记员是订阅账本的独立进程，主会话感觉不到它。

## 数据模型

有两份原件：账本是证据原件，只追加、不修改；md 记录是知识原件，人可以改；json 只是从 md 派生的查询索引。md 里每个说法都挂回账本事件的锚点，和知识图谱的锚点协议用同一套。图谱要的“每条关系可追溯到原文”、ds\_agent 要的只追加账本，都落在这一层。

### 事件字段（建议）

| 字段 | 含义 |
| --- | --- |
| id | 事件唯一编号，锚点指向它 |
| ts | 时间戳 |
| session / segment | 所属会话与段 |
| parent | 因果父事件，比如工具返回对应的那次调用 |
| actor | 用户、主 agent、子 agent、工具、书记员 |
| kind | 消息、工具调用、工具返回、文件改动、命令、环境快照、人工操作、标记 |
| body / blob | 小内容内联，大内容只存 blob 的哈希 |
| tokens / cost | 这次调用的 token 与费用 |
| exposure | 这个事件让谁看到了哪些数据、文档、时间窗 |
| prev | 上一条事件的哈希，串成哈希链 |

账本定期把链头提交进 git，“先写预测、后看结果”就从自觉变成可证明。跨会话实体用稳定编号，包括假设、决策、报错签名、论文、数据集、口径；不同会话引用同一实体时，靠编号连起来。

### 场景模块怎么挂

书记员按段判断场景。一段可以同时激活几个模块，因为读论文→写代码→跑实验常常连着来。

| 段里出现的信号 | 激活的模块 |
| --- | --- |
| 文件编辑、git 操作 | 代码任务 |
| 实验运行、假设编号 | 科学研究 |
| PDF、arXiv 链接 | 读论文 |
| dataframe、SQL、notebook | AI 数据分析 |
| 以上都没有 | 会话 |

### 主 agent 的微标记（可选）

主 agent 在正文里把关键时刻写成锚点式标记，比如 ⟦决策 D12：选 A 不选 B，因为…⟧、⟦H17 → 证伪⟧、⟦放弃：方案 X，原因…⟧。每个只多几十个 token，规则层用正则就能抽出来，省掉一次模型调用。标记只是提示、不是真相来源：主 agent 恰恰最容易在失败处漏标，书记员以原始事件为准。

## 捕获点

捕获全靠机械手段：会话内用宿主的 hooks，会话外用 notebook、shell、编辑器各自的钩子。

### 会话之外的人工操作

| 位置 | 捕获方式 | 记什么 |
| --- | --- | --- |
| notebook | IPython 的 post\_run\_cell 事件 | 每个单元的源码、输出、耗时 |
| shell | zsh 的 preexec/precmd（bash 用 PROMPT\_COMMAND） | 命令、退出码、目录 |
| 编辑器 | 文件监听或定时 diff | 人的改动 |

代码的作者归属也靠这个：AI 的改动都经过 Edit/Write 工具事件，文件现状与 AI 最后写下的版本之差，就是人改的。ds\_agent 学的是“看到什么输出之后做了什么”，所以每个动作要连同它之前那次输出、两步之间的停顿一起存。

### Claude Code

代码任务在 Claude Code 里跑时，捕获层大半是现成的。下列 hook 都拿得到 transcript\_path：UserPromptSubmit、PreToolUse / PostToolUse / PostToolUseFailure、Stop、SubagentStop、PreCompact / PostCompact、SessionStart / SessionEnd；会话 transcript 本身就是完整的 JSONL。

再打开 `OTEL_LOG_RAW_API_BODIES=file:<目录>`，能拿到每次请求的完整请求体和响应体。transcript 记的是发生了什么，请求体记的是模型实际看到了什么；审计信息暴露，要的是后者。

| 坑 | 对策 |
| --- | --- |
| transcript 会被 cleanupPeriodDays 清理（默认 30 天） | 复制进自己的账本，不依赖宿主保留 |
| SessionEnd hook 在退出时默认 1.5 秒就被杀 | 那里只做入队，重活放离线；或调大 CLAUDE\_CODE\_SESSIONEND\_HOOKS\_TIMEOUT\_MS |
| OTel 的内容属性默认截断在 60 KB | 要全，就让原始请求体落文件 |
| 原始请求体每次都带着全量上下文 | 按消息块哈希去重存，否则存储随会话长度平方增长 |

以上按 [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) 核对，截至 2026-09-26。

### 自建 host

自建 host 直接在消息总线上埋点，用同一套事件 schema。压缩、提示布局和钻取工具也都由自己控制。

## 阶段二：钱花在哪、怎么省

钱花在蒸馏和注入两处，大头是工具输出；最大的杠杆是触发式加增量，粗算能差两个数量级。主 agent 写日志的开销，已经在架构上去掉了。

粗算：一个 100 轮、每轮新增 5k token 的会话，逐轮全量重读约 2500 万 token；切成 10 段增量处理约 50 万；再先压缩工具输出，约十几万。

下表按杠杆大小排。

| 手段 | 做法 | 省在哪 |
| --- | --- | --- |
| 触发式＋增量 | 只在段边界触发：新请求、commit、测试跑完、实验结束、压缩前、空闲若干分钟、会话结束；每次只喂上次检查点之后的增量＋当前状态卡 | 成本从随轮数平方增长变成线性 |
| 分层与级联 | 规则层免费抽：退出码、pytest 摘要、归一化报错签名、diff 统计、DOI 与 arXiv 号、SQL 表名、实验指标、纠正语、人回退 AI 的改动。书记员只把一段填进 schema 并挂锚点；整理者只做汇编、跨会话合并（如报错签名聚成常见错误簇）和需要判断的项。书记员输出过不了 schema 校验或自评置信度低时，只把这一段升级给大模型 | 大模型只碰少数段 |
| 先压再喂 | 工具输出留头尾和所有 error/warn/fail 行，重复行去重、进度条折叠，其余换成 blob 指针；数据预览只给 schema、形状和几行样本；diff 给统计加改动符号附近的 hunk | 原始量的大头；原件在账本，不丢东西 |
| 按价值定深度 | 按轮数、工具调用数、纠正次数、有无决策和失败打分：闲聊只过规则层，有纠正和决策的交书记员，改变了项目知识的才进整理者；冷内容读时再蒸馏 | 不在低价值会话上花钱 |
| 批处理与缓存 | 整理者走批处理接口；书记员的系统提示、schema、场景说明固定成前缀，只让增量变；注入的索引放稳定前缀（Claude Code 用 SessionStart hook），中途不改写，更新追加在后面 | 批处理约五折，缓存命中只按原价的一小部分计 |
| 读侧渐进披露 | 新会话只注入几百 token 的索引：活跃假设、未决问题、约定标题、最近的决策；其余按“索引→记录→事件”钻取 | 读的成本随需要增长，不随档案规模增长 |
| 一份钱两处用 | 状态卡兼作上下文压缩的摘要（自建 host 直接用；Claude Code 至少把 Pre/PostCompact 当触发点）；PostToolUse 的 updatedToolOutput 能把大段工具输出换成压缩视图＋blob 指针再交给主模型 | 反过来替主会话省钱 |

折扣比例凭记忆，各家不同，以定价页为准。PostToolUse 替换会让主 agent 少看信息：必须保留报错行和按指针取原文的路径，并先过下一节的评测再放开。

## 书记员的触发规则

书记员切在一个工作单元刚闭合的地方，用体量、空闲和硬边界兜底。触发点只决定书记员什么时候跑，不决定记录粒度：代码类记录按改动位置挂锚点，不按 commit 汇总。

不按时间切，因为切点和工作无关：空闲时空跑，密集时一段塞太多。也不按工具调用次数切：一次调用的体量能差上千倍，还会把报错和修复拆进两段。

| 场景 | 主触发（一个工作单元刚闭合） |
| --- | --- |
| 通用 | 主 agent 一轮结束（Claude Code 的 Stop）、子 agent 结束（SubagentStop） |
| 代码任务 | git commit、测试跑完出结果、任务清单里一项标为完成 |
| 科学研究 | 一次实验跑完落出结果、预注册写完、假设状态变化 |
| 读论文 | 一个问答闭合（追问完或转到下一个问题）、换节、你说“懂了” |
| AI 数据分析 | 产出一个结论数字或一张图、转入下一个分析问题、一次提交 |
| 会话 | 一个问题有了结论、话题切换 |

纠正和报错都不是切点，它们是一段修正的开头。纠正把所在段标成高价值、走更细的处理；报错的切点是它被修好，比如同一个报错签名不再出现、测试转绿。

| 兜底 | 规则 | 起始值 |
| --- | --- | --- |
| 体量 | 压缩后的增量到书记员输入预算就切；只切在工具返回之后、下一次调用之前 | 模型标称窗口的约四分之一 |
| 空闲 | 没有新事件就收段 | 10 分钟 |
| 硬边界 | PreCompact（状态卡兼作压缩摘要时，压缩前必须是新的）；SessionEnd（只入队，离线处理） | 必切 |

跨段的情节靠状态卡里的“未闭合事项”接上：在试的方案、在查的报错、在测的假设。记录写成对实体的状态更新而不是流水账，后面的段可以把“在试”改成“放弃”。

频率由两件事决定：谁在等这份输出，以及书记员一次能消化多少。会话中途没人读状态卡时，只在一轮结束时跑就够；捕获是实时的，预注册的先后由账本时间戳证明，和书记员何时跑无关。起始值都是超参：先统计现有 transcript 里“一轮”的长度分布（默认 30 天清理，尽早拷出），再用阶段一的账本重放几种配置，按关键项召回和成本定。

## 书记员配置：本地小模型

本地小模型干量大的填表，判断类项升级给大模型；先加脚手架，补不上再微调。整体效果有望接近全用大模型，具体差距用阶段一的金标准按项重放测出来。

| 书记员的活 | 例子 | 小模型的表现 | 处理 |
| --- | --- | --- | --- |
| 照明确证据填字段 | 你说“改成 A”；命令失败和报错；明说的决策与理由 | 差距较小 | 交给小模型 |
| 挂锚点、标来源 | 这条出自哪个事件、是谁说的 | 会挂错，也会编 | 机械校验，错了直接拒收 |
| 长段里的前后呼应 | 把开头的报错和结尾的修复连起来 | 输入一长就明显变差 | 切小段，靠状态卡接续 |
| 实体归并 | 这段说的是不是 H17 | 容易重复建实体 | 给候选列表让它选 |
| 隐含判断 | 没明说的放弃；你为什么拒绝；一句 dropna 悄悄删掉的行；你在论文哪里卡住 | 差距最大，容易漏，也容易编理由 | 标“需判断”，升级给大模型 |

不管谁来推断“为什么”，结果都标成推断，不能当成你说的。

### 要加的脚手架

| 加什么 | 做法 | 解决什么 |
| --- | --- | --- |
| 拆窄任务 | 先把事件分类成候选（决策、纠正、死路……），再逐条填字段；每次只激活相关的场景模块 | 小模型一次只做一件事时最稳 |
| 规则信号先喂 | 把退出码、报错签名、纠正语、回退等作为结构化提示放进输入 | 让它确认和标注，而不是从头发现 |
| 约束解码 | JSON schema 或语法约束（llama.cpp 的 GBNF，vLLM 和 Ollama 的结构化输出） | 格式错误归零 |
| 机械校验 | 锚点必须指向存在的事件；引用的原话必须逐字出现在该事件里；“你决定的”必须锚在用户事件上，锚在助手事件上的一律降为“AI 提议” | 编造锚点、把 AI 建议记成你的决定，这两类错被规则直接拦掉 |
| 候选实体表 | 把已有的假设、决策、报错签名的编号和一句话描述放进提示 | 避免重复建实体 |
| 状态卡按操作更新 | 新增、关闭、改状态都按编号下指令，不整段重写 | 防止多段累积漂移 |
| 弃权与一致性 | 允许输出“需判断”；同一段跑两次，结果不一致就升级；规则层有信号而模型没抽到，也升级 | 小模型的自评置信度不可靠，改用可检查的代理 |
| 输入预算 | 按模型的有效上下文定，不按标称窗口 | 小模型远没到标称长度就开始掉质量，体量兜底因此取约四分之一 |
| 示例与微调 | 先从金标准里检索 1–3 个相似段做示例；补不上再用（段 → 修正后记录）对做 LoRA | 学会你的习惯和口径，在专项上缩小差距 |

最后一行要守污染门：做示例和训练用的金标准，不能和评测用的那部分重叠。按会话、按时间切分，同一个会话的段不能一半训练、一半测试。

### 选型与调度

优先中文强的开源模型，比如 Qwen 系列；7B 级和 30B 级（或同等规模的 MoE）之间差距不小，型号用 model-eval 在重放集上选。本地按 token 不花钱，所以同一段跑两次的一致性检查几乎白送；但吞吐有限，还会与其他计算任务争用 GPU，要放到空闲时段或限制并发。好处是账本不出本机，代码和数据都不外发。

## 从全到省：过渡与验收

先用大模型全量蒸馏做出金标准，再让每个省钱配置在同一批账本上离线重放，过了事先写死的门槛才上线。

阶段一先不上书记员：只做捕获器，会话结束后用大模型对整段会话全量蒸馏；会话太长就先做确定性压缩，让它按指针回查原文。这样贵，但看得到全局：一个方案是不是死路，往往到后面才知道，增量处理天然看不到。攒一批会话，挑一部分你亲手修正，这就是锁定的尺子。

阶段二的每个省钱配置（纯规则、换小模型、改触发策略、改压缩规则）都在同一批账本上离线重放，和金标准比下面三项。

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| 关键项召回 | 纠正、带理由的决策、死路、试验次数、暴露事件、理解状态的变化，逐项单独算 | 事先写死；纠正必须接近 100%，它是 ds\_agent 和 skill 的学习信号；其余待定 |
| 无锚点说法占比 | 记录里没挂账本事件的说法所占比例，和图谱按天报的是同一个数 | 待定 |
| 每会话成本 | 按场景分别统计 | 前两项达标后，取成本最低的配置 |

这套流程就是 model-eval 的冻结数据集、跑矩阵、预注册判决规则，可以直接复用来选书记员的模型。上线后按比例抽检，哪类段的召回掉了，就把它升级回大模型。

整套设计的前提是原始账本永远全量保留。换了更好的模型，或者发现某类信息漏记了，拿账本重新蒸馏一遍即可；账本同时也是现成的冻结评测集。“先全后省”不自相矛盾，因为省的是理解的钱，不是记录的钱。
