## 1. Takeaway：最接近目标的证据在哪里

**最值得直接比较的是 MemAgent 的独立小模型控制器与 MemOS 的首步召回接口。** 前者已经用 4B 模型为另一个任务模型决定记忆来源和注入时机；后者已经实现 DSH 模型调用之前的检索、可选模型筛选与有预算的上下文包。两者并未证明“在本项目中减少首轮 prefill 一定更快、更准”，但提供了可以逐项借鉴的机制。

Letta 支持小常驻记忆与按需展开的层级文件，并让后台代理整理记忆；RLM 让模型访问放在环境里的长材料，两者适合补充持续整理和按需展开。Memory-R1 与 AgeMem 表明记忆操作可以按下游结果学习，但它们的控制职责和本文讨论的独立首轮组装器不完全相同。

| 来源 | 谁选择、何时选择 | 已核查的主要产物 | 与当前目标的关系 |
|---|---|---|---|

## 2. MemAgent：已经分出一个小模型管理另一个模型的记忆

### Cited Findings

此处是 **MemAgent: Learning to Manage Heterogeneous Memory Providers for LLM Agents**（2026-09），不是 2025 年同名、逐块读写压缩长上下文的 MemAgent。官方 README 明确分为 BEGIN、IN、END：BEGIN 先便宜并行探查不同 provider 的内容预览，再由小模型选一个 provider 深检索；IN 每一步选择调用短期记忆或 NO_OP；END 选择哪些 provider 保存完成轨迹。记忆表示包含技能、过程经验、知识、轨迹等。— [官方实现说明](https://github.com/WalkerWorldPeace/MemAgent/blob/7121cfe991c329748cd610515a3419cabc875ba6/README.md)，[论文](https://arxiv.org/html/2609.32521v1)

实现已核查：`memory_agent_provider.py` 先 `probe_all` 再 `make_decision`，`memory_agent.py` 能加载独立模型并生成 JSON 决策。README 训练路径是对不同来源强制探索，按任务结果、裁判评价及后续实际复用过滤样本，再对 Qwen3.5-4B 做 LoRA SFT；不是在线每个任务都做强化学习。`train_memory_agent.py`、provider 实现、评测入口实际存在。仓库也有无需微调的 PromptRoute，但仍依赖探索数据构造的决策知识库，且其路由 API 默认可与任务模型相同。— [探查到决策的代码](https://github.com/WalkerWorldPeace/MemAgent/blob/7121cfe991c329748cd610515a3419cabc875ba6/EvolveLab/providers/memory_agent_provider.py#L360)，[独立模型加载](https://github.com/WalkerWorldPeace/MemAgent/blob/7121cfe991c329748cd610515a3419cabc875ba6/EvolveLab/memory_agent/memory_agent.py#L102)，[训练入口](https://github.com/WalkerWorldPeace/MemAgent/blob/7121cfe991c329748cd610515a3419cabc875ba6/train_memory_agent.py)

论文配置为 GPT-5-mini 执行任务、Qwen3.5-4B 路由；任务类型为 GAIA、WebWalkerQA、xBench-DS。GAIA 报告 BEGIN 平均加入约 369 token，路由额外耗时约 1.2 秒/任务，平均任务步骤由 9.1 降为 8.0。该比例基于整项多步任务时间，**不是首轮 prefill 的基准**；系统总体仍向任务上下文添加记忆。— [论文 §5.2 与 Appendix C.4](https://arxiv.org/html/2609.32521v1#S5.SS2)

### Inferences

可借鉴的核心是把“找哪种知识、何时补进来、完成后留什么”做成单独决策。项目可先提供当前状态、历史决策、失败原因、操作经验、证据原文等几种检索视图，让小模型先看短预览，再选择展开，避免先把所有历史灌给小模型。

不能照搬 BEGIN 必须选一个来源的限制：同一项目任务往往同时需要用户约束、当前分支状态、既往结论和反例。可以允许多来源与空集合，并让缺证据触发补查。此扩展是本项目设计提议，尚未得到该论文验证。

### Gaps

- 仓库提供训练/推理代码；本次没有找到随仓发布的可直接部署路由权重，未运行复现。当前核查版本 `7121cfe9` 是 2026-09-25 的 initial release，不能仅凭完整目录称为长期成熟服务。
- provider 是对既有方法的重新实现，能力与原项目不同。自动本体细分、跨项目权限、长期身份和事实更新不是这项研究的核心。
- 论文短期记忆中所谓 verified facts 由规则从工具输出中抽取；命名不构成事实真实性证明。迁移到本项目必须保留来源和未验证状态。

## 3. MemOS：首步上下文组装已有具体 DSH 接口

### Cited Findings

核查 main=`64388b50e2a15528bcdf032e65a1ac792bcf63ee`（2026-10-29 UTC）。`index.ts` 注册 `agent/pre-step` 与 `session/event`；`bridge.ts` 在 step=1 且用户输入被宿主接受后，为每一轮最多启动一次召回，再把结果放进此次调用。默认召回预算 3000ms、上下文上限 6000 字符；这两个数是项目默认配置，**不是建议照抄的本项目目标**。— [DSH 注册代码](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/adapters/deepseek-harness/index.ts#L409)，[首步与去重判断](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/adapters/deepseek-harness/bridge.ts#L194)，[默认配置](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/adapters/deepseek-harness/index.ts#L79)

候选来源分技能、执行轨迹/episode、环境知识；通过全文、向量、结构化错误片段等通道检索，规则融合、去重和多样性排序后，可选 LLM 精筛。精筛器输入当前 query 和有角色、时间、标签等信息的候选，输出有序下标与 `sufficient`；可以合法返回空集合。确定性代码把保留项编成 `InjectionPacket`，技能默认注入摘要及可展开的工具提示。— [检索设计](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/core/retrieval/README.md)，[精筛实现](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/core/retrieval/llm-filter.ts#L99)，[编排实现](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/core/retrieval/retrieve.ts#L416)

这里有一个阅读源码才清楚的边界：检索 README 顶部仍说无 LLM 调用，后文及源码却已有可选模型精筛；其“出错至少留一条”的说明也不能解释为“模型正常返回空集合仍强塞一条”。当前代码区分模型有效空结果和超时/错误的机械兜底。这说明应以具体分支代码确认语义。

DSH `hostLlmEnabled` 默认 true；MemOS 未另配 provider 时，辅助摘要/过滤等调用会使用 DSH 的 provider/model 与额度。它没有默认自动换成便宜小模型。README 明示异步记录的 eventual consistency，以及进程突然崩溃时未完整重放的缺口；下一轮不等待上一轮后台抽取。— [DSH adapter 运行约定与已知限制](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/adapters/deepseek-harness/README.md)

**首轮 prefill 的关键边界：这个插件实现的是追加，不能单靠它减少既有历史 token。** `beforeStep` 先取得 `await next()` 的宿主决策，最终返回 `messages: [...decision.messages, this.createRecallMessage(context)]`（第 269–275 行），保留宿主已经接受的本轮消息并追加一条记忆；`index.ts` 还注册一段系统提示说明。`decision.messages` 不能误称为完整历史：这里是 pre-step 接受的消息，宿主如何另外组装会话历史仍由宿主负责；所查插件没有删除、筛掉或替换历史的操作。若宿主原先仍发送整段历史，安装该召回逻辑会增加输入；要实现本文讨论的首轮减负，必须由能控制最终 API messages 的编译层构造精简输入，或创建只携带必要规则、任务与上下文包的新 Worker 会话，具体能力需核查各宿主。后两种是架构可选项，不是 MemOS 此插件已实现的行为。— [追加返回代码](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/adapters/deepseek-harness/bridge.ts#L269)，[系统提示与 hook 注册](https://github.com/MemTensor/MemOS/blob/64388b50e2a15528bcdf032e65a1ac792bcf63ee/apps/memos-local-plugin/adapters/deepseek-harness/index.ts#L403)

### Inferences

这个工程样例最适合回答“宿主何时调用组装器、主模型最多等待多久、失败怎么办”。其模型精筛还不是本文讨论的完整自治控制器：检索路径和基本预算主要由规则决定，模型只处理已经找出的有限候选；`sufficient` 是模型自报信号，不能直接视为证据齐全的证明。项目可在此接口形态上增加检索计划、按需展开与证据覆盖检查。

### Gaps

本次没有运行其插件或核查本机宿主 API 兼容性；其 DSH 适配是当前独立开发实现，也不等同于DeepSeek Super-agent 原型内置功能。默认 profile 共享以及 host 模型配置均需具体设计。公开功能和单元测试文件存在，不等于已测出本项目任务精度、首轮延迟或故障恢复合格。

## 4. Letta / MemFS：小常驻索引、按需打开、后台整理

### Cited Findings

当前 Letta 文档将 MemFS 定义为 Git 支持的记忆文件系统：根目录文件每轮进系统上下文；有自己 `MEMORY.md` 的子目录平时不展开，由目录名与索引引导模型读取。默认没有语义/向量索引，普通文件搜索可用，额外搜索模块可提供混合搜索。后台 dreaming 代理可按完成步骤数或压缩事件整理记忆；它与 memory doctor 使用 worktree 并发修改。— [MemFS 官方概念](https://docs.letta.com/concepts/memfs)，[Memory & dreaming 配置](https://docs.letta.com/configuration/memory)

公开 CLI 源码中的 `memory-filesystem.ts` 和 agent prompts 可以核查记忆文件的集成；读取时版本 `b8a0b3e0a4a6c4c6e94c50bdfe1804b6151ffa9e`，提交时间 2026-11-01 02:16 UTC，即洛杉矶 10 月 31 日。— [公开文件系统实现](https://github.com/letta-ai/letta-code/blob/b8a0b3e0a4a6c4c6e94c50bdfe1804b6151ffa9e/src/agent/memory-filesystem.ts)

### Inferences / Gaps

这一层级方式能给执行模型一个很小的入口，也便于人查看和修正。它通常仍由执行模型自己决定读哪些文件；后台 dreaming 是提前整理，而不是已证明的“每个新任务开始前独立小模型编好整个上下文”。本项目可保留相同的展开接口，让前置组装器先读，执行模型在证据不足时再补读。Git 版本可以回溯文件变化，但不能自动表示事实有效期、冲突语义和本体迁移。

## 5. RLM：把长材料放在环境里，让模型按需探查

### Cited Findings

RLM（2025-12-31）把长输入作为 REPL 中的变量；根模型查看概要、写程序筛选片段并调用子模型，迭代形成答案。原论文 GPT-5 实验使用 GPT-5 为根、GPT-5-mini 为子调用；控制选择的仍是强根模型。论文报告多种长材料任务的收益，也明确存在长尾成本、短输入劣势和顺序调用造成的运行时差异。— [论文 §1–3、§5](https://arxiv.org/html/2512.24601v1)

官方当前库有真实推理代码，支持不同子模型后端、上下文环境跨调用持久化，以及预算、迭代次数、超时等约束；当前 README 也列训练入口。核查版本 `d04208afbad29ca675ab13478c40ee8bebc84bfe`（2026-09-24）。— [官方库](https://github.com/alexzhang13/rlm/tree/d04208afbad29ca675ab13478c40ee8bebc84bfe)，[模型与预算接口](https://github.com/alexzhang13/rlm/blob/d04208afbad29ca675ab13478c40ee8bebc84bfe/rlm/core/rlm.py#L49)

### Inferences / Gaps

有用的借鉴是让原件可按需打开，先给短视图和来源句柄；遇到密集信息任务再扩大阅读范围。RLM 本身不负责长期记忆摄入、本体或跨会话失效管理。要改成“小模型先为大模型选资料”必须另做角色分工和评估；不能把 RLM 中强根模型的结果直接归给一个便宜前置模型。程序执行环境也不是单纯只读检索接口，产品化可先提供受限的 search/open 工具。

## 6. Memory-R1 与 AgeMem：学什么值得留下、值得读

### Cited Findings

Memory-R1 将 Memory Manager 的 ADD/UPDATE/DELETE/NOOP 结果交给固定回答模型，以回答正确性训练写入策略；检索侧先用相似度召回 60 条候选，再由 Answer Agent 自己做 distillation 并回答。论文主评估是多会话问答；这不是一个已验证可服务任意执行模型的独立上下文编译器。官方 README 当前仍写 **Code coming soon**，核查 head=`9c413a2413c4fee160ec05445856c1529d63ac7a`（2025-09-10）。— [论文方法 §3](https://arxiv.org/html/2508.19828v4#S3)，[官方发布状态](https://github.com/yansikuan/memory-r1/blob/9c413a2413c4fee160ec05445856c1529d63ac7a/README.md)

AgeMem 将长期 Add/Update/Delete 和上下文 Retrieve/Summary/Filter 都纳入同一任务模型的动作空间，通过三阶段轨迹和 step-wise GRPO 训练；轨迹显式插入干扰材料，奖励同时考虑任务表现、记忆质量和过量存储/工具调用/上下文膨胀。所查原论文没有定位作者实现仓库，正文 GitHub 链接主要指向基线。— [论文方法 §3](https://arxiv.org/html/2601.01885v1#S3)

### Inferences / Gaps

两项工作值得借鉴的不是“现在就训练模型”，而是把反馈定义成执行任务是否更顺利、关键证据是否保留、是否引入噪声。第一版可以用提示和规则形成完整轨迹数据，先测到稳定失败类型，再决定监督微调或强化学习是否值得。论文中的问答 exact-match、裁判分数和阶段构造不能直接代替真实项目任务的成功判据。

## 7. 对 Record 讨论稿的推导

以下是研究者提出的架构推导，不是目标项目已实现能力，也不是上述论文共同保证的结果。

1. **将职责分成三条路径。** 摄入路径在轮末把证据与候选记忆可靠留下；整理路径低频演化概念、别名、关系和聚合；调用路径在新任务到来时，由独立组装器检索并提供本次上下文。摄入时不知道未来任务，因而不能只保存一个永久总摘要。
2. **组装器先看任务，再决定读什么。** 输入至少包括用户原话、当前任务目标、项目/会话范围、可用记忆目录和预算。它可以拟检索词、选记忆视图、查看候选证据、补查歧义，再返回选中证据 ID、简短解释、仍缺的信息和展开入口。模型输出尽量先选择可验证的证据，减少无来源改写。
3. **确定性编译负责封装。** 独立代码检查 ID 存在、来源范围、时间/版本、内容预算、失效与删除状态，并拼出执行模型上下文。关键用户约束与当前任务原文有保留策略；选择器不能随意漏掉或改写。模型判断“够了”只是一项信号。
4. **本体服务多种索引与关系展开。** 项目—任务—决策—证据—约束—操作结果等关系，帮助检索跨过字面相似性，也能定位前置条件与冲突。自动细分是否保留，应看它是否减少错误候选、漏检和跨域混淆；无需每次输入先从树根走到叶子，更无需把整棵本体塞进主模型。
5. **执行时允许补取。** 首包不承担预知所有未来步骤的任务。执行模型可以请求某个事实的原文、某条失败经验的适用条件或某个概念的相关关系；组装器可以据工具结果更新需求，但要控制反馈循环的调用次数和延迟。
6. **保留可审计的选择轨迹。** 记录任务查询、候选集合、保留/舍弃、原因、版本、展开行为，以及主模型后来实际使用或纠正了什么。检索相关性、任务收益与事实可靠性分开记；“经常被用到”不等于“是真的”。
7. **评估优先回答首轮组装的目标。** 对同一执行模型与同一任务比较：当前上下文、机械检索、小模型组装、小模型组装加关系/本体；再在相同 token 预算下比较，以免把变化全部归给本体。至少观察首个有效动作、漏掉关键约束、任务完成质量、错误探索和总调用成本。首轮输入 token、首轮等待与整任务耗时分开测；本次没有测这些指标。

### Gaps：尚不能由文献替项目决定的事

- 该组装器能在哪些宿主真正位于执行模型第一次调用之前，以及宿主是否允许替换而非只追加既有输入。
- 哪种小模型足以识别当前任务需要的罕见历史事实、权限和否定约束；“模型小”本身不是质量保证。
- 私有记忆规模、候选量、模型启动方式、调用网络与缓存对延迟的影响；公开多步检索任务的比例不能直接搬过来。
- 本体演化与检索反馈的相互影响：以检索命中为唯一目标可能制造过拟合类别；需保留未使用但可能关键的原件，并用未来任务验证。
