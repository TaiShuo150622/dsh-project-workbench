**先读本页，再按需要查 [完整索引](INDEX.md)。** 当前工作台插件的使用方式与已经存在的能力见 [仓库 README](../../README.md)，历史桌面验证见 [验收记录](../acceptance.md)。本文集中的总体架构、通用面板、上下文组装和后端扩展包含待实现方案，不能据此认定当前插件已具备全部功能。

## 版本与阅读边界

- **总体讨论**：优先读 v0.3，v0.1 / v0.2 用于追溯问题如何展开。开源研究和资源数字保留原调研日期；本次整理没有重跑实验或更新第三方产品能力。
- **底座架构**：优先读 v0.1.6，v0.1.5 是前序版本。公司选型、项目专属评测与内部实施材料已排除，保留的通用内容以公开整理版说明为准。
- **面板平台**：v0.1.0 → v0.1.1 → v0.1.2。当前入口为 `docs/design/overall-discussion.md`；两份明确历史版放在其 `history/` 下。交接包中的分题稿保留原阶段，遇到差异先查整体稿与协作约定，实施前仍需冻结契约。
- **Record**：优先读源 v0.1.2。名为 v0.2 的旧稿后来统一编号为 v0.1.1，属于更早材料，不能只比较版本数字。本文集未附项目专属实现，研究设想不等于上下文组装能力已经实现。
- **早期 AI 编码 Harness**：一份源文件名标 v0.1.2、正文标 v0.1.1，索引同时记录，不自行改写其版本历史。
- **DAG**：以 `current/` 为主题入口。`history/dsh-complete/` 保留另一份有差异的“面板头重做”修订；涉及非公开实现的部分只发布通用方法摘编，不能当作完整协议或可执行契约。
- **远程**：先读 v0.1.1，再读 2026-11-04 的 rc.5 记录。旧稿中的 rc.3 观察保留历史语境；后续兼容记录也不等于真实跨机、模型调用和断线恢复全部通过。
- **Chrome**：设计、审计和改进队列分别保留，文件中的检查结果对应当时的版本与范围。本次归档不改变原测试结论。

## 收录与维护规则

本次收录个人 Harness 相关稿件和阅读所需的设计附件。公司项目文档、量化项目代码与数据、内部实施案例、原始会话、真实运行日志、凭据以及私有附件不随文集发布。混合稿件采用注明范围的公开整理版；深度依赖内部实现的材料采用公开摘编或整篇排除。

公开整理日期为 **2026-11-06**。历史主张、计划和测试结论保留其原时间语境；公开整理没有新增验证成果。部分原图改为标注清楚的 Mermaid 示意，原网页、原始证据包和未收附件不保证随版可用。设计 HTML 使用示例数据；画板导出缺少原环境的 `support.js` / `dsh-panel.js`，只用于查看设计源，不能作为独立运行的产品。

同一讨论稿的重复副本只保留一个入口；两套交接包共用的画板和主题按目录依赖各自保留。明确版本保留，新稿不覆盖旧稿。本次没有导出每一条 Git 中间修订。之后新增文档时：

1. 放入对应主题，使用清楚的名称与版本；同题新稿注明前序版本和当前入口。
2. 在稿件开头区分讨论、实施计划、历史记录与验收证据，注明日期与适用版本。
3. 更新本页推荐阅读关系、主题 `CONTENTS.md` 和 [完整索引](INDEX.md)。
4. 校对本地链接、公开范围与文件状态，再更新 [MANIFEST.json](MANIFEST.json) 中的路径、源版本和公开副本 SHA-256。

清单哈希用于定位本文集中的具体副本，不把整理后的文字冒充未经改动的原稿。
