## 线

只开一条线。新仓库文件不多，几乎每张卡都要改 `client/registry.js` 和 `scripts/`，拆开只会制造冲突。

| 项 | 值 |
|---|---|
| 工作树 | 计划为`${PROJECTS_ROOT}/dsh-panels-work`；开线时先查现有工作树，适用则复用 |
| 分支 | 计划为`codex/panels`，基于阶段A冻结单的完整提交SHA；不能仅记录“最新main” |
| 合并 | 全部过了再合回 `main`，人来合 |
| 写者 | 同一时间只有一个，Codex 在跑时别进这个工作树 |

开线时由实施主会话维护本页状态及协作文档约定的实施状态入口；设计侧交付变更单，实施侧明确采用提交后再改在途任务。状态／证据文件先列入任务卡允许范围，不能通过“维护状态”绕过白名单。

## 怎么验

- `tools/run-card.sh` 跑完 Codex 后自己跑卡上的 `verify`，Codex 自报不算。
- `tools/count-tests.mjs` 要求这张卡的测试真的存在、真的跑了、没有跳过，只看总数全绿不算。
- 带 `npm run e2e` 的卡在隔离的真宿主里验，不是模拟。需要本机有桌面版 CLI 和 Chrome。
- 最多两轮，不过就标卡住，失败输出留在 `.handoff-logs/`，改动留在工作区不提交。
- Codex 退出码非 0 但 verify 过了，脚本返回 1，要人看，不算通过。
- 全部 verify 只在本机跑，不需要 GPU 机器或远端。

基线上空跑过：15 张卡都因为测试文件不存在返回 1，这是对的，表示尺子是活的。`count-tests.mjs` 自己也验过，遇到跳过、条数不够都返回 1。

## 审查

每过三张卡做一次审查，用 Claude，不用 Codex 自审。审查抬头写明独立性：不同模型。界面类的卡要对照 `design/` 看截图。

审查必须附实际提交、差异和证据；尚未取得Claude结果时登记待审查。同模型的不同会话只能如实登记不同上下文复核，不代替这里的不同模型审查。卡验证通过、审查完成、集成和真实环境验收分别记录。
