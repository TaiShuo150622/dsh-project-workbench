## 持久记录与职责

`p.continuity` 保存 `revision`、`decisions`、`handoffs`、`previousLeads` 和 `deliveryPaused`。旧项目无此字段时按空接续记录读取；已有格式不支持时明确报错，不覆盖原记录。

决定包含内容、理由、`active/superseded` 状态、创建时间和前后替代链接。新增或替代只追加新项并更新旧项的替代关系。面板输入被标记为人工维护记录，不声称已由模型验证。写入在持久事务内核对 `expectedRevision`，陈旧版本及安全整数上限都明确拒绝。

接续包保存项目和接续版本、可选 `p.coordination` 的目标/标准/排序版本、当前有效决定、线程任务及汇报出处、工作树引用、状态观察和下一步说明。工作汇报明确标记为执行者报告，不升级为验收或新授权。保存包是历史快照；当前决定仍应读取实时记录。

## 读取与上下文预算

| 入口 | 行为 |
| --- | --- |
| 总会话上下文 | 简短版本、目标和有效决定预览，线程状态计数、下一步及最近快照引用；不注入线程任务/报告全文和完整接续历史 |
| 项目列表/状态 | 决定预览、总量和最近快照元数据，不复制每个快照正文 |
| `project_continuity` | 只读当前所属项目，返回有上限的 JSON 文本片段及下一页位置 |
| 面板“查看当前接续信息”及原文入口 | 按同一只读协议翻页，可按 ID 读取决定、线程或已保存快照 |

预算登记在 [hyperparams.yaml](../../../config/hyperparams.yaml)：摘要预算 8,000 字符；预览最多 8 项、单字段 240 字符；正文每页最多 12,000 字符。摘要省略会明确显示，不能把预览当完整决定。超出摘要预算时退为引用与计数。持久历史不因展示预算被删除。

只读类别为 `current`、`decisions`、`decision`、`handoffs`、`handoff`、`previousLeads`、`thread`。单条读取须给本项目内的 `id`。`nextOffset` 非空表示尚未读完；继续读取须提交上页的 `sourceToken`。同一来源变化时拒绝续页，读者须重新核对；历史快照正文不随当前项目变动。当前事实指纹不包含每次阅读产生的观察时间，实际读取时间另以 `readAt` 返回。

预览之外的历史总会话和快照可从完整目录读取。当前实现没有对全部历史做智能抽取或自动排序。

## 接手与消息行为

1. 用户在空白项目也可直接进入“管理项目”，打开“决定与接续”。
2. 接手服务与该项目汇报投递共用互斥锁。旧总会话必须已加载、状态明确为 idle，且 nextTurn/nextStep 均可检查并为空；未加载、运行中或未知都拒绝。
3. 创建普通 DSH 总会话并应用既有 research 权限边界。创建后再次核对新旧会话空闲、接续版本和会话归属，持久绑定前再核对一次。创建后失败会保留已创建 ID 和旧关联，不自动删除或重创。
4. 对旧总会话的未发送汇报核对既有接纳记录。同一消息已接纳就补记发送状态；其他消息保持原 ID，重定向至新总会话。既有 error/recoveryHold 不因重定向清除。
5. 新总会话绑定后 `deliveryPaused=true`；旧总会话列入历史，不能再分派。工作线程、工作树、成果、权限和旧会话保留。
6. 用户单独点击“开始接续并接收汇报”才放行新总会话的报告投递。没有报告时不会发送首条模型消息；此操作不分派任务，也不清除恢复方向的 hold。

实际发送前会重读当前 outbox 消息和接收方，避免先前扫描到的旧目标在接手后被继续使用。已经进入发送中的操作先完成，再尝试接手；旧总会话因此变忙就拒绝本次接手。

## 接口与集成

| 端点 | 输入 | 输出/副作用 |
| --- | --- | --- |
| `continuity` | projectId、可选 section/id/offset/sourceToken | 有界只读页，不创建会话、不启动任务 |
| `continuity-decision` | projectId、expectedRevision、text、可选 rationale/supersedesId | 保存决定及替代链接 |
| `continuity-handoff` | projectId、expectedRevision、可选 nextStep | 保存不可变包，返回元数据引用 |
| `continuity-takeover` | projectId、expectedRevision | 创建并绑定新总会话，保留旧关联历史，暂存汇报 |
| `continuity-begin` | projectId、expectedRevision | 只解除接续暂存，并尝试正常投递 |

A 的 `p.coordination` 可缺省。C 的 `thread.recoveryHold`、`outbox.recoveryHold` 被保留并参与发送前检查；B 不解释或放开这些 hold。共享接入点为 `index.js`、`server/projects.js`、`client/app.js`、构建脚本和宿主只读核对。三分支合并由统筹者处理。

客户端构建需先拼接 `client/continuity.js` 再拼接 `client/app.js`，构建指纹包括本线新增代码。工作树中的历史生成文件没有在执行者本机重新生成；验证/发布前须在目标流程重新构建。

## 限制与未闭合项

- 真实宿主已有会话读取接口的兼容差异已适配；B 通过 Native.inspect 抽象读取，并在组合试验实际完成接手。其他宿主版本仍须核对接口契约。
- 宿主外部直接发消息不参与插件的互斥锁。绑定前核对能拒绝已观察到的变化，但不构成跨系统事务；极窄的宿主并发窗口仍须实际宿主审查和试验。
- 新总会话动态读取最新上下文，代码不保证模型会完整阅读决定、正确推理或自动登记采用版本。运行线程的检查点采纳流程仍由维护者和协调者管理。
- 持久历史和保存的完整包不设删除策略；读页有界，但大量快照会增加磁盘和序列化成本。自动压缩、索引及保留策略不在本轮实现中。
- 本轮针对同一宿主的普通 DSH 总会话与工作线程；跨宿主迁移、外部代理、多实例共同写入不在验证范围。
- 创建接口回执丢失且无可识别会话 ID 的处理与 C 合并时需保留未知状态；不得据“未获得 ID”断言未创建或直接重跑。
