## 已实现行为

核对接口只保存观察元数据，核对动作与继续执行是两个不同的产品操作。

| 操作 | 行为 | 保留的边界 |
| --- | --- | --- |
| 项目页“管理项目” | 可以直接核对项目，空白总会话无需先发送模型消息 | 不依赖原生会话头部已挂载 |
| “核对原任务状态” | `POST /api/project-workbench/recovery-check`，载荷为 `projectId` | 不 create、deliver、stop、retry 或 kick；不解除 hold |
| 启动恢复 | 对历史未确认消息及活动、排队、含后续输入的线程设置 hold，观察各原会话 | 不启动调度；unknown 不改成失败或中断 |
| 已确认空闲的旧活动线程 | 启动恢复可以沿用既有 `interrupted` 阶段；稍后核对只更新观察 | 不清空 summary、sessionId 或 worktree |
| “继续原任务（可能接着执行）” | 先要求同实例、同会话、同任务代次的核对记录，执行前再确认当前空闲 | running、unknown、missing 的既有会话拒绝；review/completed 拒绝通用恢复 |
| 从未启动的历史排队项 | 仅第一代、没有会话/工作树/工作目录/启动标记/汇报成果的 held 项可显式放行 | 不因重新连接或核对自动排队；首次执行仍是原任务代次 |
| “继续已排队后续任务” | 对已结束阶段的 held 后续队列，先核对再显式取出下一项 | 保留原成果，不重跑 completed/review 的原任务；新交代遇保留队列时明确拒绝 |
| “确认重试总对话汇报” | 只选择当前 lead 的待确认汇报，要求新鲜核对与当前 idle，保留原消息 ID | 未确认 worker 输入继续 held，不阻塞已核对的 lead 汇报；重定向不解除 hold |
| 创建前明确失败 | 记录能证明尚未创建的阶段，核对后允许显式继续 | 复用已经记录的工作树；未知创建不进入此路径 |
| 已创建后设置失败 | 持久保存 `createdSessionId`，继续前只读核对原权限 | 不通过新建会话绕过权限问题；核对和权限验证均不激活 Agent |
| 浏览器连接失败 | 保留最近项目数据，单独显示连接状态和“状态已陈旧” | 不用断连状态覆盖任务 phase |

启动恢复仍保留已有的原生 Workspace 归属修复，仅针对插件创建的会话；用户加入的会话保留其原归属。单个冷会话或无法检查的会话不会阻止观察项目中的其他会话。手动核对接口本身不执行 Workspace 修复。

当前宿主的被动会话读取通过 `sessionPersistence.open(id, 'read')`，读取 `header/events` 后在 `finally` 关闭 handle；较旧宿主继续使用已有 `sessionController.inspect`。主线核实了该兼容入口，本分支采用同一适配及 3 条兼容行为测试。读取不调用 `resolveAgent`，不获取写入控制权。

## 状态契约

运行观察与业务阶段独立保存，观察为 idle 仅证明当前 Agent 可检查且空闲。

| `runtimeState` | 成立条件 | 不代表 |
| --- | --- | --- |
| `running` | 当前宿主 Agent 注册表明确报告 running | 外部命令正常、阶段结果正确或目标完成 |
| `idle` | Agent 明确 idle，且 nextTurn/nextStep 都是可检查的空数组 | 原任务已完成或外部副作用成功 |
| `missing` | 尚未分配会话，或宿主明确返回 `session/not-found` | 可以为已有任务自动新建替代会话 |
| `unknown` | Agent 未加载、收件箱不可检查/有待处理输入、检查失败或任务身份变化 | 失败、停止、完成或可安全重复执行 |

持久字段 `p.recovery` 保存 `checkedAt`、`runtime`、`lead` 和 `threads`。每个线程观察包含 `threadId`、`sessionId`、`generation`、`runtimeState`、`reason`。记录发生变化时保守保存 `task-changed-during-check`，不把旧观察归给新的代次。

`runtime` 只包含随机 `id`、进程 `startedAt`、`platform` 和 `arch`。同一 Node 进程热加载保留该标识；新进程具有新的标识。响应另附 `currentRuntime`、`stale` 和 `staleReason`，实例、身份或可观察状态变化会使旧观察陈旧。公开观察不包含主机名、用户名、IP 或原始异常详情。

DSH 进程持续、Agent 当前状态、外部命令是否结束、外部动作是否生效、产物是否通过验收是不同事实。本接口没有外部命令效果读回协议，也不保证外部作用恰好一次。用户明确继续前仍需结合成果与任务记录判断下一步。

## 历史消息与组合约束

`thread.recoveryHold` 和 `outboxMessage.recoveryHold` 是独立的保留标记，观察或总会话重定向都不能解除它们。

`flush` 读取当前消息目标，跳过 held 消息和线程；在异步观察后再次读取目标及状态。投递抛错时，消息可能已经被宿主接纳，因此记录“结果尚未确认”，保留原阶段并设置 hold。后续调度不自动重送。原生稳定消息 ID 去重继续保留，但不能被表述为外部效果的恰好一次保证。

显式继续既有线程会取消其未确认旧投递，保留原会话与工作树，再形成新的任务代次。有效的当前线程汇报可以解除线程 hold；对应历史 outbox 消息的 hold 仍保留。已验收或待验收成果不会通过通用恢复操作重新执行。

`retry_followup` 只适用于 `review/completed/waiting_user` 且保留后续队列的线程，要求同实例、同会话、同代次的 idle 核对，并再次检查当前 idle。它消费既有队列项，保留原 summary；不将原任务文字再投递。普通 `dispatch` 遇到待确认后续队列时拒绝新交代，调度也不再用后续队列覆盖已排队的当前任务。

创建失败记录 `creationRecovery.sessionState/worktreeState/permissionVerified`。`Native.create` 在调用原生会话创建前失败可以证明 `sessionNotCreated`；调用后无身份则保留 unknown；返回身份后改名或权限设定失败则保存原身份。`Worktrees.create` 仅在尚未调用 `git worktree add` 时标记 `worktreeNotCreated`，调用后的错误不能证明没有创建工作树。未知创建结果提示人工核对、保留成果，本轮不自动修复或绑定未知身份。

A 线负责整体目标和验收约定。B 线接手时必须保留 C 的 hold，并与投递共享每项目互斥；过期总会话不应继续控制项目。本分支只验证“重定向保留 hold”的 C 行为；真实 B 接手 API、旧总会话权限和三线组合交付须在整合版本验证。

## 后续真实验收

后续验收要证明重新观察同一个任务的行为，而不是把测试成功扩展为远程持续执行承诺。

1. 在实际宿主核对一个空白总会话和原工作线程，确认页面可用、匿名实例及最后观察可见。
2. 只改变测试观察连接，验证重连没有新增会话、任务代次或重投旧消息；保留正常运行任务。
3. 对可确认的原会话核实其成果与状态，再测试用户显式继续；未知状态继续保持待核对。
4. 组合 B 的接手与 C 的 hold：旧总会话失去派发权，held 结果重定向后不自动执行。
5. 用 A 的同一目标和验收条件检查最终成果，区分源代码、测试、真实模型执行和用户验收结果。
