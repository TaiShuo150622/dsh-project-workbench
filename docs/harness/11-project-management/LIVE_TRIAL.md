## 写入与原结果保留

试验新建一个合成项目，写入目标和验收条件、两条有替代关系的决定、两个研究任务、保存的接续包和一次协调会话接手。I1 结束后只修改线程排序；I2 不创建工作任务。原工作线程始终各为 generation 1，最终停在 `review`，未自动标记验收完成。

驱动在创建项目、两次发模型消息及接手前保留检查点，并在每个阶段记录状态。三份输入文件 SHA-256 前后相同；原始检查点、宿主会话及测试输出留在私有验证环境，不上传公开仓库。试验对象保留供后续界面查看，未清空或重建。

初次调用旧宿主 RPC 格式被网关拒绝，尚未创建工作线程。修正为当前宿主的 `{args:{request:...}}` 格式后，复用原项目和原请求身份继续；只结束过错误的监测脚本，未重启宿主或已完成的模型任务。驱动遇到已有检查点默认拒绝自动重放。

## 内容复核与待验收项

新协调会话正确使用了被替代后的决定，说明已有两份研究汇报，同时指出 Markdown 验收说明本体尚未交付，汇报不等于用户验收。接续过程中没有把“已有汇报”直接升级为“整体完成”。

两份汇报存在应人工裁定的解释差异：输入约束仅规定 id 非空、name 为文本、同批次 id 不重复；另一份汇报附加了去空白、建议 name 非空等处理建议。新协调会话虽列出待定口径，但“没有冲突点”的概括过强。后续验收应明确区分原文约束、建议和待决定项，再核对最终验收说明；本轮没有自动语义一致性门禁。

## 复用方式

组合分支提供 `scripts/trial-management.mjs`。仅对授权的隔离合成项目使用，通过进程环境提供 `DSH_TRIAL_URL`、`DSH_TRIAL_TOKEN`、`DSH_TRIAL_PROJECT`、`DSH_TRIAL_EVIDENCE`；令牌不写入驱动或公开记录。长任务使用 screen，保留原始输出和退出码。已有检查点先人工检查，不能为重新得到绿色结果重跑已完成任务。

`scripts/refresh-client-registry.mjs` 是针对该宿主版本保留旧客户端注册路径的一次性维护入口，仅在确有旧构建证据时使用。它刷新客户端模块注册表，不重启 DSH 主进程或工作会话，运行后应停用 Loader 入口；本次已停用。
