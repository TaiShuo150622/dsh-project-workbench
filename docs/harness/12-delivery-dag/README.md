# 交付管理与项目 DAG

2026-11-13 · 实现分支 `codex/harness-delivery-dag` · 构建 `b8bafddb38df`

本轮把整体要求与模块工作连起来：验收条件 → 模块输入输出约定 → 原工作线程 → 成果 → 人工验收。项目图显示关联、缺口和变更影响，帮助协调者判断哪些工作真正支撑当前交付。

先读 [整体方案 v0.1.1](Harness-工作台与DAG整体实施讨论稿-v0.1.1.md)，具体数据与接口见 [CONTRACT.md](CONTRACT.md)，已运行的检查和未完成步骤见 [VALIDATION.md](VALIDATION.md)。文件清单见 [CONTENTS.md](CONTENTS.md)。

## 如何使用

1. 打开已有项目的管理面板，进入「交付管理与 DAG」，显式启用本项目交付管理。既有验收文字会获得稳定身份，原线程和会话保留。
2. 逐项维护验收条件。创建模块工作包，填写输入、输出、完成要求，选择负责的条件、原线程、上游模块及适用决定。
3. 在工作包下「登记成果」，写明成果位置或原会话引用、实际核对证据和限制。登记动作不读取文件，也不把线程汇报自动当作验收通过。
4. 在条件下「核对并记录验收」，选择实际核对的成果版本，填写依据并明确确认。通过要求所选成果覆盖全部负责模块，并且相关上游成果仍适用。
5. 使用「交付 DAG」标签或管理面板的图查看缺口。点击模块、线程或成果节点可打开原线程；线程页的「在交付图中定位」可以返回对应节点。
6. 约定或相关依据变化后，查看待复核成果，记录沿用或补充决定。沿用形成新的成果版本，旧验收不会自动恢复，需要再次明确验收。
7. 通过已有「保存接续包」保存当时的目标、有效决定、模块约定、成果、验收、缺口和原线程引用。历史包不会随后续编辑改变。

## 实现边界

- 这是工作台内的项目交付图。既有独立 `cfl-dag` 面板尚未适配；本轮没有复制其私有实现。
- 当前布局面向小规模试验，采用分列、滚动和关系类型筛选；尚未验证大型图性能。
- 关系由用户明确登记。输入约定位于工作包，未提供逐条依赖边的独立说明编辑器；语义一致性仍需核对。
- 图中运行状态、成果适用性和人工验收分别表达。条件全部通过仅覆盖已登记要求。
- 模型可以读取交付摘要，正式修改和验收从用户界面进入。本轮未重复模型调用演示，也未新建协调会话或人为中断宿主验证恢复。
- 公开包只包含实现、通用方案和脱敏结论；不附宿主地址、凭据、完整状态、原始会话和私有图数据。
