- ADR-001 附录：字段变更记录

**验收**：上面命令全过；bad 例的错误信息能定位到字段；`ledger.good.jsonl` 仍通过；I11–I13 各有一个反例。

**预估**：1 天 ｜ **执行者**：Lead ｜ **注意**：不改 agent-bridge 其他目录；不删旧 schema 字段。

### H0-B 意外分类技能与评测

```text
depends: H0-A1
verify:  cd ~/projects/agent-harness
         node test/skill-package.mjs
         python3 eval/run_surprise_eval.py --set eval/cases-locked.jsonl --runs 3 --out eval/results/
         # 脚本退出 0 且报告满足：accuracy>=0.80、plan_as_impl<=2、escalate_ratio∈[0.10,0.25]
write_scope: <repo>/skills/**、<repo>/eval/**（worktree 内）；~/.dsh/skills/surprise-classify（符号链接，Lead 建）
```

**目标**：把设计稿里"已写好"的技能落成 DSH 可加载的包，并过决定规则。

**产物**
- `skills/surprise-classify/SKILL.md`：触发条件、分类顺序（环境→尺子→假设→理解→实现→拿不准）、每类证据要求、上报规则
- `skills/surprise-classify/references/`：分类顺序表、五类字段说明、2 个正例 1 个反例
- `eval/cases-locked.jsonl`：40 条锁定集（先找回设计稿说的 v2 标注集；找不到则从 `docs/records` 重建，流程与来源写进 ADR）
- `eval/run_surprise_eval.py`：每题跑 3 次取多数、混淆矩阵、决定规则判定
- `eval/results/<日期>.json` + 一页结论
- `test/skill-package.mjs`：frontmatter/结构/引用完整性

**验收**：技能可在真实 DSH 会话里被加载；40 条集上按决定规则判定出"过/不过"；结果可复跑。**不过就按设计稿决定规则改分类顺序与证据要求，换新 40 条重测。**

**预估**：1–2 天 ｜ **执行者**：teammate（实现）｜**注意**：锁定集不得用于调提示词（另留开发集 20 条）。

### H0-C DSH 组合（harness profile）

```text
depends: H0-A1
verify:  cd ~/projects/agent-harness
         node test/harness-profile.mjs
         dsh --profile harness --dump-config | grep -E "agent-team|hooks-claude-code|skill-filesystem|harness-"
         bash install/compose-smoke.sh      # 起一次 headless 会话，加载技能，退出清理
write_scope: <repo>/profiles/**、<repo>/install/**（worktree 内）；
             ~/.dsh/.agent-presets/harness-{designer,implementer,reviewer}/（新增）；
             不改 ~/.dsh/profiles/desktop/**、~/.dsh/cordis.patch.yml
```

**目标**：一条命令装出一个可用的 `harness` 组合：团队工具 + 记录技能 + 独立门禁 hooks + 角色 preset。

**产物**
- `profiles/harness/`：`cordis.yml`、`package.json`、`cordis.patch.yml`（挂 `dsh-base` + `dsh-experimental-agent-team-profile` + `dsh-hooks-claude-code` + `dsh-skill-filesystem` + 记录工具）
- `profiles/harness/hooks.json`：PreToolUse 示例——写范围外阻断（退出 2），其余事件只记录
- 三个 agent preset：`harness-designer`（只读+方案）、`harness-implementer`（写范围+验证）、`harness-reviewer`（只读+审计）
- `install/`：把组合与 preset 同步进 `~/.dsh` 的脚本（符号链接优先，避免两份漂移）
- `test/harness-profile.mjs`：dump 结构断言 + 不覆盖 desktop 断言

**验收**：dump-config 可见上述条目；冒烟脚本通过；一次真实会话能加载技能并看到团队工具；desktop profile 行为不变（`git -C ~/.dsh diff --stat` 只含新增）。

**预估**：0.5–1 天 ｜ **执行者**：teammate ｜ **注意**：DSH 锁 0.2.0-rc.2；Orca 的 hooks 段一行不动。

### H0-D 记录写入管线与观测

```text
depends: H0-A1
verify:  cd ~/projects/agent-harness
         node test/record-cmd.mjs
         node tools/record.mjs surprise --input test/fixtures/surprise.json --ledger /tmp/ledger-test.jsonl
         python3 ~/.agent-bridge/schemas/validate.py ledger /tmp/ledger-test.jsonl --max-depth 3
         python3 tools/records_stats.py --ledger /tmp/ledger-test.jsonl
write_scope: <repo>/tools/**、<repo>/test/**、<repo>/.github/workflows/（worktree 内）
```

**目标**：让"发生时写入"成为唯一的写入口，写上就校验，可统计。

**产物**
- `tools/record.mjs`：`surprise|lesson` 两个子命令；append-only；幂等 id；写入前跑 schema+不变量；失败非 0 退出；脱敏过滤
- `tools/records_stats.py`：总数、五类分布、证据条数、校验失败、周报一页
- `tools/ledger-append.mjs`（被 record 调用）：单写者 + 文件锁（`flock`），半行写入回滚
- `test/record-cmd.mjs`、`test/fixtures/*`
- `.github/workflows/validate.yml`：examples 正反例 + 单测 + `validate.py` 全量

**验收**：坏记录被拒且退出码非 0；同 id 同内容重试幂等；统计字段齐全；CI 绿；账本文件行行可被 `validate.py` 通过。

**预估**：1–1.5 天 ｜ **执行者**：teammate ｜ **注意**：不实现令牌/预算；只允许它写账本。

### H0-E 真实试点（2 周）

**产物**
- 试点任务清单（1–3 个真实任务，非玩具）
- ≥30 条记录，覆盖五类；计划错必填假设与回滚点
- 一条完整闭环链路：预测 → 检查点 → 判定 → 意外 → 分类 → 教训条目 → 回放
- 每周一页统计 + 最终交接记录（见 §4）

**验收**：verify 通过；链路可按 ID 回放；业务代码零改动；审查者抽 10 条核对证据。

**预估**：2 周（可缩为一周 ≥15 条，但 H0 不算"过"）｜ **执行者**：Lead 或独立人 ｜ **注意**：只记录不修；发现业务 bug 记一条 deviation 后停。
