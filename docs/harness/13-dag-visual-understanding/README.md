# DAG 统一图形表达与场景映射

2026-11-13 · 讨论与来源核对，未修改产品代码。

DAG 的目标是通过可交互的图，让人更直观地理解系统、过程、选择、依据与当前工作。以前为帮助理解而要求绘制的架构图，都进入这一产品范围。现有工作台交付图是其中一种视图。

推荐按以下顺序阅读：

1. [整体讨论稿 v0.1.0](DAG统一图形表达与场景映射讨论稿-v0.1.0.md)：定位、总体方案、图形语义、交互与实施边界。
2. [15 类场景映射](SCENE_MAP.md)：当时想看清的问题 → 具体稿件和图号 → DAG 呈现 → 读图验收问题。
3. [图块清单与覆盖口径](DIAGRAM_INVENTORY.md)：95 个含图 Markdown 文件、433 处 Mermaid 图块；包含历史版本和副本，按正文逐字节去重有 193 组，不能视作相同数量的独立架构图。
4. [逐图数据](DIAGRAM_INVENTORY.json)：源路径、图题、行号、文件与图块哈希。它是机械目录，不是已转换的运行图。

三张代表图——统一 Harness 总体架构、Record 三路径与反馈、远程双模式——只是后续能力验证候选，不是产品边界。本轮用户选择先整理整体方案；新增产品代码和样板实现仍需明确范围。

本包保留公开材料的出处。历史原始需求和目标截图已在私有材料中回查，公开包不附个人原话、原始会话、私有项目图和运行数据。本轮未复测既有 DAG 面板或重新部署工作台。已有交付功能见 [12-delivery-dag](../12-delivery-dag/README.md)，旧 DAG 公开设计见 [06-dag](../06-dag/CONTENTS.md)。
