怎么做出来

后端做在 dsh-project-workbench 插件里，不改 DSH。项目、线程、工作树和总对话已经有，缺会话图载荷和几个读接口。

数据从哪来

地图上的来源现状
卡片和状态插件的线程 phase，加上会话里的审批事件已有
实线、双线的边项目成员、dependsOn、parentSession、子智能体事件已有
目标插件里新增项目级目标，和单会话的 /goal 分开要新增
虚线的边两条工作树线程的改动文件取交集要新算
卡片一行字线程最后一句和当前工具，新增 thread-tail要新增

能复用什么

卡片和展开web/graph/components/card.js、open.js
边和强调edge.js、ui/layout/emphasis.js
横排布局ui/layout/route_lr.js 和让位规则
卡片里的真会话插件已有的 EmbeddedConversation，审批和发消息都走原生
TUI插件用 dsh-tui 的 tuiPanels 注册侧栏面板

分四步

第 1 步只读地图：卡片、状态、实线的边，点一下跳到会话。
第 2 步卡片里对话：展开后能发消息、批准、回答。
第 3 步在图上开分支、放进分屏，把目标挂到多个会话。
第 4 步加虚线的推测边和流动动效，TUI 跟上。

要守的规矩

一份语义会话图走现有图载荷的服务层，不另起一套。
同屏展开上限沿用停靠 2 张、全屏 3 张，多开费内存也费注意力。
位置不乱跳状态变化不改布局，只有增删会话才让位。
虚线不是事实推测边只提示，不触发任何动作。
会话多了已完成的折成“还有 N 个”，时间久的默认收起。
